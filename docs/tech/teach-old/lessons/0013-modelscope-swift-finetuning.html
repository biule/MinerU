1. SWIFT 是什么？为什么要学第二个框架？

第 12 课用 LLaMA-Factory 跑通了第一次微调。那为什么还要学 SWIFT？

1.1 一句话定义

SWIFT（Scalable lightWeight Infrastructure for Fine-Tuning）是魔搭社区（ModelScope）官方维护的微调框架，由阿里通义千问团队深度参与开发。它在 GitHub 上有 6k+ stars，是中文大模型生态中最活跃的微调框架之一。

SWIFT 的定位： 不是 LLaMA-Factory 的替代品，而是 Qwen / 魔搭生态的"亲儿子" 如果你重度使用 Qwen 系列模型 → SWIFT 的适配是最快最深的 如果你依赖魔搭社区做模型分发 → SWIFT 的推送/拉取是无缝的

1.2 SWIFT vs LLaMA-Factory：什么时候用哪个

维度LLaMA-FactorySWIFT
上手门槛 Web UI + YAML，零代码可跑 CLI + Python API，需少量代码
Qwen 系列支持 一等公民，适配及时 最高优先级，Qwen 发版当日即适配
中文文档与社区 英文为主，中文资料分散 全中文，魔搭社区直接答疑
模型分发 需手动推到 HuggingFace 一键推送到魔搭 Hub，国内下载快
自定义训练逻辑 有限，主要通过 YAML 控制 Python API 灵活性高，自定义 loss/数据加载
多模态支持 完善，Qwen2-VL 支持好 完善，Qwen2-VL 是核心支持目标
LoRA 合并 export 命令 merge_lora 命令 + Python API
推理部署 需外部工具（vLLM 等） 内置 deploy 命令，直接起服务
选择建议

第一次微调用 LLaMA-Factory（第 12 课），追求零代码和 Web UI 体验。
当你需要：①更强的 Qwen 适配速度 ②中文社区支持 ③推送到魔搭 Hub ④自定义训练逻辑 → 切到 SWIFT。
两者可以共存——用同一个 conda 环境装两个框架，数据格式互转（都是 ShareGPT 变体），灵活切换。

2. 环境搭建

前置要求

3. 数据准备：适配 SWIFT 格式

第 12 课详细讲了如何构造微调数据。这里聚焦于把已有训练数据转成 SWIFT 兼容格式。

3.1 SWIFT 的数据格式

SWIFT 对 Qwen2-VL 多模态训练使用 messages 格式（与 LLaMA-Factory 的 ShareGPT 格式几乎一样）：

# SWIFT 兼容的 JSONL 格式（每行一条） {"messages": [{"role": "user", "content": "\nLayout Detection:"}, {"role": "assistant", "content": "<|box_start|>120 85 880 145<|box_end|><|ref_start|>title<|ref_end|>"}], "images": ["images/page_001.png"]}
好消息：LLaMA-Factory 的 ShareGPT JSON 数据和 SWIFT 的 messages JSONL 数据格式兼容。只需把 JSON 数组转成 JSONL（每行一条），字段名完全一致（messages + images）。

3.2 格式转换脚本

import json def sharegpt_to_swift(input_json, output_jsonl): """LLaMA-Factory ShareGPT JSON → SWIFT JSONL""" with open(input_json, encoding="utf-8") as f: data = json.load(f) with open(output_jsonl, "w", encoding="utf-8") as f: for item in data: swift_item = { "messages": item["messages"], "images": item.get("images", []) } f.write(json.dumps(swift_item, ensure_ascii=False) + "\n") print(f"转换完成: {len(data)} 条 → {output_jsonl}") sharegpt_to_swift("mineru_layout_train.json", "mineru_layout_train.jsonl")

3.3 数据目录结构

~/mineru-finetune/ ├── data/ │ ├── mineru_layout_train.jsonl ← SWIFT 训练数据（Step 1） │ ├── mineru_layout_val.jsonl ← SWIFT 验证数据 │ ├── mineru_content_train.jsonl ← SWIFT 训练数据（Step 2） │ ├── mineru_content_val.jsonl ← SWIFT 验证数据 │ └── images/ ← 图片文件 └── output/ ← 训练输出目录
images 路径注意

JSONL 中 images 字段的路径相对于执行 swift 命令时的当前目录。建议在数据目录下执行 swift 命令，或用绝对路径。

4. SWIFT CLI 一条命令跑微调

4.1 Step 1：Layout Detection 微调

LoRA 微调命令（拆行展示，实际是一条命令）

cd ~/mineru-finetune swift sft \ --model_type qwen2-vl-2b \ --model_id_or_path ~/models/MinerU2.5-Pro-2605-1.2B \ --sft_type lora \ --lora_rank 16 \ --lora_alpha 32 \ --lora_dropout_p 0.05 \ --target_modules all-linear \ --dataset mineru_layout_train.jsonl \ --val_dataset mineru_layout_val.jsonl \ --train_type custom \ --template qwen2-vl \ --max_length 4096 \ --output_dir output/mineru-layout-lora \ --num_train_epochs 3 \ --per_device_train_batch_size 2 \ --per_device_eval_batch_size 2 \ --gradient_accumulation_steps 8 \ --learning_rate 5e-5 \ --lr_scheduler_type cosine \ --warmup_ratio 0.1 \ --bf16 true \ --logging_steps 10 \ --save_steps 200 \ --eval_steps 200 \ --save_total_limit 3 \ --dataloader_num_workers 4

4.2 关键参数解释

参数含义建议值
--model_typeSWIFT 内置的模型类型标识qwen2-vl-2b（1.2B 也适用）
--model_id_or_path模型本地路径或 HF/ModelScope ID本地绝对路径最稳
--sft_type微调方式lora / full / longlora
--target_modulesLoRA 挂载目标all-linear（Qwen2-VL 推荐）
--template对话模板qwen2-vl（Qwen2-VL 专用）
--train_type数据加载方式custom（从本地 JSONL 读）
--dataset训练数据文件JSONL 文件路径
model_type 说明

SWIFT 用 model_type 标识模型架构以匹配 tokenizer、processor、对话模板。MinerU 的 1.2B 模型与 Qwen2-VL-2B 共用同一架构类 Qwen2VLForConditionalGeneration，所以 model_type=qwen2-vl-2b 可以正常工作。

4.3 Step 2：Content Extraction 微调

与 Step 1 几乎一样，只改数据集路径和输出目录：

swift sft \ --model_type qwen2-vl-2b \ --model_id_or_path ~/models/MinerU2.5-Pro-2605-1.2B \ --sft_type lora \ --lora_rank 16 \ --lora_alpha 32 \ --lora_dropout_p 0.05 \ --target_modules all-linear \ --dataset mineru_content_train.jsonl \ --val_dataset mineru_content_val.jsonl \ --train_type custom \ --template qwen2-vl \ --max_length 4096 \ --output_dir output/mineru-content-lora \ --num_train_epochs 3 \ --per_device_train_batch_size 2 \ --per_device_eval_batch_size 2 \ --gradient_accumulation_steps 8 \ --learning_rate 5e-5 \ --lr_scheduler_type cosine \ --warmup_ratio 0.1 \ --bf16 true \ --logging_steps 10 \ --save_steps 200 \ --eval_steps 200 \ --save_total_limit 3 \ --dataloader_num_workers 4

4.4 训练监控

SWIFT 默认用 SwanLab（国产替代，国内流畅）或 WandB 记录训练曲线：

# SwanLab（国内流畅，无需翻墙） pip install swanlab swift sft ... --report_to swanlab --run_name mineru-layout-v1 # WandB swift sft ... --report_to wandb --run_name mineru-layout-v1 # 纯本地不上报 swift sft ... --report_to none

训练启动后关注三个指标：

  • loss 是否稳定下降（不下降 = lr 太小或数据有问题）
  • eval_loss 是否先降后升（上升 = 过拟合，减 epoch 或加 dropout）
  • GPU 显存是否稳定（波动大 = 可能 OOM，降 batch_size）

5. SWIFT Python API：自定义训练逻辑

5.1 最小训练脚本

# train_layout.py import os from swift.llm import sft_main, TrainArguments args = { "model_type": "qwen2-vl-2b", "model_id_or_path": os.path.expanduser("~/models/MinerU2.5-Pro-2605-1.2B"), "sft_type": "lora", "lora_rank": 16, "lora_alpha": 32, "target_modules": ["all-linear"], "dataset": ["mineru_layout_train.jsonl"], "val_dataset": ["mineru_layout_val.jsonl"], "train_type": "custom", "template": "qwen2-vl", "max_length": 4096, "output_dir": "output/mineru-layout-lora", "num_train_epochs": 3, "per_device_train_batch_size": 2, "gradient_accumulation_steps": 8, "learning_rate": 5e-5, "bf16": True, "logging_steps": 10, "save_steps": 200, "save_total_limit": 3, } if __name__ == "__main__": result = sft_main(TrainArguments(**args)) print(f"训练完成，最佳 checkpoint: {result['best_model_checkpoint']}")

5.2 自定义 Loss：给特殊 token 加权

SWIFT 支持注册自定义 loss。一个常见场景：给布局 token（<|box_start|> 等）更高的 loss 权重，让模型更关注布局结构：

import torch from swift.llm import register_loss_func SPECIAL_TOKEN_IDS = [151665, 151666, 151667, 151668] # box_start/end, ref_start/end SPECIAL_WEIGHT = 3.0 @register_loss_func("mineru_weighted_loss") def mineru_weighted_loss(outputs, labels, **kwargs): logits = outputs.logits shift_logits = logits[..., :-1, :].contiguous() shift_labels = labels[..., 1:].contiguous() loss_per_token = torch.nn.functional.cross_entropy( shift_logits.view(-1, shift_logits.size(-1)), shift_labels.view(-1), reduction='none' ) weights = torch.ones_like(shift_labels, dtype=torch.float) for token_id in SPECIAL_TOKEN_IDS: weights[shift_labels == token_id] = SPECIAL_WEIGHT return (loss_per_token * weights.view(-1)).mean() # CLI 使用：swift sft ... --loss_func mineru_weighted_loss
大部分场景不需要自定义

SWIFT 内置的数据加载和训练逻辑覆盖了 90% 需求。只有需要数据增强、动态混合多数据集、自定义 loss 等高级场景才需要 Python API。

6. 合并 LoRA 并部署

6.1 合并 adapter 到基础模型

# CLI 合并 swift merge_lora \ --model_id_or_path ~/models/MinerU2.5-Pro-2605-1.2B \ --lora_checkpoint output/mineru-layout-lora/checkpoint-600 \ --output_dir ./MinerU-Layout-SWIFT \ --device cpu # Python API 合并 from swift.llm import merge_lora_main, MergeArguments merge_lora_main(MergeArguments( model_id_or_path="~/models/MinerU2.5-Pro-2605-1.2B", lora_checkpoint="output/mineru-layout-lora/checkpoint-600", output_dir="./MinerU-Layout-SWIFT", device="cpu" ))

6.2 验证合并后的模型

from transformers import Qwen2VLForConditionalGeneration, AutoProcessor model = Qwen2VLForConditionalGeneration.from_pretrained( "./MinerU-Layout-SWIFT", torch_dtype="auto", device_map="auto" ) processor = AutoProcessor.from_pretrained("./MinerU-Layout-SWIFT") print(f"加载成功，参数量: {sum(p.numel() for p in model.parameters()) / 1e9:.2f}B")

6.3 推送到魔搭 Hub（SWIFT 独有优势）

# 一键推送到魔搭社区 swift push_to_hub \ --model_path ./MinerU-Layout-SWIFT \ --hub_token YOUR_MODELSCOPE_TOKEN \ --repo_name "yourname/MinerU-Layout-Invoice" \ --private false # 国内其他用户直接拉取 modelscope download --model yourname/MinerU-Layout-Invoice --local_dir ./downloaded
为什么这对你很重要

魔搭 Hub 在国内访问速度快（不需要翻墙），微调的 MinerU 模型可通过魔搭社区直接分发。企业内部部署也可推送到私有仓库，团队成员一键拉取。

6.4 接回 MinerU

# 运行时替换 ModelPath from mineru.utils.enum_class import ModelPath ModelPath.vlm_root_modelscope = "./MinerU-Layout-SWIFT" # 或编辑 ~/.mineru.json： # { "models-dir": { "vlm": "/home/user/MinerU-Layout-SWIFT" }, "model-source": "local" } # 或环境变量 export MINERU_MODEL_SOURCE=local export MINERU_VLM_MODEL_PATH=/home/user/MinerU-Layout-SWIFT

7. SWIFT 的独有功能

7.1 多轮对话训练

SWIFT 原生支持多轮对话训练。对 MinerU 而言，可以把两步推理串联：

{ "messages": [ {"role": "user", "content": "\nLayout Detection:"}, {"role": "assistant", "content": "<|box_start|>120 85 880 145<|box_end|><|ref_start|>title<|ref_end|>"}, {"role": "user", "content": "\nText Recognition:"}, {"role": "assistant", "content": "MinerU 是一个开源的高精度文档解析引擎"} ], "images": ["page_001.png", "crop_title_001.png"] }
实验性建议

两步联合训练是进阶技巧。大部分情况下分开训练更稳定。联合训练适用于"新版式适配 + 版式内容联动"场景，需更多数据和更长训练时间。

7.2 一键推理部署

# 内置 deploy 命令，起 OpenAI 兼容推理服务 swift deploy \ --model_type qwen2-vl-2b \ --model_id_or_path ./MinerU-Layout-SWIFT \ --infer_backend vllm \ --port 30001
与 mineru-vllm-server 的区别

swift deploy 是通用推理方案，适合快速验证微调效果。生产环境仍用 mineru-vllm-server——它对 MinerU 的输出格式做了专门后处理（LogitsProcessor 等）。

10. 小测验

问题 1： SWIFT 的 model_type=qwen2-vl-2b 对 MinerU 的 1.2B 模型也适用，原因是什么？

  1. SWIFT 会自动把 1.2B 模型升级到 2B
  2. 两者共用同一个架构类 Qwen2VLForConditionalGeneration
  3. 1.2B 和 2B 是同一个模型，只是改了名字
  4. SWIFT 会自动检测参数数量并调整 model_type
查看答案

B。MinerU 的 1.2B 和 Qwen2-VL-2B 共用同一架构类，model_type 决定的是 tokenizer、processor、模板的加载方式，与参数量无关。

问题 2： 把 LLaMA-Factory 的 ShareGPT JSON 数据转成 SWIFT 兼容格式，需要做什么？

  1. 完全重写，字段名全部不同
  2. 只需把 JSON 数组转成 JSONL（每行一条），字段名不变
  3. 需要把 messages 改成 conversations，images 改成 pictures
  4. 需要把 JSON 转成 CSV
查看答案

B。SWIFT 的 messages 格式与 LLaMA-Factory 的 ShareGPT 格式字段名完全相同。唯一区别是 SWIFT 要求 JSONL 格式（每行一条 JSON），LLaMA-Factory 接受 JSON 数组。

问题 3： SWIFT 相比 LLaMA-Factory 最大的独特优势是什么？

  1. SWIFT 训练的模型精度更高
  2. 与魔搭社区深度集成，支持一键推送到魔搭 Hub 和中文社区支持
  3. SWIFT 不需要 GPU
  4. SWIFT 完全不需要写代码
查看答案

B。SWIFT 的核心优势是魔搭生态集成：Qwen 系列最高优先级适配、全中文文档社区、一键推送魔搭 Hub、国内网络无障碍。

问题 4： LoRA 微调完成后，生产部署时应该怎么做？

  1. 直接用 adapter 部署，不需要合并
  2. 先用 merge_lora 合并为完整模型，再用 mineru-vllm-server 加载
  3. 把 .safetensors 文件直接复制到 MinerU 目录
  4. 用 swift deploy 替代 mineru-vllm-server 用于生产
查看答案

B。不合并的 LoRA 每次 forward 额外计算 A·B，推理慢且可能因加载问题报错。合并后用 mineru-vllm-server 加载——swift deploy 适合验证，生产用 mineru-vllm-server（有专门后处理）。

11. 动手挑战

挑战 1：装 SWIFT 并跑通一条命令

在 WSL2 或 Linux 中装好 ms-swift[all]，下载 MinerU2.5-Pro 模型，用任意一条数据执行 swift sft --max_steps 5 确认能跑通。

挑战 2：数据格式迁移

如果你已有 LLaMA-Factory 格式的训练数据，写脚本把 JSON → JSONL，用 --max_steps 5 验证 SWIFT 能正确加载和训练。

挑战 3：推送到魔搭 Hub

注册魔搭社区账号，获取 Access Token，用 swift push_to_hub 推送微调模型，再用 modelscope download 验证能正常拉取。

14. 小结

五个核心收获

1. SWIFT 是魔搭社区的官方微调框架，对 Qwen 系列支持最快最深，中文生态最完善。与 LLaMA-Factory 互补而非替代。
2. 数据格式兼容：LLaMA-Factory ShareGPT JSON 和 SWIFT messages JSONL 字段名一致，只用改文件格式（JSON 数组 → JSONL）。
3. CLI 一条命令跑通：swift sft 覆盖模型加载、数据读取、LoRA 训练、checkpoint 保存全部环节。Python API 用于自定义 loss 等进阶需求。
4. 训练后必须 merge_lora：合并为完整模型再部署——swift deploy 适合验证，生产用 mineru-vllm-server。
5. 魔搭 Hub 是国内分发最佳渠道：swift push_to_hub 一键推送，团队成员 modelscope download 一键拉取，无需翻墙。
