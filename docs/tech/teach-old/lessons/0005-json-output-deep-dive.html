1. 为什么需要 JSON 输出？

第 4 课我们看到了 Markdown 输出——它适合人类阅读和直接喂给 LLM。但如果你的目标是程序化后处理（比如自动提取发票金额、汇总合同条款、入库报表数据），Markdown 就力不从心了。

Markdown 是渲染结果，JSON 是结构化数据。后者记录了每个元素的位置、类型、置信度——这正是后处理程序需要的。

Markdown 输出

  • 纯文本，人可读
  • 丢失了位置信息
  • 丢失了类型标注
  • 丢失了置信度分数
  • 适合：阅读、LLM 输入

JSON 输出

  • 结构化数据，程序可读
  • 保留每个元素的位置（bbox）
  • 明确标注元素类型
  • 包含 OCR 置信度
  • 适合：后处理、入库、分析

2. 整体结构：从大到小

MinerU 的 JSON 输出是一个五层嵌套结构。理解这个层次关系是读懂 JSON 的关键。

根对象 middle_json → 页面 pdf_info[i] → 块 block → 行 line → 片段 span

每一层的含义：

层级含义类比
根对象整个文档的容器，包含页面列表和元数据一本书
页面文档的一页，包含若干内容块和位置尺寸一页纸
块页面中的一个逻辑区块（段落、标题、表格……）一页中的一段文字或一个表格
行块内的一行，由多个片段组成段落中的一行
片段最小单位——一段文字、一个公式、一张图片行中的几个字或一个公式
关键区别：块 vs 片段

块表示"这是一个标题"或"这是一个表格"，是一个语义单位。片段表示"这是标题中的一行文字"或"这是表格单元格中的内容"，是一个内容单位。先按块理解文档结构，再按片段读取具体内容。

3. 三种 JSON 输出格式

MinerU 提供三种 JSON 格式，从"原始保真"到"高级语义"逐步抽象：

3.1 middle_json — 最完整的原始数据

这是 MinerU 内部处理过程中的中间表示，保留最丰富的信息。根结构：

{ "pdf_info": [ ← 页面列表 { "preproc_blocks": [ ← 正文内容块 { "type": "text", ← 块类型 "bbox": [x0,y0,x1,y1], ← 块边界框（归一化到[0,1000]） "lines": [ ← 行列表 { "spans": [ ← 片段列表 { "type": "text", ← 片段类型 "content": "MinerU是一个...", ← 实际文字 "bbox": [x0,y0,x1,y1], ← 片段位置 "score": 0.98 ← OCR 置信度 } ] } ] } ], "discarded_blocks": [...], ← 被丢弃的内容（页眉页脚等） "page_idx": 0, ← 页码（从0开始） "page_size": [595, 842] ← 页面尺寸（宽×高） } ], "_backend": "pipeline", "_version_name": "3.4.4" }

3.2 content_list — 面向后处理的平铺结构

从 middle_json 加工而来，去掉了行/片段嵌套，每个元素直接给出类型、文字、图片路径和位置：

[ { "type": "text", "text": "# 第 5 课：JSON 输出详解", "text_level": 1, "bbox": [120, 80, 800, 100], "page_idx": 0 }, { "type": "table", "img_path": "images/table-1.jpg", "table_body": "<table>...</table>", "table_caption": ["表1: 引擎对比"], "bbox": [100, 300, 800, 500], "page_idx": 0 } ]

3.3 content_list_v2 — 更细粒度的语义版本

将内容按页面分组，段落内以 span 为单位展开，区分行内公式和纯文本：

[ [ ← 第 0 页 { "type": "paragraph", "content": { "paragraph_content": [ {"type": "text", "content": "MinerU是一个 "}, {"type": "equation_inline", "content": "E=mc^2"} ] }, "bbox": [120, 150, 800, 170] } ] ]
格式适用场景信息密度
middle_json调试、二次解析、需要原始位置信息最高
content_list单证后处理、字段提取、数据库入库中
content_list_v2精细文本处理、公式与文字分离分析高

4. 核心块类型速查

JSON 中你会遇到这些块类型。记住它们的含义，往后读 JSON 就像查字典：

type 值含义包含的特殊字段
text普通段落text
title标题text, text_level (1-9)
table表格table_body (HTML), table_caption, img_path
image图片img_path, image_caption, content
chart图表img_path, content
equation行间公式text (LaTeX), text_format: "latex", img_path
code代码块code_body, code_language, code_caption
list列表list_items, list_type
header/footer页眉/页脚text（在 discarded_blocks 中）

5. 实战：读取并解析 JSON 输出

5.1 启用 JSON 输出

通过 Python API 调用时，设置以下参数即可获得 JSON：

# 获取 middle_json（最完整）
return_middle_json=True

# 获取 content_list（最常用，适合后处理）
return_content_list=True

# 获取 content_list_v2（最精细）
return_content_list_v2=True

CLI 命令默认只输出 Markdown。用 Python API 才能拿到 JSON——这也是第 6 课会讲的内容。

5.2 用 Python 提取所有标题

假设你已经拿到了 content_list，提取所有标题：

import json

with open("output.json", encoding="utf-8") as f:
    content_list = json.load(f)

# 提取所有标题（按页内顺序）
titles = []
for item in content_list:
    if item["type"] == "text" and "text_level" in item:
        titles.append({
            "level": item["text_level"],
            "text": item["text"],
            "page": item["page_idx"]
        })

for t in titles:
    indent = "  " * (t["level"] - 1)
    print(f"{indent}[H{t['level']}] {t['text'][:60]} (第{t['page']+1}页)")

5.3 提取所有表格并保存 HTML

tables = []
for item in content_list:
    if item["type"] == "table" and "table_body" in item:
        tables.append({
            "caption": " ".join(item.get("table_caption", [])),
            "html": item["table_body"],
            "page": item["page_idx"]
        })

# 保存第 1 个表格
if tables:
    with open("table_1.html", "w", encoding="utf-8") as f:
        f.write(tables[0]["html"])
    print(f"保存了 {len(tables)} 个表格")

5.4 从 middle_json 提取 OCR 置信度

只有 middle_json 保留了片段级别的置信度。这在评估解析质量时很有用：

low_confidence_spans = []

for page in middle_json["pdf_info"]:
    for block in page["preproc_blocks"]:
        for line in block.get("lines", []):
            for span in line.get("spans", []):
                score = span.get("score", 1.0)
                if score < 0.7:
                    low_confidence_spans.append({
                        "text": span.get("content", ""),
                        "score": score,
                        "page": page["page_idx"]
                    })

print(f"找到 {len(low_confidence_spans)} 个低置信度片段")
for span in low_confidence_spans[:5]:
    print(f"  第{span['page']+1}页 score={span['score']:.2f}: {span['text'][:40]}")
bbox 坐标说明

bbox 格式为 [x0, y0, x1, y1]，坐标系原点在页面左上角。坐标值被归一化到 [0, 1000]，即页面宽度和高度都映射为 1000。要恢复实际像素位置，乘以实际页面尺寸除以 1000 即可。

7. 小测验

问题 1： 如果你需要按位置筛选特定区域的文字（比如发票左上角的发票号码），应该使用哪种 JSON 格式？

  1. Markdown
  2. middle_json 或 content_list（包含 bbox）
  3. 纯文本
  4. 打印输出的日志
查看答案

B。Markdown 输出不保留位置信息。Middle_json 和 content_list 都包含 bbox 字段，可以按坐标筛选特定区域的文字。

问题 2： block（块）和 span（片段）的区别是什么？

  1. 没有区别，是同义词
  2. block 是语义单位（如一个段落），span 是内容最小单位（如一行文字）
  3. block 只用于表格，span 只用于文字
  4. block 是页面的子集，span 是文档的子集
查看答案

B。Block 表示逻辑区块（标题、段落、表格），是语义单位。Span 是 block 内更细粒度的内容片段（一行文字、一个公式），是最小单位。

问题 3： content_list 相比 middle_json 做了什么简化？

  1. 去掉了所有中文内容
  2. 去掉了 line/span 嵌套，每个元素直接包含 text 和 bbox
  3. 只保留表格，去掉文字
  4. 把 JSON 转成了 XML
查看答案

B。Content_list 去掉了烦琐的 block→line→span 三层嵌套，每个元素直接是一个字典，包含 type、text、bbox 等顶层字段，更适合直接用于后处理。
