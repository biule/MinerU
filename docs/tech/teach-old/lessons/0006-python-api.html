1. CLI 够用了吗？什么时候需要 Python API？

前几课我们用 mineru 命令完成了各种解析任务。但当你面临这些场景时，CLI 力不从心：

CLI 命令

  • 每次解析都要手动输入命令
  • 输出格式固定（默认 Markdown）
  • 难以嵌入自动化流水线
  • 无法在解析过程中插入自定义逻辑
  • 适合：临时测试、少量文档

Python API

  • 批量循环处理所有文档
  • 自由控制输出（Markdown + JSON + 自定义）
  • 可嵌入 Web 服务、监控系统、自动化流水线
  • 解析前后可做任意处理（预处理、校验、入库）
  • 适合：生产环境、大规模处理、系统集成

一句话总结：CLI 是手工工具，Python API 是工厂流水线。前者灵活简单，后者可控可扩展。

2. 核心工作流

用 Python API 解析一个 PDF，本质上经历了这五步：

1. 读取文件 → 2. 准备目录 → 3. 解析文档 → 4. 生成输出 → 5. 写入文件
步骤做什么调用的函数
1. 读取文件把 PDF 文件读入为字节流（bytes）common.read_fn(path)
2. 准备目录创建输出目录，初始化 DataWritercommon.prepare_env(...) + FileBasedDataWriter(...)
3. 解析文档调用引擎分析 PDF，产出中间 JSONpipeline_analyze.doc_analyze_streaming(...)
4. 生成输出将中间 JSON 转为 Markdown / content_listpipeline_union_make(...)
5. 写入文件将结果保存到磁盘writer.write_string(...)
源码位置一览

第 1-2 步在 mineru/cli/common.py，第 3 步在 mineru/backend/pipeline/pipeline_analyze.py，第 4 步在 mineru/backend/pipeline/pipeline_middle_json_mkcontent.py，第 5 步在 mineru/data/data_reader_writer.py。你现在不需要通读这些文件，但知道它们在哪儿，遇到问题时有处可查。

3. 关键模块导入

写一个 MinerU Python 脚本，通常需要导入这些模块：

# 辅助函数：读取文件、准备目录、PDF 字节处理
from mineru.cli.common import convert_pdf_bytes_to_bytes, prepare_env, read_fn

# 数据写入器：把结果保存到文件
from mineru.data.data_reader_writer import FileBasedDataWriter

# 输出模式：MM_MD（Markdown）、CONTENT_LIST（JSON）、CONTENT_LIST_V2
from mineru.utils.enum_class import MakeMode

# 引擎入口：不同后端对应不同函数
from mineru.backend.pipeline.pipeline_analyze import \
    doc_analyze_streaming as pipeline_doc_analyze
from mineru.backend.pipeline.pipeline_middle_json_mkcontent import \
    union_make as pipeline_union_make

其中两个核心概念需要提前理解：

概念作用类比
FileBasedDataWriter负责把输出的 Markdown、JSON、图片写入磁盘。你需要提供一个目录路径，它负责写文件。一个邮递员，你把信交给他，他负责送到正确的地址。
MakeMode枚举类型，定义输出格式：MM_MD（完整 Markdown）、NLP_MD（纯文字 Markdown）、CONTENT_LIST（结构化 JSON）等。一个开关，决定输出"什么样的"结果。

4. 完整示例：解析一个 PDF

下面是一个完整的 Python 脚本，用 pipeline 引擎解析一个 PDF 并输出 Markdown 和 JSON：

import json import os from pathlib import Path from mineru.cli.common import convert_pdf_bytes_to_bytes, prepare_env, read_fn from mineru.data.data_reader_writer import FileBasedDataWriter from mineru.utils.enum_class import MakeMode from mineru.backend.pipeline.pipeline_analyze import \ doc_analyze_streaming as pipeline_doc_analyze from mineru.backend.pipeline.pipeline_middle_json_mkcontent import \ union_make as pipeline_union_make # === 配置区 === pdf_path = "demo/pdfs/demo1.pdf" # 输入的 PDF 文件 output_dir = "demo/my_api_output" # 输出根目录 lang = "ch" # OCR 语言 parse_method = "auto" # auto / txt / ocr # === 第一步：读取文件 === pdf_bytes = read_fn(pdf_path) pdf_bytes = convert_pdf_bytes_to_bytes(pdf_bytes) # === 第二步：准备目录和 Writer === pdf_name = Path(pdf_path).stem # "demo1" image_dir, md_dir = prepare_env(output_dir, pdf_name, parse_method) image_writer = FileBasedDataWriter(image_dir) md_writer = FileBasedDataWriter(md_dir) # === 第三步：解析文档 === # 回调函数：当某个文档解析完成时被调用 def on_doc_ready(doc_index, model_list, middle_json, ocr_enable): pdf_info = middle_json["pdf_info"] image_subdir = os.path.basename(image_dir) # 第四步 a：生成 Markdown md_content = pipeline_union_make(pdf_info, MakeMode.MM_MD, image_subdir) md_writer.write_string(f"{pdf_name}.md", md_content) # 第四步 b：生成 content_list（结构化 JSON） content_list = pipeline_union_make(pdf_info, MakeMode.CONTENT_LIST, image_subdir) md_writer.write_string( f"{pdf_name}_content_list.json", json.dumps(content_list, ensure_ascii=False, indent=2) ) # 第四步 c：保存完整 middle_json（调试用） md_writer.write_string( f"{pdf_name}_middle.json", json.dumps(middle_json, ensure_ascii=False, indent=2) ) print(f"完成！输出在: {md_dir}") # 发起解析 pipeline_doc_analyze( pdf_bytes_list=[pdf_bytes], image_writer_list=[image_writer], lang_list=[lang], on_doc_ready=on_doc_ready, parse_method=parse_method, )

把这个脚本保存为 my_parse.py，在项目目录下运行：

python my_parse.py

运行完成后，检查输出目录：

demo/my_api_output/demo1/auto/
├── demo1.md                    # Markdown 解析结果
├── demo1_content_list.json     # 结构化 JSON（第 5 课学的）
├── demo1_middle.json           # 完整中间 JSON（调试用）
└── images/                     # 提取的图片
注意：首次运行会下载模型

和 CLI 一样，首次运行 Python API 也需要下载模型文件。确保网络畅通，或者提前设置 MINERU_MODEL_SOURCE=modelscope（回顾第 3 课）。

5. 关键技术点讲解

5.1 回调函数（Callback）模式

上面的代码中，on_doc_ready 是一个回调函数——它不是立即执行的，而是当 pipeline 解析完某个文档后自动被调用。

为什么用回调？因为 doc_analyze_streaming 可以同时处理多个 PDF（我们传了列表），每个 PDF 解析完的时间不同。回调模式让你能一边解析一边输出，不用等全部完成。

回调函数的参数含义：

参数含义
doc_index文档的序号（对应输入列表中的第几个 PDF）
model_list模型输出的原始列表（通常不直接使用）
middle_json中间 JSON——第 5 课学过的五层结构，这是产出 Markdown 和 content_list 的"原料"
ocr_enable布尔值，表示该文档是否走了 OCR 路径

5.2 单个文件 vs 批量处理

上面的例子只处理了一个 PDF。处理多个 PDF 只需把列表拉长：

# 处理多个文件
pdf_paths = ["demo/pdfs/demo1.pdf", "demo/pdfs/demo2.pdf"]
langs = ["ch", "ch"]

pdf_bytes_list = []
image_writer_list = []
for pdf_path in pdf_paths:
    pdf_bytes = read_fn(pdf_path)
    pdf_bytes = convert_pdf_bytes_to_bytes(pdf_bytes)
    pdf_bytes_list.append(pdf_bytes)

    pdf_name = Path(pdf_path).stem
    image_dir, _ = prepare_env(output_dir, pdf_name, parse_method)
    image_writer_list.append(FileBasedDataWriter(image_dir))

pipeline_doc_analyze(
    pdf_bytes_list=pdf_bytes_list,
    image_writer_list=image_writer_list,
    lang_list=langs,
    on_doc_ready=on_doc_ready,
    parse_method=parse_method,
)

关键约束：pdf_bytes_list、image_writer_list、lang_list 三个列表的长度必须相等，第 i 个元素对应第 i 个文档。

5.3 MakeMode 输出模式速查

MakeMode 值输出适合
MM_MD完整 Markdown（含图片引用和表格 HTML）人阅读、LLM 输入
NLP_MD纯文字 Markdown（不含图片和图表）文本分析、关键词提取
CONTENT_LIST结构化 JSON（每个元素含 type/text/bbox）后处理、字段提取、入库
CONTENT_LIST_V2细粒度结构化 JSON（span 级展开）精细文本处理、公式分析
最佳实践：同时输出多种格式

在生产环境中，建议同时输出 MM_MD（用于展示和 LLM）和 CONTENT_LIST（用于后端逻辑处理）。一份文档、两种视角，互不冲突。

6. DataWriter 详解

FileBasedDataWriter 是写入器，负责把字符串内容保存到文件。它的接口非常简洁：

# 创建实例：指定输出目录
writer = FileBasedDataWriter("./output_dir")

# 写入字符串
writer.write_string("result.md", "# Hello World")

# 写入二进制内容
writer.write_bytes("image.jpg", image_data)

# 获取写入目录
print(writer.get_dir())  # ./output_dir

你可能会奇怪——为什么不直接用 Python 的 open().write()？因为 DataWriter 是一个抽象层：它支持写本地文件，也支持直接写 S3（云存储），切换时只需替换 Writer 实现，不用改业务代码。

7. 三个引擎的 API 选择

引擎导入路径入口函数是否需要 GPU
pipeline mineru.backend.pipeline.pipeline_analyze doc_analyze_streaming(...) 否
hybrid mineru.backend.hybrid.hybrid_analyze doc_analyze(...) 是
vlm mineru.backend.vlm.vlm_analyze doc_analyze(...) 是

pipeline 是唯一可以在纯 CPU 上运行的引擎，也是最适合初学者的 Python API 入口。当你熟悉了 pipeline 的调用流程后，hybrid 和 vlm 引擎的调用方式大同小异（函数签名略有不同，但核心思路不变）。

hybrid / vlm 引擎的额外参数

hybrid 和 vlm 引擎还支持 effort（解析力度）、image_analysis（图片分析）等参数。这些可以在掌握了 pipeline API 之后再逐一尝试，避免一开始就被大量参数淹没。

8. 小测验

问题 1： CLI 命令和 Python API 最核心的区别是什么？

  1. CLI 速度更快
  2. Python API 可以嵌入自动化流水线、自由控制输出格式和处理逻辑
  3. Python API 不支持 OCR
  4. CLI 只能解析 PDF
查看答案

B。CLI 是一次性手工操作，Python API 可控可扩展，能嵌入自动化流水线、自定义输出格式和处理逻辑。

问题 2： doc_analyze_streaming 的回调函数 on_doc_ready 在什么时候被调用？

  1. 当脚本启动时
  2. 当某个文档解析完成时
  3. 当所有文档解析完毕时
  4. 当脚本出错时
查看答案

B。回调函数在"某个文档解析完成时"被自动调用，参数包括 doc_index、model_list、middle_json、ocr_enable。这使得你可以边解析边输出，支持异步处理。

问题 3： 如果你只需要纯文字内容（不需要图片和图表引用），应该用哪个 MakeMode？

  1. MM_MD
  2. NLP_MD
  3. CONTENT_LIST
  4. CONTENT_LIST_V2
查看答案

B。NLP_MD 输出纯文字 Markdown，不含图片引用和图表，适合文本分析和关键词提取场景。
