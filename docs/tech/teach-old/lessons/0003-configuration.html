1. 回顾与导入

前两课我们学习了 MinerU 的基本使用和架构。但你有没有思考过这些问题：

  • 如果只想解析 PDF 的第 3-5 页，怎么做？
  • 如果文档是韩文的，怎么告诉 MinerU 用韩文 OCR？
  • 如果不需要识别公式，关掉它能加速吗？
  • 模型下载太慢，能不能换成国内镜像？

这些问题的答案，都在 MinerU 的参数配置里。本节课将系统性地覆盖所有配置方式。

2. 三种配置方式

MinerU 提供三种配置方式，从最常用到最底层：

方式优先级适用场景
CLI 参数 最高 每次运行指定不同的参数（最常用）
JSON 配置文件（~/mineru.json） 中 固定配置：模型路径、模型来源、S3 存储等
环境变量（MINERU_*） 高 模型源切换、设备选择、日志级别等系统级设置

这些配置方式的源码位置：

  • CLI 参数：mineru/cli/client.py:1037-1184（@click.option 定义）
  • JSON 配置：mineru/utils/config_reader.py
  • 环境变量：散布在 common.py、backend/ 各模块中

3. CLI 参数完全手册

运行 mineru --help 可以查看所有参数。下面我们从最重要的开始逐条讲解。

必选参数

参数简写说明示例
--path -p 输入文件或目录路径（支持 PDF、图片、DOCX、PPTX、XLSX） -p report.pdf 或 -p ./docs/
--output -o 输出目录路径 -o ./output/

这是唯一两个必填参数。其他都有默认值。

引擎选择参数

参数默认值可选值说明
--backend / -b hybrid-engine pipeline / vlm-engine / hybrid-engine / vlm-http-client / hybrid-http-client 选择解析后端引擎
--method / -m auto auto / txt / ocr 解析方式（仅 pipeline 和 hybrid 引擎生效）
--effort medium medium / high Hybrid 引擎的解析力度

其中 --method 的三个选项含义是：

  • auto（默认）— MinerU 自动检测 PDF 类型，文本型直接提取，扫描型走 OCR
  • txt — 强制走文字提取路径，适合确认是文本型 PDF 时跳过检测
  • ocr — 强制走 OCR 路径，适合扫描型 PDF

内容提取参数

参数默认值说明
--lang / -l ch 文档语言（提高 OCR 准确率，仅 pipeline 后端）
--formula / -f True 是否启用公式解析（→ LaTeX）
--table / -t True 是否启用表格解析（→ HTML）
--image-analysis True 是否启用图片/图表分析（vlm 和 hybrid 后端）

语言选项详解

--lang 参数的可选值（定义在 mineru/utils/ocr_language.py）：

值覆盖语言
ch中文、英文、日文、繁体中文、拉丁语系
korean韩语、英语
th泰语、英语
arabic阿拉伯语、波斯语、维吾尔语、乌尔都语等 + 英语
el希腊语、英语
east_slavic俄语、白俄罗斯语、乌克兰语 + 英语
cyrillic30+ 种西里尔字母语言 + 英语
devanagari印地语、尼泊尔语、梵语等 15+ 种语言 + 英语
💡 语言参数小技巧

如果你的文档是中英文混排（最常见的情况），保持默认 --lang ch 即可。MinerU 在 3.4 版本后将日文、繁体中文、英文等统一到了 ch 模型下，简化了语言选择。

页面范围参数

参数默认值说明
--start / -s 0 起始页码（从 0 开始计数）
--end / -e None（到最后一页） 结束页码（从 0 开始计数）

示例：只解析 PDF 的第 3-5 页：

mineru -p report.pdf -o ./output --start 2 --end 4
# 注意: 页码从 0 开始，所以 0,1,2 是前 3 页
# start=2,end=4 → 第 3,4,5 页

远程服务参数

参数默认值说明
--api-url None（自动启动本地服务） 连接到已有的 MinerU FastAPI 服务
--url / -u None VLM/混合 HTTP 客户端的远程服务器地址

--api-url 是一个非常重要的参数。当你指定它时，mineru 命令会变成"客户端模式"，把任务提交给远程的 mineru-api 服务：

# 在服务器上启动 API 服务
mineru-api --port 8000

# 在客户端上提交任务到远程服务
mineru -p report.pdf -o ./output --api-url http://server-ip:8000

高级参数

参数默认值说明
--client-side-output-generation False 在客户端从中间 JSON 生成最终输出（用于 API 模式）
--version / -v — 显示版本号并退出

一个完整的命令示例

mineru \
  -p "./发票扫描件.pdf" \
  -o "./output" \
  -b hybrid-engine \
  --effort high \
  -m auto \
  -l ch \
  -f True \
  -t True \
  --image-analysis True \
  --start 0 \
  --end 10

这条命令的意思是：用 hybrid-engine（高精度模式）解析发票 PDF 的前 11 页，启用公式和表格识别。

4. JSON 配置文件

MinerU 会在 ~/mineru.json 寻找配置文件（可通过环境变量 MINERU_TOOLS_CONFIG_JSON 修改路径）。

我们来看项目根目录下的模板文件 mineru.template.json：

{
    "bucket_info": {
        "bucket-name-1": ["ak", "sk", "endpoint"],
        "bucket-name-2": ["ak", "sk", "endpoint"]
    },
    "latex-delimiter-config": {
        "display": { "left": "$$", "right": "$$" },
        "inline": { "left": "$", "right": "$" }
    },
    "llm-aided-config": {
        "title_aided": {
            "api_key": "your_api_key",
            "base_url": "https://dashscope.aliyuncs.com/compatible-mode/v1",
            "model": "qwen3.5-plus",
            "enable_thinking": false,
            "enable": false
        }
    },
    "models-dir": {
        "pipeline": "",
        "vlm": ""
    },
    "model-source": "auto",
    "config_version": "1.3.2"
}
字段说明
bucket_info S3 存储配置。如果解析结果需要存到 S3，在这里配置 AccessKey、SecretKey 和 Endpoint
latex-delimiter-config LaTeX 公式的分隔符样式。行间公式默认 $$，行内公式默认 $
llm-aided-config LLM 辅助功能（如标题修正）。需要配置 API Key 和模型名，默认关闭
models-dir 本地模型路径。如果提前下载了模型，可以指定路径避免自动下载
model-source 模型下载源：auto / huggingface / modelscope
config_version 配置文件版本号，供 MinerU 向前兼容

这个配置文件的读取逻辑在 mineru/utils/config_reader.py，它被 read_config() 函数加载后被各个模块使用。

5. 环境变量

MinerU 使用多个 MINERU_* 环境变量来控制运行时行为。下面是重要的几个：

环境变量说明示例
MINERU_MODEL_SOURCE 模型下载源。huggingface（国际）或 modelscope（国内镜像）。国内用户推荐设为 modelscope export MINERU_MODEL_SOURCE=modelscope
MINERU_TOOLS_CONFIG_JSON 自定义配置文件路径（默认 ~/mineru.json） export MINERU_TOOLS_CONFIG_JSON=/path/to/custom.json
MINERU_LOG_LEVEL 日志级别。DEBUG / INFO / WARNING / ERROR。设为 DEBUG 可以看到详细处理过程 export MINERU_LOG_LEVEL=DEBUG
MINERU_VLM_FORMULA_ENABLE VLM 引擎的公式解析开关 export MINERU_VLM_FORMULA_ENABLE=true
MINERU_VLM_TABLE_ENABLE VLM 引擎的表格解析开关 export MINERU_VLM_TABLE_ENABLE=true
MINERU_LMDEPLOY_DEVICE LMDeploy 推理设备类型（可用于指定华为昇腾等国产芯片） export MINERU_LMDEPLOY_DEVICE=npu
MINERU_API_OUTPUT_ROOT API 模式下的输出根目录 —
MINERU_ROUTER_UPSTREAM_URLS_JSON Router 服务的上游服务地址列表（JSON 数组） export MINERU_ROUTER_UPSTREAM_URLS_JSON='["http://host1:8000","http://host2:8000"]'
🌟 最常用的环境变量

MINERU_MODEL_SOURCE=modelscope — 在国内网络环境下设置这个变量，模型下载速度会从"几 KB/s"变成"几 MB/s"。你可以在 demo/demo.py 第 248 行看到这个提示注释。

6. 实战技巧

场景 1：快速批量扫描文档

# 用 pipeline 引擎，强制 OCR，输入一个目录
mineru -p ./scan_docs/ -o ./output -b pipeline -m ocr

场景 2：高精度解析发票

# 用 hybrid-engine 高精度模式
mineru -p invoice.pdf -o ./output -b hybrid-engine --effort high

场景 3：只提取文字，不要表格和公式

# 关闭表格和公式识别，提升速度
mineru -p report.pdf -o ./output -f False -t False

场景 4：测试前先看详细日志

# DEBUG 日志会打印每个处理步骤的详细信息
export MINERU_LOG_LEVEL=DEBUG
mineru -p test.pdf -o ./output

场景 5：国内网络，指定模型路径

# 先设置国内镜像源
export MINERU_MODEL_SOURCE=modelscope
# 或者手动下载模型后指定路径
# vi ~/mineru.json → 设置 models-dir.pipeline 和 models-dir.vlm

场景 6：服务器-客户端模式

# 服务端（有 GPU）
mineru-api --port 8000

# 客户端（无 GPU 的笔记本）
mineru -p doc.pdf -o ./output --api-url http://server:8000

7. 小测验

问题 1： 要只解析 PDF 的 第 1-3 页，正确的参数是？

  1. --start 0 --end 2
  2. --start 1 --end 3
  3. --start 0 --end 3
  4. --start 1 --end 2
查看答案

A。页码从 0 开始计数。start=0,end=2 表示解析第 0,1,2 页，即第 1-3 页。

问题 2： 在国内网络环境下，下载模型太慢怎么办？

  1. 没办法，只能等
  2. 设置 MINERU_MODEL_SOURCE=modelscope
  3. 用 --lang ch 加快下载
  4. 关掉公式解析
查看答案

B。ModelScope 是阿里云托管的模型仓库，国内访问速度远快于 HuggingFace。设置环境变量或修改 ~/mineru.json 中的 model-source 即可。

问题 3： pipeline 引擎下，force_txt 和 force_ocr 是什么参数？

  1. 没有这个参数，对应的是 --method txt 和 --method ocr
  2. 在配置文件中设置的字段
  3. 环境变量
  4. 上述都不对
查看答案

A。CLI 中使用 --method（简写 -m）来指定解析方式，可选 auto / txt / ocr。
