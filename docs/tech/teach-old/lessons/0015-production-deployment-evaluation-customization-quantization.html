1.3 systemd unit：mineru-vllm.service

vLLM 是推理引擎，必须先于 FastAPI 启动。把它注册为 systemd 服务：

sudo tee /etc/systemd/system/mineru-vllm.service << 'EOF' [Unit] Description=MinerU vLLM Inference Engine After=network.target [Service] Type=simple User=mineru Group=mineru WorkingDirectory=/home/mineru Environment="MINERU_MODEL_SOURCE=modelscope" Environment="CUDA_VISIBLE_DEVICES=0" # 启动 vLLM 服务 ExecStart=/home/mineru/.local/bin/mineru-vllm-server \ --port 30000 \ --model opendatalab/MinerU2.5-Pro-2605-1.2B \ --gpu-memory-utilization 0.85 \ --max-model-len 32768 # 健康检查：等 /health 返回 200 才算启动成功 ExecStartPost=/bin/bash -c ' \ for i in {1..60}; do \ if curl -s http://localhost:30000/health > /dev/null 2>&1; then \ exit 0; \ fi; \ sleep 2; \ done; \ exit 1' Restart=always RestartSec=10 # 被 OOM kill 后自动重启 TimeoutStartSec=180 # 日志输出到 journald StandardOutput=journal StandardError=journal SyslogIdentifier=mineru-vllm [Install] WantedBy=multi-user.target EOF # 创建 mineru 用户（如不存在） sudo useradd -r -s /bin/false mineru 2>/dev/null || true sudo chown -R mineru:mineru /home/mineru/.cache/modelscope

1.4 systemd unit：mineru-api.service

FastAPI 依赖 vLLM，用 Requires 和 After 确保启动顺序：

sudo tee /etc/systemd/system/mineru-api.service << 'EOF' [Unit] Description=MinerU FastAPI Service Requires=mineru-vllm.service After=mineru-vllm.service [Service] Type=simple User=mineru Group=mineru WorkingDirectory=/home/mineru Environment="MINERU_MODEL_SOURCE=modelscope" Environment="MINERU_API_OUTPUT_ROOT=/data/mineru/output" Environment="MINERU_LOG_LEVEL=INFO" Environment="MINERU_API_ENABLE_FASTAPI_DOCS=0" # 绑定 127.0.0.1，只接受 Nginx 转发 ExecStart=/home/mineru/.local/bin/mineru-api \ --host 127.0.0.1 \ --port 8000 ExecStartPost=/bin/bash -c ' \ for i in {1..30}; do \ if curl -s http://127.0.0.1:8000/health > /dev/null 2>&1; then \ exit 0; \ fi; \ sleep 1; \ done; \ exit 1' Restart=always RestartSec=5 TimeoutStartSec=120 StandardOutput=journal StandardError=journal SyslogIdentifier=mineru-api [Install] WantedBy=multi-user.target EOF
安全要点：FastAPI 绑定 127.0.0.1 而非 0.0.0.0——外部流量必须走 Nginx，不能绕过反代直接访问。vLLM 同样只在本机监听，不对外暴露。

1.5 Nginx 反向代理

sudo tee /etc/nginx/sites-available/mineru << 'EOF' # 限流区域：每秒 10 个请求，burst 20 limit_req_zone $binary_remote_addr zone=mineru_limit:10m rate=10r/s; upstream mineru_api { server 127.0.0.1:8000; } server { listen 80; server_name mineru.example.com; # base64 图片可能很大 client_max_body_size 100m; # OCR 解析可能慢 proxy_read_timeout 300s; proxy_send_timeout 300s; access_log /var/log/nginx/mineru-access.log; error_log /var/log/nginx/mineru-error.log; location / { limit_req zone=mineru_limit burst=20 nodelay; proxy_pass http://mineru_api; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_set_header X-Forwarded-Proto $scheme; } # /docs 只在开发环境开，生产关掉 location /docs { deny all; } location /redoc { deny all; } } server { listen 443 ssl; server_name mineru.example.com; ssl_certificate /etc/ssl/certs/mineru.crt; ssl_certificate_key /etc/ssl/private/mineru.key; # 同 HTTP 配置 client_max_body_size 100m; proxy_read_timeout 300s; proxy_send_timeout 300s; location / { limit_req zone=mineru_limit burst=20 nodelay; proxy_pass http://mineru_api; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_set_header X-Forwarded-Proto https; } location /docs { deny all; } location /redoc { deny all; } } EOF # 启用站点 sudo ln -sf /etc/nginx/sites-available/mineru /etc/nginx/sites-enabled/ sudo rm -f /etc/nginx/sites-enabled/default sudo nginx -t && sudo systemctl reload nginx

3. 单证解析的客户化适配

以银行信用证（Letter of Credit, L/C）字段抽取为例——这几乎是最经典的单证解析客户化场景。

3.1 定位：MinerU 做什么 vs 你需要什么

MinerU 能做的：PDF → 结构化 Markdown + middle.json
你额外需要的：从 Markdown 中抽取 issuing_bank、lc_number、amount、expiry_date、beneficiary 等字段

MinerU 做结构解析，字段抽取是下游的信息抽取任务。
不应期望 MinerU 直接吐出字段——而是把它当作管道的第一环。

3.3 Layer 1 客户化：Layout 微调适配信用证版式

信用证的版式特点：字段 key-value 对密集排列、表格格式统一、block 类型全是 text 但语义不同。Layout 微调的目标是让模型精准识别每个字段块的位置。

3.4 Layer 2 字段抽取：三种策略

策略 A：规则匹配（最快落地）

import re LC_PATTERNS = { "issuing_bank": [ r"ISSUING\s*BANK\s*[：:]\s*(.+?)(?:\n|$)", r"开证行\s*[：:]\s*(.+?)(?:\n|$)", r"51A?\s*[：:]\s*(.+?)(?:\n|$)", # SWIFT MT700 格式 ], "lc_number": [ r"(?:L/?C|CREDIT)\s*(?:NO|NUMBER)[. ]*[：:]*\s*([A-Z0-9]{10,20})", r"信用证号\s*[：:]\s*([A-Z0-9]{10,20})", ], "amount": [ r"(?:AMOUNT|AMT)\s*[：:]\s*([A-Z]{3}\s*[\d,]+\.?\d*)", r"金额\s*[：:]\s*([A-Z]{3}\s*[\d,]+\.?\d*)", ], "expiry_date": [ r"(?:EXPIRY|VALID)\s*(?:DATE)?\s*[：:]\s*(\d{6,8})", r"有效期\s*[：:]\s*(\d{4}[-/]\d{2}[-/]\d{2})", ], "beneficiary": [ r"BENEFICIARY\s*[：:]\s*(.+?)(?:\n(?:[A-Z]{2}|$))", r"受益人\s*[：:]\s*(.+?)(?:\n(?:[A-Z]|$))", ], } def extract_lc_fields(markdown_text): fields = {} for field_name, patterns in LC_PATTERNS.items(): for pattern in patterns: match = re.search(pattern, markdown_text, re.IGNORECASE | re.DOTALL) if match: fields[field_name] = match.group(1).strip() break else: fields[field_name] = None return fields

策略 B：LLM few-shot（适应多变格式）

EXTRACT_PROMPT = """你是信用证信息抽取专家。从以下 MinerU 解析的 Markdown 中提取字段。 字段说明： - issuing_bank: 开证银行全称（ISSUING BANK / 开证行 / field 51A） - lc_number: 信用证编号，10-20 位字母数字 - amount: 金额，含币种代码（如 USD 1,250,000.00） - expiry_date: 有效期 YYYYMMDD 或 YYYY-MM-DD - beneficiary: 受益人/出口商全称 找不到填 null。只返回 JSON，不要解释。 示例 Markdown: ISSUING BANK: Bank of China, Shanghai Branch LC NUMBER: LC20260727001 AMOUNT: USD 1,250,000.00 EXPIRY DATE: 20260930 BENEFICIARY: ABC Import & Export Co., Ltd. 输出: {"issuing_bank": "Bank of China, Shanghai Branch", ...} ## 输入 Markdown: {markdown} 输出:""" import openai, json def extract_with_llm(markdown_text): response = openai.chat.completions.create( model="gpt-4o-mini", messages=[{"role": "user", "content": EXTRACT_PROMPT.format(markdown=markdown_text[:3000])}], temperature=0, response_format={"type": "json_object"}, ) return json.loads(response.choices[0].message.content)

策略 C：BERT-CRF 序列标注（高吞吐生产）

当每天处理数万份单证时用 LLM 太慢太贵。用 BERT-CRF 做序列标注，1000 份标注数据就能到 95%+ F1：

3.6 Layer 3 校验

def validate_lc_fields(fields): errors = [] # SWIFT code 格式（8 或 11 位） if swift := fields.get("issuing_bank_swift"): if not re.match(r"^[A-Z]{4}[A-Z]{2}[A-Z0-9]{2}([A-Z0-9]{3})?$", swift): errors.append(f"Invalid SWIFT code: {swift}") # 日期合理性 if date_str := fields.get("expiry_date"): from datetime import datetime date = datetime.strptime(date_str, "%Y%m%d") if date < datetime.now(): errors.append(f"LC already expired: {date_str}") # 必填字段 for field in ["issuing_bank", "lc_number", "amount", "expiry_date", "beneficiary"]: if not fields.get(field): errors.append(f"Missing required field: {field}") return errors

4. 模型量化：int8 / int4 加速推理

4.1 量化的本质

回到第 12 课的知识：每个参数是一个 BF16 浮点数，占 2 字节。量化就是把 2 字节压到 1 字节（int8）甚至 0.5 字节（int4）：

BF16: 12 亿 × 2 字节 = 2.4 GB
int8: 12 亿 × 1 字节 = 1.2 GB（省 50%，速度 +30-50%）
int4: 12 亿 × 0.5 字节 = 0.6 GB（省 75%，速度 +50-80%，精度微降）

4.2 量化方式对比

方式原理精度损失速度提升vLLM 兼容操作复杂度
AWQ 自动识别重要通道并保护，非重要通道量化 极小（1-3%） 30-60% 原生支持 中
GPTQ 用校准数据逐层量化，误差补偿到后续层 很小 30-50% 原生支持 中
bitsandbytes 加载时在线量化 有 不一定快 不兼容 低
GGUF 离线量化 + CPU 推理优化 中 快（CPU 友好） 不兼容 低
推荐 AWQ：精度损失最小、vLLM 原生支持、量化过程 1-2 小时跑完。对于 MinerU 的 1.2B 小模型，AWQ int4 几乎不掉精度。

4.3 AWQ 量化实操

pip install autoawq python -c " from awq import AutoAWQForCausalLM from transformers import AutoTokenizer model_path = './MinerU-Layout-Finetuned' quant_path = './MinerU-Layout-Finetuned-AWQ' model = AutoAWQForCausalLM.from_pretrained(model_path) tokenizer = AutoTokenizer.from_pretrained(model_path) quant_config = { 'zero_point': True, # 非对称量化，精度更好 'q_group_size': 128, # 分组大小，128 最常用 'w_bit': 4, # int4 'version': 'GEMM', # vLLM 兼容格式 } # 校准数据：100-200 张文档图片即可 model.quantize(tokenizer, quant_config=quant_config) model.save_quantized(quant_path) tokenizer.save_pretrained(quant_path) print(f'量化完成') " # 输出文件大小约 0.6 GB（原始 BF16 是 2.4 GB）

4.4 vLLM 加载 AWQ 量化模型

mineru-vllm-server --port 30000 \ --model ./MinerU-Layout-Finetuned-AWQ \ --quantization awq \ --gpu-memory-utilization 0.85 \ --max-model-len 32768

注意 --quantization awq 告诉 vLLM 权重是 int4 格式。不写这个参数 vLLM 会用 BF16 的方式尝试加载 int4 权重 → 报错。

4.5 量化前后精度对比

# 在 50 份验证集上量化前后 CER 对比 import numpy as np def compare_quantization(original_model, quantized_model, val_pdfs): orig_scores = [evaluate_one(pdf, original_model) for pdf in val_pdfs] quant_scores = [evaluate_one(pdf, quantized_model) for pdf in val_pdfs] orig_cer = np.mean([s.cer for s in orig_scores]) quant_cer = np.mean([s.cer for s in quant_scores]) degradation = (quant_cer - orig_cer) / orig_cer * 100 print(f"原始 CER: {orig_cer:.4f}") print(f"量化 CER: {quant_cer:.4f}") print(f"退化: {degradation:.1f}%") # AWQ int4 通常退化 1-3%，int8 退化 < 0.5%

7. 小结

四个核心收获

1. 生产部署的最佳起点是 systemd + Nginx：vLLM 和 FastAPI 各自注册为一个 systemd 服务，Nginx 挡在前面做反代 + 限流 + HTTPS 卸载。FastAPI 绑定 127.0.0.1 不对外暴露，安全性和简洁性同步满足。这种架构在单机 1-2 GPU 场景下完全够用——等流量大到一台机器跑不动时再考虑上 k8s。
2. OmniDocBench 给你四维量化对比报告：Layout mAP / Text CER / Table TEDS / Formula Edit。注册自定义 Adapter 只需实现一个 parse(image_path) → dict 接口。无 OmniDocBench 时自己凑 60 份 GT（3 类 × 20 份）是最低门槛的替代方案。
3. 客户化适配 = 三层架构：MinerU 解析（Layout 微调适配版式）→ 字段抽取（规则/LLM/BERT-CRF 按量选策略）→ 校验输出（格式+一致性+完整性）。每个银行客户的版式差异主要在 Layer 2 的正则上体现，不一定要从头训练模型。
4. AWQ int4 是 1.2B 模型的量化最佳选择：模型从 2.4GB 压到 0.6GB，推理加速 50-80%，精度退化通常 < 2%。vLLM 加 --quantization awq 一键切换。量化后必须跑一次评估确认退化可接受。
