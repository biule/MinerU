1. 1000 份文档的批量 A/B 评估

第 12 课跑通了单次微调，但"微调后到底好了多少"不是靠肉眼盯输出就能回答的。需要一套能复现的量化评估流程。

1.1 评估架构

graph TB A["1000 份 PDF"] --> B["原始模型"] A --> C["微调模型"] B --> D["output_baseline/"] C --> E["output_finetuned/"] D --> F["逐文件对比"] E --> F G["Ground Truth
（人工标注 50-200 份）"] --> F F --> H["指标汇总"] H --> I["统计检验
paired t-test + Cohen's d"] style B fill:#e2e8f0,stroke:#94a3b8 style C fill:#dbeafe,stroke:#3b82f6 style I fill:#d1fae5,stroke:#10b981

核心思路：同一份文档分别经过原始模型和微调模型，产出两份输出，用同一套指标对比。这样每份文档的得分是配对的（paired），可以用 t-test 判断差异是否显著。

1.2 评估指标速查

指标公式适用解读
CER Levenshtein(pred, gt) / len(gt) 文字识别 字级别编辑距离，越低越好。0.05 表示 100 个字里错 5 个
WER Levenshtein(pred_words, gt_words) / len(gt_words) 英文文字 词级别。中文按词算需先分词，按字算等同于 CER
Table Exact Match pred_html == gt_html 的比例 表格 严格：多一个空格就算错
Table TEDS 1 - TreeEditDistance(pred_html, gt_html) / max_nodes 表格 比 Exact Match 宽容，结构对但文字有小差异也能得高分
Formula Edit Levenshtein(pred_latex, gt_latex) / len(gt_latex) 公式 LaTeX 源码的编辑距离，0.02 表示很接近
Layout F1 2×P×R / (P+R)，P=TP/(TP+FP)，R=TP/(TP+FN) 布局 框位置 + 类型都要对，IoU≥0.5 算命中
Layout mAP 多 IoU 阈值下 Precision-Recall 曲线下面积 布局 比 F1 更全面，评估更严格

1.3 批量评估脚本骨架

import json, os, numpy as np from concurrent.futures import ProcessPoolExecutor, as_completed from dataclasses import dataclass from scipy import stats import Levenshtein @dataclass class DocScore: cer: float layout_f1: float table_teds: float def evaluate_one_doc(pdf_path, model_path, output_dir): """单文档解析 + 指标计算（可并行）""" from mineru.do_parse import do_parse from mineru.utils.enum_class import ModelPath old = ModelPath.vlm_root_hf ModelPath.vlm_root_hf = model_path try: do_parse(pdf_path=pdf_path, output_dir=output_dir, parse_method="hybrid") finally: ModelPath.vlm_root_hf = old with open(os.path.join(output_dir, "middle.json")) as f: return json.load(f) def compute_metrics(pred_json, gt_json): """对一个文档的 pred vs gt 算出全部指标""" # Layout F1 pred_blocks = pred_json["pdf_info"][0].get("para_blocks", []) gt_blocks = gt_json["pdf_info"][0].get("para_blocks", []) layout = compute_layout_f1(pred_blocks, gt_blocks, iou_thresh=0.5) # CER pred_text = extract_all_text(pred_json) gt_text = extract_all_text(gt_json) cer = Levenshtein.distance(pred_text, gt_text) / max(len(gt_text), 1) return DocScore(cer=cer, layout_f1=layout, table_teds=...) def run_ab_eval(pdf_dir, gt_dir, baseline_path, finetuned_path, n_workers=4): """批量 A/B 评估主流程""" pdfs = [f for f in os.listdir(pdf_dir) if f.endswith(".pdf")] baseline_scores, finetuned_scores = [], [] for model_name, model_path in [("baseline", baseline_path), ("finetuned", finetuned_path)]: scores = [] with ProcessPoolExecutor(max_workers=n_workers) as ex: futures = {} for pdf in pdfs: out = f"eval_output/{model_name}/{pdf.replace('.pdf','')}" os.makedirs(out, exist_ok=True) futures[ex.submit(evaluate_one_doc, os.path.join(pdf_dir, pdf), model_path, out)] = pdf for fut in as_completed(futures): pdf = futures[fut] try: pred = fut.result() gt_path = os.path.join(gt_dir, pdf.replace(".pdf", ".json")) with open(gt_path) as f: gt = json.load(f) scores.append(compute_metrics(pred, gt)) except Exception as e: print(f"FAIL {model_name} on {pdf}: {e}") if model_name == "baseline": baseline_scores = scores else: finetuned_scores = scores # 统计检验 b = [s.cer for s in baseline_scores] f = [s.cer for s in finetuned_scores] t_stat, p_value = stats.ttest_rel(f, b) diffs = [f_i - b_i for f_i, b_i in zip(f, b)] cohens_d = np.mean(diffs) / np.std(diffs) return { "baseline_cer": np.mean(b), "finetuned_cer": np.mean(f), "cer_improvement": np.mean(diffs), "p_value": p_value, "cohens_d": cohens_d, "significant": p_value < 0.05, }

1.4 统计检验的意义

paired t-test → p-value < 0.05 说明"微调模型比原始模型好"不是随机波动
Cohen's d → 0.2 小效果 / 0.5 中效果 / 0.8 大效果

为什么不用简单的平均值对比？ 假设 CER 从 0.08 降到 0.075，看起来好了 6%。但如果 1000 份里有 600 份变好、400 份变差，平均下来是 0.005 的改善——你不做统计检验就不知道这 0.005 是否可信。t-test 告诉你这个改善是否一致，Cohen's d 告诉你幅度是否值得在乎。

1.5 无 Ground Truth 时的替代方案

方案做法成本可信度
随机抽 50 份人工看 挑 50 份输出，盲评 A/B 谁更好，统计胜率 2-4 小时 高（最有说服力）
GPT-4 做 judge 把两份输出喂给 GPT-4，让它判断哪个更好 API 费用 中（GPT-4 对格式错误敏感但对细微结构差异可能漏判）
启发式信号 统计输出中的异常：空块比例、表格 HTML 合法率、LaTeX 渲染通过率 零 低（只能发现明显的退化，不能证明变好）
下游任务表现 把 MinerU 输出喂给 RAG 系统或 LLM 问答，对比最终准确率 中 高（你的真实场景才是终极 judge）
最务实的策略：先看启发式信号（有没有大量异常输出），再用 GPT-4 粗筛，最后人工确认 50 份。三层过滤，把人工精力花在最有价值的样本上。

2. LoRA 算术：Adapter 叠加

2.1 原理

回顾第 12 课：LoRA 的 ΔW = B·A，训练出来的是权重增量（delta），不是完整权重。多个 adapter 的 delta 可以线性组合：

Wmerged = Wbase + α1·ΔW1 + α2·ΔW2 + α3·ΔW3
                     ↑          ↑          ↑
              Layout 适配  表格增强  公式增强

这个性质叫任务算术（Task Arithmetic）——每个 adapter 编码了一种"能力"，合并就是叠加能力。

2.2 三种叠加方式

方式适用场景难度
PEFT add_weighted_adapter 快速实验、调权重 低
LLaMA-Factory 多数据集联合训练 从一开始就计划多能力 中
手动合并 safetensors 部署时减少加载复杂度 中
经验法则：实验阶段用 PEFT add_weighted_adapter 快速试 α 值；验证完成后用 LLaMA-Factory 联合训练（效果好于事后合并）；部署时手动合并成一个 safetensors 文件。

方式一：PEFT add_weighted_adapter

from peft import PeftModel from transformers import AutoModelForCausalLM base = AutoModelForCausalLM.from_pretrained( "opendatalab/MinerU2.5-Pro-2605-1.2B", device_map="cpu" ) # 加载多个 adapter，每个给一个名字 model = PeftModel.from_pretrained(base, "path/to/layout_adapter", adapter_name="layout") model.load_adapter("path/to/table_adapter", adapter_name="table") model.load_adapter("path/to/formula_adapter", adapter_name="formula") # 加权合并 model.add_weighted_adapter( adapters=["layout", "table", "formula"], weights=[1.0, 0.5, 0.3], adapter_name="merged", combination_type="svd", # "svd" / "linear" / "cat" ) # 激活合并后的 adapter model.set_adapter("merged") model.save_pretrained("path/to/merged_adapter")

方式二：LLaMA-Factory 联合训练（效果最好）

把 Layout + 表格 + 公式的数据合成一份 JSON，YAML 中直接挂多个数据集：

# YAML 配置 dataset: mineru_layout_base, mineru_layout_invoice, mineru_table_enhance # LLaMA-Factory 自动 mix，每个 batch 按比例均匀采样

联合训练比事后合并好的原因：训练过程中梯度来自所有任务，模型学会了在共享表示层协调不同能力。事后合并两个独立训练的 adapter 时，它们在共享层上的改动可能互相冲突。

方式三：手动合并 safetensors

from safetensors.torch import load_file, save_file def merge_lora_weights(base_path, adapter_specs, output_path): """adapter_specs = [("path1", 1.0), ("path2", 0.5), ...]""" base = load_file(f"{base_path}/model-00001-of-00002.safetensors") for adapter_path, alpha in adapter_specs: delta = load_file(f"{adapter_path}/adapter_model.safetensors") for key in delta: if key in base: base[key] = base[key] + alpha * delta[key].to(base[key].dtype) save_file(base, f"{output_path}/model-00001-of-00002.safetensors")

2.3 什么能叠加、什么不能

场景可行性说明
Layout 适配发票 + Layout 适配合同效果好同一任务域的不同子分布，1+1>2
中文增强 + 日文增强可行多语言 adapter 是 LoRA 经典用法
Layout 适配 + 表格识别增强需调权重不同层有交互，α 值需要网格搜索
Layout 增强 + 公式识别增强需调权重同上，共享层的梯度方向可能不完全一致
两个不同 rank 的 adapter不能直接加A·B 的维度不匹配，必须先 resample 到相同 rank
训练时用了不同 lora_alpha需折算ΔW = (alpha/r) × B·A，合并前需统一缩放因子

2.4 权重搜索

合并权重 α 不是你猜出来的，是在小验证集上扫描出来的：

best_alpha, best_score = None, 0 for alpha in [0.1, 0.3, 0.5, 0.7, 0.9, 1.0, 1.2, 1.5]: merged = merge(W_base, [ (layout_adapter, 1.0), # 主 adapter 权重固定 (table_adapter, alpha), # 辅助 adapter 权重扫描 ]) score = evaluate_on_val_set(merged, val_pdfs) # 50 份验证集 if score > best_score: best_score, best_alpha = score, alpha print(f"最佳 table adapter 权重 α = {best_alpha}")

α > 1.0 有时也有效——这意味着这个 adapter 学到的方向对当前任务有帮助，但原始训练数据量不够。α > 2.0 还不收敛说明两个 adapter 的梯度方向冲突，不如联合训练。

3. 训练数据增强

数据不够、标注太贵、又不想退化质量——数据增强是量变到质变的杠杆。

3.1 文档图片增强工具箱

import albumentations as A doc_transform = A.Compose([ # ---- 几何变换（Layout 任务必须同步更新 bbox！）---- A.Rotate(limit=5, border_mode=0, p=0.3), # ±5° 微旋转 A.Perspective(scale=(0.01, 0.03), p=0.2), # 轻微透视 A.Affine(scale=(0.9, 1.1), translate_percent=(0, 0.05), p=0.2), # ---- 像素级退化（模拟扫描/拍照）---- A.GaussNoise(var_limit=(5, 20), p=0.3), # 扫描噪声 A.GaussianBlur(blur_limit=(1, 3), p=0.2), # 轻微失焦 A.ImageCompression(quality_lower=70, quality_upper=95, p=0.3), # ---- 光照变化 ---- A.RandomBrightnessContrast(brightness_limit=0.1, contrast_limit=0.1, p=0.3), A.CLAHE(clip_limit=2.0, p=0.1), # ---- 分辨率变化 ---- A.Downscale(scale_min=0.5, scale_max=0.9, p=0.2), # ---- 文档特有伪影 ---- A.CoarseDropout(max_holes=4, max_height=8, max_width=8, p=0.1), ], # Layout 任务专用：同步变换 bbox bbox_params=A.BboxParams( format='pascal_voc', label_fields=['class_labels'], min_visibility=0.3 ) )

3.2 Layout Detection 增强的关键约束

对 Layout 任务做几何增强时，bbox 坐标必须同步变换，否则标签和图片就对不上了。这是整个增强流程最容易出错的点：

def augment_layout_sample(image, bboxes, class_labels): """Layout 样本增强：同步变换图片和 bbox""" transformed = doc_transform( image=image, bboxes=bboxes, # [[x1,y1,x2,y2], ...] class_labels=class_labels # ["title", "text", "table", ...] ) aug_image = transformed["image"] aug_bboxes = transformed["bboxes"] aug_labels = transformed["class_labels"] # 把新 bbox 转回训练 token 串（归一化到 0-1000） h, w = aug_image.shape[:2] lines = [] for (x1, y1, x2, y2), label in zip(aug_bboxes, aug_labels): lines.append( f"<|box_start|>{int(x1/w*1000)} {int(y1/h*1000)} " f"{int(x2/w*1000)} {int(y2/h*1000)}<|box_end|>" f"<|ref_start|>{label}<|ref_end|>" ) return aug_image, "\n".join(lines)
重要：albumentations 的几何变换在极端情况下可能裁掉部分 bbox。设置 min_visibility=0.3 意味着一个 bbox 被裁掉超过 70% 时直接丢弃这条样本——这比带着错误标签训练好得多。

3.3 Content Extraction 增强（更自由）

Content 任务不涉及坐标，增强可以更激进：

content_transform = A.Compose([ A.Rotate(limit=3, p=0.2), A.Affine(scale=(0.95, 1.05), p=0.2), A.OneOf([ A.GaussNoise(var_limit=(10, 30)), A.GaussianBlur(blur_limit=(1, 3)), A.ImageCompression(quality_lower=60, quality_upper=90), ], p=0.3), A.RandomBrightnessContrast(p=0.3), ])

3.4 合成数据：零成本放量

用不同字体渲染同一段文字，一条标注生成 10 条变体：

from PIL import Image, ImageDraw, ImageFont import random FONTS = [ "C:/Windows/Fonts/simhei.ttf", # 黑体 "C:/Windows/Fonts/simsun.ttc", # 宋体 "C:/Windows/Fonts/msyh.ttc", # 微软雅黑 "C:/Windows/Fonts/kaiu.ttf", # 楷体 "C:/Windows/Fonts/simfang.ttf", # 仿宋 ] def render_text_variants(text, fonts=FONTS, n=10): """同一段文字 × 不同字体 × 不同大小 = 数据量 ×10""" variants = [] for _ in range(n): font = ImageFont.truetype(random.choice(fonts), size=random.randint(14, 24)) # 量文字尺寸 temp = Image.new("RGB", (500, 50), "white") draw = ImageDraw.Draw(temp) bbox = draw.textbbox((0, 0), text, font=font) w, h = bbox[2]-bbox[0], bbox[3]-bbox[1] # 渲染 img = Image.new("RGB", (w+20, h+10), "white") draw = ImageDraw.Draw(img) color = tuple(random.randint(0, 40) for _ in range(3)) draw.text((10, 5), text, font=font, fill=color) variants.append(img) return variants

这个方法的前提是：你有少量真实的文字标注（作为 seed），然后靠字体/大小/颜色组合爆炸来扩量。对表格和公式无效——表格的结构复杂性无法从单条标注中自动变体。

3.5 增强策略决策表

数据量增强策略增强倍数注意事项
< 200 条 全部开：几何 + 像素 + 合成字体渲染 15-20× 必须人工抽查增强后的图片是否还像真实文档
200-500 条 几何 + 像素各 0.3 概率，合成字体 5 变体 5-8× 几何增强概率不宜太高，避免坐标漂移积累
500-2000 条 只开像素增强，关闭几何变换 2-3× 此时坐标质量比数量重要
> 2000 条 只开轻微 brightness/contrast 1.5× 数据量够大，增强主要防过拟合

4.2 DeepSpeed ZeRO-3 配置

4.4 数据量级与过拟合风险

数据规模效果预期
< 5,000 条几乎一定过拟合，不建议全参
5,000-20,000 条勉强可跑，需强正则化 + 必须混入通用领域数据
20,000-100,000 条合理区间，全参优势开始显现
> 100,000 条全参的全量表示能力得到充分利用
灾难性遗忘的防御：无论多少数据，必须混入 10-20% 通用领域数据（学术论文/杂志/网页 PDF）。否则你的模型会成为"发票专家"但对其他文档彻底废掉。这意味着标注数据里要刻意保留一些"看起来跟你的任务没关系"的通用页面。

4.5 监控体系

全参训练跑 3-7 天，你需要 watch 这六个信号：

wandb.log({ "train/loss": loss, # 应该在下降，突然不动 = lr 太小 "train/lr": lr, # 跟随 scheduler "train/grad_norm": grad_norm, # 突然超过 10× 正常值 = 梯度爆炸 "train/throughput": samples_per_sec, # 突然下降 = 某张卡可能挂了 "eval/layout_f1": layout_f1, # 验证集指标，连续 3 次不涨考虑 early stop "system/gpu_util": gpu_util, # 长期 < 80% = dataloader 是瓶颈 "system/gpu_memory": gpu_mem, # 接近 100% = 离 OOM 不远 })

梯度范数告警：设置一个监控脚本，grad_norm 超过历史均值 10 倍时发通知。全参训练中梯度爆炸是最常见的崩溃原因，往往发生在训练 2-3 小时后——你不会一直盯着终端。

4.6 Checkpoint 策略

# YAML 配置 save_strategy: steps save_steps: 200 # 每 200 步存一次 save_total_limit: 3 # 只保留最近 3 个（节省空间） metric_for_best_model: eval_layout_f1 load_best_model_at_end: true # 训练结束加载最佳模型 greater_is_better: true # 断点续训 # deepspeed --num_gpus=8 src/train.py ... --resume_from_checkpoint saves/checkpoint-1200

4.8 决策清单

全参微调前逐条确认
□ 有 ≥ 4×A100 80GB？（没有 → 回去用 LoRA）
□ 有 ≥ 20,000 条高质量标注数据？（没有 → 回去扩数据）
□ 混入了 10-20% 通用领域数据防遗忘？（没有 → 回去补数据）
□ 搭建了 WandB 监控 + 梯度告警？（没有 → 搭好再来）
□ 做过 LoRA 实验确认"方向值得全参"？（没有 → 先做 LoRA 验证方向）
□ 跑通过小规模试探（100 步）验证不 OOM？（没有 → 先 dry run）
□ 有能力排查 DeepSpeed ZeRO-3 错误？（没有 → 找有经验的同事护航）
务实的建议

LoRA 能解决 80% 的实际问题。全参是剩下 20% 的放大器——如果方向对，放大效果；如果方向错，放大错误。大多数场景下，多做一轮数据清洗的收益 > 从 LoRA 切到全参的收益。

7. 小结

四个核心收获

1. 批量 A/B 评估靠配对的统计检验：同一份文档分别过两个模型，用 CER / Layout F1 / Table TEDS 量化差距，paired t-test + Cohen's d 判断差异是否显著。没有 GT 时用启发式信号 → GPT-4 粗筛 → 人工确认的三层过滤。
2. LoRA adapter 可以像乐高一样拼接：PEFT add_weighted_adapter 加权合并，α 值在小验证集上网格搜索。但事后合并不如多数据集联合训练效果好——梯度来自所有任务时模型能协调共享表示。
3. 数据增强是投入产出比最高的杠杆：200 条精准标注 + albumentations 几何/像素/合成字体 = 等效 2000 条。Layout 增强的关键是 bbox 同步变换，min_visibility=0.3 防止残缺标签污染训练。
4. 全参微调是正确方向的放大器：需要 ≥ 4×A100 + ≥ 20,000 条数据 + 通用领域数据防遗忘 + DeepSpeed ZeRO-3 + WandB 监控。大多数情况多做一轮数据清洗比切全参更划算。
