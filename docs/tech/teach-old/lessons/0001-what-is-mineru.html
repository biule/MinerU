1. 一个被低估的难题

假设你手头有 1000 份 PDF 发票，想自动提取出所有发票号码、日期和金额。

你可能会想："这不就是复制粘贴吗？"—— 但现实远比这复杂。

PDF 的"美丽谎言"

PDF 的设计初衷是"无论在哪台设备上打开，看起来都一样"。它记录的是"把这段文字放在这个坐标"，而不是"这是一个标题，这是一个表格单元格"。所以 PDF 本质上是一组绘图指令，不是结构化文档。

⚠️ 常见的坑

即便是最简单的 PDF，直接用代码提取文字也可能遇到：文字顺序错乱、同一段落被拆成多个碎片、表格无法识别、公式变成乱码。扫描件本质是图片，连文字都"没有"。

这就需要一个工具来理解文档的结构——这就是文档解析（Document Parsing）。

2. 什么是 MinerU？

MinerU 是一个开源的高精度文档解析引擎，由上海人工智能实验室（OpenDataLab）开发，诞生于 InternLM 大模型的预训练过程中。

属性说明
开发者OpenDataLab（上海人工智能实验室）
当前版本3.4.4
输入格式PDF、图片（JPG/PNG/...）、DOCX、PPTX、XLSX
输出格式Markdown、JSON
许可证MinerU 开源许可证（基于 Apache 2.0）
GitHub Stars28k+

它能做什么？

  • 把 PDF（包括扫描件）转成结构清晰的 Markdown
  • 识别文档中的 标题层级（h1、h2、h3...）
  • 提取 表格 并转为 HTML 格式
  • 将 数学公式 转为 LaTeX
  • 提取 图片 及其描述
  • 自动删除页眉、页脚、页码等干扰信息
  • 支持 109 种语言 的 OCR 识别

它不能做什么？

  • 不能"理解"文档内容的语义（它做的是结构解析，不是文档问答）
  • 不能生成新的文档（它读文档，不写文档）
  • 不是通用的 PDF 编辑器

3. 核心概念速览

PDF 的两种"性格"

PDF 实际上分两种，MinerU 对它们的处理方式完全不同：

类型描述MinerU 怎么做
文本型 PDF由文字构成（如 Word 导出的 PDF）直接提取文字 → 分析布局
扫描型 PDF由图片构成（如扫描仪生成的 PDF）先用 OCR 识别图中文字 → 再分析布局

MinerU 能自动检测 PDF 的类型，你不用手动区分。

三个处理引擎 重要

MinerU 提供三个解析引擎，你可以在使用前选择：

引擎特点适合场景
pipeline传统深度学习模型分步处理，CPU/GPU 均可，资源占用低普通文档，服务器配置有限
vlm-engine基于视觉语言模型，一步完成理解，精度最高，需要 GPU复杂排版、高精度要求的文档
hybrid-engine 默认推荐混合策略，结合前两者的优势，速度和精度的最佳平衡日常使用，大多数场景

目前你只需要知道有这三个选项，我们后续会详细学习它们的区别。

4. 安装 MinerU

我们先在你的机器上安装 MinerU。确保你已经安装了 Python 3.10 ~ 3.13。

检查 Python 版本

python --version

应该显示 Python 3.10.x 到 3.13.x。如果版本过低，请先升级 Python。

安装 uv（推荐）或直接使用 pip

MinerU 官方推荐使用 uv 来安装，速度更快：

pip install uv

或者直接使用 pip 也可以，只是慢一些。

安装 MinerU

uv pip install -U "mineru[all]"

这个命令会安装 MinerU 及其所有依赖（包括 pipeline 和 VLM 后端）。

验证安装

mineru --help

如果看到帮助信息，说明安装成功。

💡 安装提示

在项目的 pyproject.toml 中可以看到，MinerU 的依赖分为几个可选组：pipeline（传统引擎）、vlm（VLM 引擎）、gradio（Web 界面）等。[all] 会安装全部。如果只想安装轻量版，可以只装 mineru 基本包。

5. 第一次解析：跑通一个文档

安装完成后，我们用 MinerU 自带的 demo 来解析一个示例 PDF。

使用 demo 目录

在 MinerU 项目根目录下，有一个 demo/ 文件夹，里面包含示例 PDF 和 Office 文档：

ls demo/pdfs/

运行解析

mineru demo/pdfs --output-dir demo/output

这里 demo/pdfs 是输入目录（包含示例 PDF），--output-dir demo/output 指定输出目录。

查看输出

运行完成后，查看输出目录：

ls demo/output/

你会看到每个输入 PDF 对应的输出文件夹，里面包含：

  • *.md — 解析结果的 Markdown 文件
  • *.json — 解析结果的 JSON 文件（如果开启）
  • images/ — 提取出的图片
🎉 恭喜！

你已经成功完成了第一次文档解析。打开 .md 文件，比较一下与原始 PDF 的差异。你会看到 MinerU 自动去除了页眉页脚，保留了标题层级，表格和公式都被正确识别了。

6. 理解输出：Markdown

Markdown 是一种轻量级标记语言，它用简单的符号表示格式：

原始 PDFMarkdown 输出
大标题# 大标题
小标题## 小标题
粗体**粗体**
列表项- 列表项
表格| 列1 | 列2 |
公式 E=mc²$$ E=mc^2 $$
图片![图片描述](images/xxx.jpg)

Markdown 的好处是：人类可读、机器友好、可以方便地导入各种系统（LLM、RAG、文档管理系统）。

7. 小测验：检查你的理解

问题 1： 下列哪种 PDF 需要 OCR 才能提取文字？

  1. 从 Word 导出的 PDF
  2. 扫描仪生成的 PDF
  3. 从 Chrome 打印的 PDF
  4. LaTeX 编译的 PDF
查看答案

B。扫描仪生成的 PDF 实际上是图片，不经过 OCR 无法提取文字。其余三种都是"文本型 PDF"，可以直接提取。

问题 2： MinerU 默认推荐的解析引擎是哪个？

  1. pipeline
  2. vlm-engine
  3. hybrid-engine
  4. 以上都是
查看答案

C。hybrid-engine（混合引擎）是默认推荐，它在速度和精度之间取得最佳平衡。pipeline 资源需求低，vlm-engine 精度最高但需要 GPU。

问题 3： MinerU 输出哪种文件格式？

  1. 仅 Markdown
  2. 仅 JSON
  3. Markdown 和 JSON
  4. PDF
查看答案

C。MinerU 可以输出 Markdown 和/或 JSON 格式。Markdown 适合人类阅读和 LLM 输入，JSON 适合程序进一步处理。
