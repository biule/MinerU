1. 前置知识：模型"权重"到底是什么

第 11 课反复提到"权重"这个词，但没展开解释。这一节把它彻底讲清楚——这是理解微调的前提。

1.1 权重 = 神经网络里的可学习参数

一个神经网络由很多层（Layer）组成，每一层做一次数学变换。以最简单的线性层为例：

y = x · W + b x：输入向量（比如 4096 个浮点数） W：权重矩阵（比如 4096×4096 个浮点数） ← 这就是"权重" b：偏置向量（4096 个浮点数） ← 这也是"权重"的一部分

训练的过程就是不断调整 W 和 b 里的值，让输出 y 越来越接近正确答案。这些值就是参数（Parameters），也叫权重（Weights）。

MinerU 用的 MinerU2.5-Pro-2605-1.2B，1.2B = 12 亿个参数。每一个参数是一个浮点数，所以：

12 亿参数 × 每个占用字节数 = 模型文件大小
12 亿 × 2 字节 (FP16/BF16) ≈ 2.4 GB 的纯权重数据
12 亿 × 4 字节 (FP32) ≈ 4.8 GB 的纯权重数据

1.2 不同精度的权重

同一个数字可以用不同的精度存储——精度越高，占空间越大，但计算越准确：

4 字节
FP32（全精度）
训练时常用
2 字节
FP16 / BF16（半精度）
推理最常用，省一半
1 字节
int8（量化）
推理加速，精度微降
0.5 字节
int4（量化）
极端压缩，精度明显下降

MinerU 的模型分发时用的是 BF16，每个参数 2 字节。如果你下载的 .safetensors 文件总大小约 2.4 GB，说明你拿到的是 BF16 权重。

1.3 模型文件 ≠ 只有权重

一个能跑起来的模型至少需要这些文件：

文件内容如果缺失会怎样
model-00001-of-00002.safetensors
model-00002-of-00002.safetensors		 12 亿个浮点数——模型的"知识" 无法推理，相当于只有脑细胞但没有脑结构
config.json 网络架构定义：多少层、每层多大、激活函数类型 transformers 不知道用什么类加载，直接报错
tokenizer.json / vocab.json 词表：把文字切成 token 的规则 文字无法转换成模型能理解的数字
preprocessor_config.json 图片怎么 resize、归一化参数 图片预处理参数不对，输出乱码
为什么用 .safetensors 而不是 .bin（Pickle）？

Pickle 是 Python 的序列化格式，加载时可以执行任意代码——恶意模型文件能在你 import 时窃取数据。safetensors 是纯数据格式，不包含可执行代码，加载更快，且支持内存映射（mmap）——不用一次读完整个文件。HuggingFace 现在默认用 safetensors 就是这个原因。

1.4 权重矩阵怎么被"训练"

训练的本质就三步循环：

graph LR A["① 前向传播
输入 × 权重 → 预测"] --> B["② 计算 Loss
预测 vs 标准答案 差距"] B --> C["③ 反向传播
算梯度 → 更新权重"] C --> A style A fill:#dbeafe,stroke:#3b82f6 style B fill:#fef3c7,stroke:#f59e0b style C fill:#d1fae5,stroke:#10b981

每次循环中，每个权重参数都往"让 Loss 变小"的方向挪一点点。这个"挪多少、往哪挪"由梯度（Gradient）和学习率（Learning Rate）共同决定：

W_new = W_old - learning_rate × gradient

12 亿个参数，每个都这样更新——所以训练需要巨大的算力。

2. 微调 = 改权重：三种改变方式

有了上面的基础，理解微调就很容易了。微调就是从一个已经训练好的模型（基座模型）出发，用你自己的数据继续训练，让权重向你的场景倾斜。

2.1 三种方式对比

方式改多少参数显存需求数据量训练速度
全参微调 全部 12 亿个 ≥4×A100 (80GB) 万页级 慢（几天）
LoRA（低秩适配） 约 100-200 万个
（仅为全量的 0.01-0.1%）		 24GB 单卡 500-3000 页 快（几小时）
冻结 + 分类头 只在最后加几层 很小 很少 很快

2.2 LoRA 为什么能用这么少参数？

LoRA 的核心思想：不改原始权重，而是额外挂一个小的"修正矩阵"。

graph LR subgraph "原始权重（冻结不动）" W["W (4096×4096)
≈ 1600 万个参数"] end subgraph "LoRA 增量（只训练这个）" A["A (4096×16)
≈ 6.5 万参数"] --> B["B (16×4096)
≈ 6.5 万参数"] end X[输入 x] --> W X --> A B --> P[+] W --> P P --> Y[输出 y] style W fill:#e2e8f0,stroke:#94a3b8 style A fill:#dbeafe,stroke:#3b82f6 style B fill:#dbeafe,stroke:#3b82f6
原始：y = x · W LoRA：y = x · W + x · A · B ↑ 冻结不动 ↑ 只训练这俩小矩阵

把 W (4096×4096 ≈ 1600 万参数) 的改动压缩成 A (4096×16) + B (16×4096) ≈ 13 万个参数。r=16 就是你指定的这个"压缩维度"（rank）。

r 值可训练参数显存表达能力
r=8约 6.5 万 / 层最低够用小修小补
r=16约 13 万 / 层适中大多数场景最性价比
r=32约 26 万 / 层更高大幅改动时用
r=64约 52 万 / 层接近全参逼近全参效果但省显存
实践经验

对 MinerU VLM 这种 1.2B 的小模型，r=16 挂在 q_proj / v_proj / o_proj 上，24GB 单卡能跑 batch_size=2。效果已经能覆盖"新版式适配""特定表格格式修正"等常见需求。

4. Step 1 数据构造：Layout Detection

4.1 输出格式

Layout 检测的输出是一串特殊 token，描述图片中每个区域的坐标和类型：

<|box_start|>x1 y1 x2 y2<|box_end|><|ref_start|>block_type<|ref_end|>(<|rotate_up|>)?(txt_contd_tgt)?
Token含义
<|box_start|> / <|box_end|>一对标记，围住一个布局块的边界框
x1 y1 x2 y2四个整数，范围 0-1000 的归一化坐标（不是真实像素）
<|ref_start|> / <|ref_end|>一对标记，围住该块的类型名
<|rotate_up|>可选，表示文字竖排（旋转 90°）
txt_contd_tgt可选，表示该块是上一块的跨页/跨栏延续

4.2 27 种 Block 类型

text — 正文段落 title — 标题 table — 表格 equation — 行内公式 display_formula — 独立公式 code — 代码块 image — 图片 chart — 图表 header — 页眉 footer — 页脚 page_number — 页码 table_caption — 表格标题 figure_caption — 图片标题 footnote — 脚注 list_item — 列表项 reference — 参考文献 abstract — 摘要 keywords — 关键词 author — 作者 affiliation — 机构 date — 日期 doi — DOI acknowledgment — 致谢 appendix — 附录 toc — 目录 algorithm — 算法 other — 其他

4.3 一条完整的训练样本

输入（图片）：page_001.png（整页文档截图，已 resize 到 1036×1036） 输出（文本）： <|box_start|>120 85 880 145<|box_end|><|ref_start|>title<|ref_end|> <|box_start|>120 160 880 320<|box_end|><|ref_start|>abstract<|ref_end|> <|box_start|>120 340 430 580<|box_end|><|ref_start|>text<|ref_end|> <|box_start|>560 340 880 420<|box_end|><|ref_start|>table<|ref_end|> <|box_start|>560 430 880 465<|box_end|><|ref_start|>table_caption<|ref_end|> <|box_start|>120 600 880 720<|box_end|><|ref_start|>text<|ref_end|> <|box_start|>120 740 880 800<|box_end|><|ref_start|>footer<|ref_end|> <|box_start|>850 780 880 800<|box_end|><|ref_start|>page_number<|ref_end|>

关键约束：坐标是 0-1000 归一化值；每行一个 block；block 顺序 = 阅读顺序（上到下、左到右）；每个 <|box_start|> 必须有对应的 <|box_end|>。

4.4 三种数据构造方法

方法怎么做优点缺点
A. 纯人工标注 LabelStudio / CVAT 画框 → Python 脚本导出为 token 串 最准 慢，一小时大概标 10-15 页
B. MinerU 反向生成（推荐起步） 用 MinerU 先解析一遍 → 从 middle.json 提取 block 坐标和类型 → 拼成 token 串 → 人工只纠错 快，人工只看错的 依赖 MinerU 已有一定精度
C. 合成数据（放量用） LaTeX / HTML 渲染文档 → 编译为 PDF → 截图 → 源码中提取精确坐标作为标签 零人工成本、可规模化 合成文档和真实扫描件有 gap
推荐路线

先 B 起步（MinerU 跑 50-100 页目标场景 PDF → middle.json → 脚本转 token 串 → 人工逐条看一眼），覆盖基础版式。遇到 MinerU 完全不对的版式时，用 A 补几十条。想扩量再用 C。

5.3 数据量参考（LoRA 微调）

数据类型最少可跑推荐备注
Step 1（Layout）300 页1000-2000 页覆盖目标场景的版式多样性
Step 2 — Text500 条2000 条覆盖各种文字排版（横排/竖排/多栏）
Step 2 — Table200 条500-1000 条覆盖有线/无线/合并单元格
Step 2 — Formula100 条300-500 条LaTeX 语法准确性是核心质量指标
Step 2 — Image50 条200 条图片描述，量可以少一些
不要混着训：Step 1 和 Step 2 的数据格式完全不同，混在一起训练会让模型困惑。正确的做法是分开训练——先微调 Step 1，导出后评估 Layout 效果；满意后再用同一份导出模型微调 Step 2。

6.3 数据格式转换：ShareGPT 格式

LLaMA-Factory 的多模态数据采用 ShareGPT 格式——一条 JSON 里有 messages 和 images：

[ { "messages": [ { "role": "user", "content": "<image>\nText Recognition:" }, { "role": "assistant", "content": "进料对口" } ], "images": ["images/crop_001.png"] }, { "messages": [ { "role": "user", "content": "<image>\nTable Recognition:" }, { "role": "assistant", "content": "<table>\n<tr><th>项目</th><th>金额</th></tr>\n<tr><td>合计</td><td>1200</td></tr>\n</table>" } ], "images": ["images/crop_002.png"] } ]

对于 Layout Detection（Step 1）的数据，图片是整页文档，assistant 回复是所有 block 的 token 串：

{ "messages": [ { "role": "user", "content": "<image>\nLayout Detection:" }, { "role": "assistant", "content": "<|box_start|>120 85 880 145<|box_end|><|ref_start|>title<|ref_end|>\n<|box_start|>120 160 880 320<|box_end|><|ref_start|>abstract<|ref_end|>\n<|box_start|>120 340 430 580<|box_end|><|ref_start|>text<|ref_end|>" } ], "images": ["images/page_001.png"] }
<image> 占位符

Qwen2-VL 的对话模板会用 <image> 标记图片插入位置。images 数组的顺序必须和 <image> 出现的顺序一致。一条消息里有多张图（如多栏对比），就写多个 <image> 并在 images 数组里按序排好。

7. 关键经验与避坑指南

7.1 数据质量 > 数据数量

LoRA 只有约 0.01% 的参数可训练，所以脏数据的影响会被放大。500 条精准标注的效果远超 5000 条粗标。

数据质量检查清单（每条都过一遍）
□ 每个 <|box_start|> 都有对应的 <|box_end|>
□ 坐标值在 0-1000 范围内
□ block 类型名拼写正确（27 种之一，大小写敏感）
□ Step 2 数据中，Prompt 与该 block 的实际类型一致
□ 表格输出是合法的 OTSL 或 HTML
□ 公式输出是合法的 LaTeX
□ 图片没有损坏、尺寸不为零

7.2 训练策略建议

场景策略数据量预期效果
增加对新版式的识别 只微调 Step 1 (Layout) 500-1000 页新格式 新版式 recall +30-50%
提升特定类型文字识别 只微调 Step 2 (Content) 1000-2000 条 目标类型 CER -20%
适配新语言 两步都微调 各 1000+ 条 中文模型适配日/韩/阿拉伯语等
整体精度提升 先 Step1 后 Step2 串联微调 各 2000+ 条 端到端 WER -15-25%

10. 小结

五个核心收获

1. 权重 = 浮点数矩阵，12 亿个 BF16 参数 ≈ 2.4 GB 的 safetensors 文件。模型文件包含权重 + config.json + tokenizer + processor，缺一不可。
2. 微调 = 用你的数据继续更新权重。全参微调改全部 12 亿个参数，LoRA 只训练挂在原矩阵上的两个小矩阵（约 13 万个参数），省显存 90%+。
3. 数据必须分两步覆盖：Step 1 Layout Detection（整页图 → 特殊 token 串）和 Step 2 Content Extraction（裁块图 + 类型 prompt → 文字/表格/公式）。数据质量比数量重要得多。
4. LLaMA-Factory 是最快上手路线：数据转 ShareGPT JSON → dataset_info.json 注册 → YAML 配好 → llamafactory-cli train 或 WebUI 启动。
5. 训练完要 export 合并再部署——不合并的 LoRA 每次 forward 多算一次矩阵乘法，推理慢且可能因为 adapter 加载问题报错。
