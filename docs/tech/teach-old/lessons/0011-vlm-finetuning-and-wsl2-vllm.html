2. 能不能微调？三种"能"的等级

遇到"能微调吗"这种问题，先分层回答，不要混在一起：

层能否说明
权重层（safetensors） 能 权重本身就是可训练张量，没有"锁定"概念
架构层（Qwen2VLForConditionalGeneration） 能 标准 HF 模型类，.train() / Trainer / PEFT 全部可用
流程层（mineru 包提供的 API） 不能 MinerU 是纯推理框架，无任何训练/微调脚本
配置层（special tokens、prompt 格式） 需要同步改 MinerU 自定义了 <|box_start|>、<|rotate_up|> 等 token，改格式时 tokenizer 要扩

全仓搜索可以验证第三行：

$ find . -name "train*.py" -o -name "finetune*.py" （空） $ grep -ri "Trainer\|peft\|lora\|datasets" pyproject.toml （空，pyproject 里没有任何训练相关依赖）

命中过的 self.training 都是 PyTorch 模型内部的 dropout/batchnorm 模式标志，跟微调没关系。

3. 微调前要准备的五样东西

模型走两步推理，训练数据结构必须分别覆盖。

3.1 第一步：Layout 检测数据

输入 整页 PDF/文档的 RGB 图，resize 到 1036×1036
输出 特殊 token 串，格式如下：
<|box_start|>x1 y1 x2 y2<|box_end|><|ref_start|>type<|ref_end|>(<|rotate_up|>)?(txt_contd_tgt)?

坐标是 0-1000 的整数；type 共 27 种（text/title/table/equation/code/image/chart/header/footer/page_number/table_caption/...）。

3.2 第二步：内容抽取数据

对每个 Layout 检出的 block，按类型喂不同 prompt：

Block 类型Prompt期望输出
text/title/header/footer\nText Recognition:纯文字/Markdown
table\nTable Recognition:OTSL 或 HTML
equation\nFormula Recognition:LaTeX
image/chart\nImage Analysis:图片描述

3.3 模型权重 & processor

huggingface-cli download opendatalab/MinerU2.5-Pro-2605-1.2B \ --local-dir ~/models/MinerU2.5-Pro-2605-1.2B

要拿到完整的 config.json、tokenizer.json、preprocessor_config.json，光有 .safetensors 不够。

5. 为什么 Windows 上默认是 LMDeploy？

回头看 mineru/utils/engine_utils.py:38-67，三平台分流逻辑：

def _select_windows_engine() -> str: try: import lmdeploy return 'lmdeploy' except ImportError: return 'transformers' def _select_linux_engine(is_async: bool) -> str: try: import vllm return 'vllm-async' if is_async else 'vllm' except ImportError: try: import lmdeploy return 'lmdeploy' except ImportError: return 'transformers'
平台第一选择第二第三
LinuxvLLMLMDeployTransformers
WindowsLMDeployTransformers—
macOSMLXTransformers—

Windows 上不是"挑了 LMDeploy"，是vLLM 在 Windows 原生跑不起来。看 pyproject.toml:117：

"mineru[vllm]" ; sys_platform == "linux",

pip 在 Windows 装 vLLM 直接 No matching distribution。vLLM 团队从未把 Windows 原生当一等公民，依赖 Linux 特有的 CUDA 驱动接口和共享内存机制。

LMDeploy on Windows 也不是没代价

看 mineru/backend/vlm/utils.py:60-77，Windows 被强制 turbomind 后端，新卡 (CC ≥ 8.0) 在 Linux 才能用的 pytorch 后端没你份。
Turbomind 渐趋边缘化，Flash Attention 2 不支持，新模型适配滞后，性能比 Linux vLLM 差 20-40%。

6. 跃迁方案：WSL2 + vLLM

vLLM 团队的官方姿势是：WSL2 (Windows Subsystem for Linux 2) 一等支持。CUDA 通过 WSL2 的 GPU passthrough 直接调用宿主机的 N 卡驱动。

7. 完整搭建步骤

前置检查

宿主 PowerShell 跑 nvidia-smi，确认驱动 ≥ 535；BIOS 开启 VT-x / SVM；Windows 功能开启"虚拟机平台"。

① 安装 WSL2 + Ubuntu 22.04

wsl --install -d Ubuntu-22.04 wsl --set-default-version 2 wsl --update # 装好后进 WSL 验证 GPU 透传 nvidia-smi # 看到 GPU 表格即 passthrough 成功

② WSL2 内装 conda + Python 环境

sudo apt update && sudo apt install -y build-essential cuda-toolkit-12-4 wget https://repo.anaconda.com/miniconda/Miniconda3-latest-Linux-x86-64.sh bash Miniconda3-latest-Linux-x86-64.sh -b -p $HOME/miniconda3 source ~/.bashrc conda create -n mineru python=3.12 -y conda activate mineru pip install torch==2.6.0 torchvision --index-url https://download.pytorch.org/whl/cu124

注意：WSL 内不装NVIDIA 驱动，驱动由 Windows 宿主提供。

③ 把 MinerU 装到 WSL 内（不要放 /mnt/c/）

cd ~ git clone https://github.com/opendatalab/MinerU.git cd MinerU pip install -e ".[core]" pip install -e ".[vllm]" # Linux 上才装得上 vLLM # 验证 pip show vllm # 应看到版本号

代码放 /mnt/c/... 会跨文件系统 I/O，慢 10 倍以上。

④ 下载模型 + 启动 vLLM 服务

huggingface-cli download opendatalab/MinerU2.5-Pro-2605-1.2B \ --local-dir ~/models/MinerU2.5-Pro-2605-1.2B # MinerU 封装的 serve 命令（自动加 logits processor） mineru-vllm-server --port 30000 \ --model ~/models/MinerU2.5-Pro-2605-1.2B \ --gpu-memory-utilization 0.85

⑤ Windows 侧直接访问

WSL2 默认把端口绑定到 localhost，Windows 浏览器 / Postman 直接 http://localhost:30000/v1 即可。

8. WSL2 性能调优

8.1 限制 WSL2 不要吃光内存

在 C:\Users\<你>\.wslconfig 写：

[wsl2] memory=32GB swap=16GB processors=8

然后 PowerShell：

wsl --shutdown # 应用配置

8.2 关键 vLLM 参数

参数作用建议值
--gpu-memory-utilization显存占比0.85-0.9（单卡服务）
--max-model-len最大序列长度32768
--enforce-eager禁用 CUDA Graph只调试开
--tensor-parallel-size单机多卡切= GPU 数

8.3 常见坑速查

现象根因解法
WSL 内 nvidia-smi 报错宿主驱动太旧回 Windows 更新 N 卡驱动到最新
跑文档解析极慢代码放在 /mnt/c/移到 ~/（WSL 内部 ext4）
关进程后显存不释放WSL2 内核驻留wsl --shutdown
Windows 访问不到服务端口绑定到 WSL 子网用 localhost:port（WSL2 自动转发）

9. 日常工作流

# 每次重启后只需 wsl conda activate mineru cd ~/MinerU # 起 vLLM 服务（后台） mineru-vllm-server --port 30000 & # 跑解析 mineru -p input.pdf -o output/

Windows 原生 + LMDeploy：起服务 ~10s，推理速度 1.0×

11. 小结

三个核心收获

1. MinerU 的 VLM = Qwen2-VL 骨架 + MinerU2.5-Pro-2605-1.2B 权重，是可微调的；但 MinerU 仓库本身只是推理框架，训练 pipeline 需要自己搭（推荐 LLaMA-Factory 起步）。
2. Windows 上 LMDeploy 不是首选而是唯一，vLLM 原生不支持 Windows，pyproject.toml 里 sys_platform == "linux" 这行就是明证。
3. WSL2 + vLLM 是 Windows 用户的标准跃迁路径，CUDA 通过 passthrough 直调用宿主 GPU，性能比 LMDeploy 高 20-40%，且微调链路同样在 WSL2 里铺好。
