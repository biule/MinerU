2. 什么是"解析流水线"？

"流水线"（Pipeline）在这里不是指 MinerU 的 pipeline 引擎，而是一个更宽泛的概念：把多个处理步骤串联起来，输入是一批 PDF，输出是结构化数据。

一个典型的单证解析流水线长这样：

1. 收集文件 → 2. 分类判断 → 3. 选择策略 → 4. 调用 MinerU → 5. 提取字段 → 6. 汇总输出
阶段做什么为什么需要这一步
1. 收集文件从目录或数据库中获取待处理文件生产环境中文件来源多样，不能假设每次都手动指定路径
2. 分类判断识别文件类型（PDF/图片）、文本/扫描不同文档需要不同的解析策略，用错策略效果很差
3. 选择策略根据类型决定引擎、parse_method、lang 等参数组合影响精度和速度，需要按类型自动决策
4. 调用 MinerU用 Python API 解析文档核心步骤，前面课程已详细覆盖
5. 提取字段从 JSON 中提取业务关心的信息解析结果是通用结构，需要映射到具体业务字段
6. 汇总输出生成报告、写入数据库或导出 CSV流水线的最终交付物

3. 核心设计：策略选择

流水线中最关键的一步是"根据文档类型选择策略"。回顾第 2 课和第 4 课的知识：

文档特征推荐引擎推荐 method说明
文本型 PDF（Word 导出）pipelinetxt速度快，资源低，精度够用
文本型 PDF（复杂排版）hybridauto需要 GPU，精度更好
扫描型 PDFpipelineocr强制 OCR，CPU 可跑
扫描型 PDF（高精度）hybridocr需要 GPU，复杂排版处理更好
纯图片pipelineocr图片一定需要 OCR

判断文本型还是扫描型的方法：用 pypdfium2 尝试提取文字，如果前几页提取不到文字，大概率是扫描件。

def is_scanned_pdf(pdf_bytes, check_pages=3):
    """通过尝试提取前几页文字来判断 PDF 是否为扫描件。"""
    import pypdfium2 as pdfium

    pdf_doc = pdfium.PdfDocument(pdf_bytes)
    total_text = ""
    # 只检查前 check_pages 页，避免在超长 PDF 上浪费时间
    for page_idx in range(min(check_pages, len(pdf_doc))):
        page = pdf_doc[page_idx]
        text_page = page.get_textpage()
        total_text += text_page.get_text_range()
    # 如果前面几页加起来少于 50 个字符，判定为扫描件
    return len(total_text.strip()) < 50

这个函数会用在流水线的"分类判断"阶段。注意这只是启发式判断——有些 PDF 同时包含文本和图片，对这类文档用 auto 模式最稳妥。

4. 完整流水线代码

下面是一份可运行的完整流水线脚本。理解了它，你就理解了如何把 MinerU 嵌入实际应用。

"""
单证解析流水线
输入：一个目录，里面放 PDF 文件
输出：同目录下的 output/ 子目录，包含每个 PDF 的 MD + JSON + 汇总表
"""
import json
import os
import csv
from pathlib import Path
from datetime import datetime

import pypdfium2 as pdfium
from loguru import logger

from mineru.cli.common import convert_pdf_bytes_to_bytes, prepare_env, read_fn
from mineru.data.data_reader_writer import FileBasedDataWriter
from mineru.utils.enum_class import MakeMode
from mineru.backend.pipeline.pipeline_analyze import \
    doc_analyze_streaming as pipeline_doc_analyze
from mineru.backend.pipeline.pipeline_middle_json_mkcontent import \
    union_make as pipeline_union_make


# === 步骤 1：收集文件 ===

def collect_files(input_dir):
    """从目录中收集所有需要处理的文件。"""
    input_path = Path(input_dir)
    supported = {".pdf", ".png", ".jpg", ".jpeg"}
    files = sorted(
        p for p in input_path.iterdir()
        if p.is_file() and p.suffix.lower() in supported
    )
    logger.info(f"收集到 {len(files)} 个文件待处理")
    return files


# === 步骤 2 + 3：分类判断 + 选择策略 ===

def classify_and_strategize(pdf_bytes):
    """根据 PDF 特征决定解析策略。返回 (parse_method, lang)。"""
    try:
        scanned = is_scanned_pdf(pdf_bytes)
    except Exception:
        scanned = True  # 无法判断时保守走 OCR

    if scanned:
        return "ocr", "ch"   # 扫描件 → 强制 OCR
    else:
        return "auto", "ch"  # 文本型 → 自动检测


def is_scanned_pdf(pdf_bytes, check_pages=3):
    """尝试提取前几页文字，少于阈值则判定为扫描件。"""
    pdf_doc = pdfium.PdfDocument(pdf_bytes)
    total_text = ""
    for page_idx in range(min(check_pages, len(pdf_doc))):
        page = pdf_doc[page_idx]
        text_page = page.get_textpage()
        total_text += text_page.get_text_range()
    return len(total_text.strip()) < 50


# === 步骤 4：解析文档（复用第 6 课的模式） ===

def run_parse(files, output_root):
    """批量解析文档，返回每个文档的输出路径和中转 JSON。"""
    # 准备三个平行列表
    pdf_bytes_list = []
    image_writer_list = []
    lang_list = []
    parse_methods = []
    output_info = []

    for file_path in files:
        pdf_bytes = read_fn(file_path)
        pdf_bytes = convert_pdf_bytes_to_bytes(pdf_bytes)
        method, lang = classify_and_strategize(pdf_bytes)

        file_stem = file_path.stem
        image_dir, md_dir = prepare_env(output_root, file_stem, method)

        pdf_bytes_list.append(pdf_bytes)
        image_writer_list.append(FileBasedDataWriter(image_dir))
        lang_list.append(lang)
        parse_methods.append(method)  # 记录下来供步骤 5 使用
        output_info.append({
            "name": file_stem,
            "image_dir": image_dir,
            "md_dir": md_dir,
            "method": method,
        })

    # 存储解析结果，供后续步骤使用
    results = []

    def on_doc_ready(doc_index, model_list, middle_json, ocr_enable):
        info = output_info[doc_index]
        pdf_info = middle_json["pdf_info"]
        image_subdir = os.path.basename(info["image_dir"])

        # 生成 Markdown（给人看）
        md_writer = FileBasedDataWriter(info["md_dir"])
        md_content = pipeline_union_make(pdf_info, MakeMode.MM_MD, image_subdir)
        md_writer.write_string(f"{info['name']}.md", md_content)

        # 生成 content_list（给程序用）
        content_list = pipeline_union_make(pdf_info, MakeMode.CONTENT_LIST, image_subdir)
        md_writer.write_string(
            f"{info['name']}_content_list.json",
            json.dumps(content_list, ensure_ascii=False, indent=2),
        )

        results.append({
            "name": info["name"],
            "method": info["method"],
            "content_list": content_list,
            "md_dir": info["md_dir"],
        })
        logger.info(f"完成: {info['name']} (策略={info['method']})")

    pipeline_doc_analyze(
        pdf_bytes_list=pdf_bytes_list,
        image_writer_list=image_writer_list,
        lang_list=lang_list,
        on_doc_ready=on_doc_ready,
        parse_method="auto",  # 文档合并列表后统一用 auto，pipeline 自行处理
    )

    return results


# === 步骤 5：提取业务字段 ===

def extract_summary(results):
    """从每个文档的 content_list 中提取关键汇总信息。"""
    rows = []
    for result in results:
        content_list = result["content_list"]
        row = {
            "文件名": result["name"],
            "策略": result["method"],
            "页数": len(set(c.get("page_idx", 0) for c in content_list)) + 1,
            "文本块数": sum(1 for c in content_list if c["type"] == "text"),
            "标题数": sum(1 for c in content_list
                        if c["type"] == "text" and "text_level" in c),
            "表格数": sum(1 for c in content_list if c["type"] == "table"),
            "图片数": sum(1 for c in content_list if c["type"] == "image"),
            "公式数": sum(1 for c in content_list if c["type"] == "equation"),
        }

        # 提取所有标题作为文档大纲
        titles = []
        for c in content_list:
            if c["type"] == "text" and "text_level" in c:
                titles.append(f"{'#' * c['text_level']} {c['text'][:80]}")
        row["大纲"] = " | ".join(titles[:10])  # 只取前 10 个标题

        rows.append(row)
    return rows


# === 步骤 6：汇总输出 ===

def write_summary(rows, output_dir):
    """将汇总信息写入 CSV 文件。"""
    csv_path = os.path.join(output_dir, f"summary_{datetime.now():%Y%m%d_%H%M%S}.csv")
    with open(csv_path, "w", newline="", encoding="utf-8-sig") as f:
        if not rows:
            return
        writer = csv.DictWriter(f, fieldnames=rows[0].keys())
        writer.writeheader()
        writer.writerows(rows)
    logger.info(f"汇总表已保存: {csv_path}")
    return csv_path


# === 主函数 ===

def main(input_dir=None, output_root=None):
    """执行完整流水线。"""
    if input_dir is None:
        input_dir = "demo/pdfs"
    if output_root is None:
        output_root = f"pipeline_output/{datetime.now():%Y%m%d_%H%M%S}"

    logger.info(f"=== 单证解析流水线启动 ===")
    logger.info(f"输入目录: {input_dir}")
    logger.info(f"输出目录: {output_root}")

    files = collect_files(input_dir)          # 1. 收集
    results = run_parse(files, output_root)   # 2-4. 分类+解析
    rows = extract_summary(results)           # 5. 提取
    csv_path = write_summary(rows, output_root)  # 6. 汇总

    logger.info(f"=== 流水线完成 ===")
    logger.info(f"共处理 {len(files)} 个文件")
    logger.info(f"汇总报告: {csv_path}")

    return rows


if __name__ == "__main__":
    main()

5. 流水线的六个阶段逐一拆解

阶段 1：收集文件

用 Path.iterdir() 遍历目录，按后缀过滤。生产环境中你可能还要处理子目录递归、从数据库拿文件列表、从 S3 下载等场景——但这些只是"数据来源"不同，流水线的后续阶段不变。

阶段 2+3：分类 + 策略

核心判断是 is_scanned_pdf()——用 pypdfium2 尝试提取前 3 页文字，少于 50 个字符就判为扫描件。这个阈值可以根据实际文档调整。注意 try/except 兜底——万一 pdfium 报错（比如 PDF 损坏），保守走 OCR 路径。

阶段 4：调用 MinerU

和第 6 课的模式完全一致：准备三个平行列表 → 回调函数 → doc_analyze_streaming。唯一的增强是把每个文档的解析策略记录下来，方便事后分析"哪种策略被用了多少次、效果如何"。

阶段 5：提取字段

这是把"通用 JSON"变成"业务数据"的一步。extract_summary() 从 content_list 中统计文本块数、标题数、表格数等——这些数字本身就能帮助判断文档类型和复杂度。在真实业务中，这里可以扩展为：

# 单证解析时扩展 extract_summary 为具体提取函数
def extract_invoice_fields(content_list):
    """从发票中提取关键字段。"""
    # 按位置找发票号码：通常在左上角 bbox[0] < 300, bbox[1] < 150
    for item in content_list:
        if item["type"] == "text":
            bbox = item.get("bbox", [])
            if bbox and bbox[0] < 300 and bbox[1] < 150:
                if "发票号码" in item["text"] or "发票代码" in item["text"]:
                    return item["text"]

阶段 6：汇总输出

用 Python 标准库的 csv.DictWriter 写出 CSV——这是最通用的数据交换格式，Excel、数据库、Pandas 都能直接读。encoding="utf-8-sig" 是 Windows 上写入 CSV 的最佳实践（加 BOM 头，Excel 打开不会乱码）。

6. 进阶：字段提取的模式

从 JSON 中提取业务字段，有三种常见模式：

模式适用场景实现方式
位置匹配 字段位置固定（如发票号码永远在左上角） 用 bbox 坐标筛选区域
关键词匹配 字段旁边有固定标签（如"金额："后面跟数字） 正则表达式或字符串查找
结构匹配 表格中的行列数据 解析 table_body HTML，遍历 <tr> 和 <td>

这三种模式不互斥——大多数真实场景是组合使用。比如提取"发票金额"：先用关键词匹配找到"金额合计"标签，再检查它后面的数字是否符合金额格式（正则），最后用 bbox 验证它在页面的右下区域。

7. 小测验

问题 1： 流水线中"分类判断"这一步的目的是什么？

  1. 给文件重命名
  2. 判断文档是文本型还是扫描型，以便选择正确的解析策略
  3. 检查文件是否损坏
  4. 统计文件数量
查看答案

B。文本型 PDF 和扫描型 PDF 需要不同的 parse_method（txt vs ocr）。错误的选择会导致乱码或漏字，所以分类是流水线的关键第一步。

问题 2： pypdfium2 在流水线中扮演什么角色？

  1. 做 OCR 识别
  2. 提取 PDF 中的文字来判断是否为扫描件
  3. 把 PDF 转成图片
  4. 生成 CSV 报告
查看答案

B。pypdfium2 是 PDF 底层渲染库，能直接提取文本型 PDF 中的文字。通过检查前几页提取到的文字量，可以判断 PDF 是文本型还是扫描件。

问题 3： 流水线脚本中为什么用了 encoding="utf-8-sig" 而不是 encoding="utf-8" 来写 CSV？

  1. utf-8-sig 速度更快
  2. Windows 上 Excel 打开 utf-8 CSV 会乱码，加 BOM 头可以解决
  3. 两种编码没有区别
  4. utf-8 不支持中文
查看答案

B。utf-8-sig 在文件开头写入 BOM（字节序标记），告诉 Excel 这个文件是 UTF-8 编码。不加 BOM 的话 Excel 可能按 GBK 解析导致中文乱码。

8. 动手挑战

挑战 1：跑通流水线

把上面的完整脚本保存为 pipeline_demo.py，在项目根目录运行。检查输出的 CSV 汇总表，看看每个 demo PDF 被分配了什么策略。

挑战 2：添加字段提取

挑战 3：加入错误处理

改进流水线，使单个文档解析失败时不影响其他文档继续处理。提示：在 run_parse 的回调函数中用 try/except 包裹处理逻辑，失败时记录错误但不中断流程。
