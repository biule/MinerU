档位矩阵

四档解析的产品语义、内部 effort、模型引擎与默认选择规则。用于回答“该选哪档”和“为什么选了这档”。

1. 档位 → effort

tiereffortPDF 执行方式典型用途
flash 极速解析flashtxt：DocVortex 原生 PDF 模型；ocr：布局小模型 + OCR发现、预览、索引；不做最终阅读质量
basic 基础解析medium小模型：layout + OCR + MFR + 表格私有本地阅读、资源受限
standard 标准解析high小模型 + VLM 单步抽取（带布局块）默认高质量阅读
advanced 高级解析xhigh小模型 + VLM 两步抽取 + 图片分析难文档、最高质量

3. 各入口的默认选择

场景默认规则
Python parse() / MinerUParser默认 standard；不接受 tier=None/auto；原生格式实际输出 flash/txt
mineru-kit parsePDF/图片默认 standard；原生单文件未指定 tier 时用 flash，显式质量档位报错；批量中的原生文件归一为 flash
Tasks / HTTP SDK / file-parse按 standard → basic → flash → advanced；只有 Advanced 时选中它；原生文件固定 flash
Gradio 初始档位与 Tasks 使用同一选择函数；外部 API 依据 /v1/tiers
Doclib 主动质量解析PDF/图片按 standard → basic；缺少可用默认档位则报错
Doclib 已缓存读取未指定 tier 时选可读的 advanced → standard → basic；不自动新建解析
Doclib parsing rulestandard → basic → flash

5. 服务档位上限

api-server --tier 与 WebUI 的 --tier 控制最高开放档位，并包含较低档位：

上限可用解析档位
flashflash
basicflash, basic
standardflash, basic, standard
advancedflash, basic, standard, advanced

注意：服务档位是部署能力上限，不是单次请求选择的档位；auto 是启动模式，不是第五个解析档位。

6. 常见误区

  • “tier 就是模型大小”：tier 决定是否使用 VLM、是否两阶段、是否做图片分析。
  • “flash 一定最差”：原生格式（Office/EPUB/OFD/HTML/CSV）只有 flash，质量由格式解析决定。
  • “Standard 与 Advanced 是两套模型”：两者共用部署模型；Advanced 增加推理投入与图片分析。
  • “显式档位不受支持时会自动降级”：不会；显式请求不支持的档位返回错误。
  • “配置了远端地址就会上传”：不会；必须显式 --remote 或规则允许。
