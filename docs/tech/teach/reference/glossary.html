术语表

MinerU 4.x 的稳定术语。后续课程与参考文档统一使用这些定义。

术语含义源码 / 依据
tier产品档位：flash / basic / standard / advanced。决定解析质量和资源取舍。mineru/types.py
effort内部分析强度：flash / medium / high / xhigh。由 tier 显式映射。mineru/parser/tier.py
small backend小模型执行后端：ONNX 或 Torch。影响依赖、设备和模型文件。model/runtime/device.py
VLM engine视觉语言模型推理引擎：llama.cpp、vLLM、LMDeploy、MLX；配置了远程地址时改用 HTTP 客户端。model/vlm/selector.py
ModelJson内部原始分析结果：raw pages + page_index_map + metadata + extensions。不进入公开结果包。docs/next/glossary.md
MiddleJson公开的有序页面语义树，schema 身份 docvortex.middle、版本 2.0。docs/next/middle-json/
ParseResultSDK 结果对象，唯一字段是 middle_json；提供渲染、序列化、保存。不持有 PDF 对象。mineru/parser/base.py
Doclib本地有状态文档库：入库、缓存、搜索、扫描、按 locator 读取。mineru/doclib/
short_idDoclib 的短文档标识，用于 locator；不同于 Tasks 的 file_id。doclib/locators.py
TaskHTTP 父任务与有序 files 清单；每个文件独立执行、独立完成。mineru/tasks/
file_idTasks 从创建到成功产物保持的公共逐文件 ID；不透明，不推导存储路径。docs/next/api/
locator文档/档位/页/块/字符定位表达式：doc:{short_id}/tier:{tier}/page:{n}/block:{n}/char:{offset}。doclib/locators.py
page_idx / page_no内部从 0 开始的页面索引 / 面向用户从 1 开始的页码。docs/next/page-naming.md
page_rangePDF 页范围字符串：1-5,8、r3-r1（从末尾计）、all。仅 PDF 支持。docs/next/page-ranges.md
windowPDF 处理窗口，默认 64 页；控制单文档内存上界。backend/analysis/pdf/window.py
managed / self_hosted / remoteDoclib 的三种质量解析来源：托管本地服务 / 自托管服务 / 远端服务。docs/next/config.md
RuntimeOwner运行时资源所有者，用于显式获取/释放模型与服务资源，避免泄漏。model/runtime/ownership.py
DocVortex共享文档层：原生格式解析、PDF 访问与分类、schema、确定性后处理、七种通用 renderer、export。CLAUDE.md
FTSSQLite 全文搜索：fts_contents（正文）与 fts_filenames（文件名）。doclib/core/fts.py
Structured Content派生的内容字典，没有独立 schema 身份；不是 MiddleJson 协议。mineru/render/structured_content.py
Content List V1 / V2MinerU 专属的扁平/按页内容列表输出；与通用 renderer 分开维护。mineru/render/content_list*.py
parse recordDoclib 持久化的解析批次；状态与缓存语义独立于 HTTP Task。doclib/types.py
layout页面级版面分析：给出标题、正文、表格、图片、公式等块的 label/bbox/score 与阅读顺序。model/layout/
OCR det / rec文字检测（找框）与文字识别（读字）；MinerU 4.x 使用 PP-OCRv6 Tiny Det + Small Rec，Torch/ONNX 共用字符表。model/ocr/
MFR数学公式识别（Math Formula Recognition）；输出 LaTeX。basic 跑完整 MFR，standard/advanced 主要走 VLM 并对失败切片局部回退。model/mfr/
table rec表格结构识别：无线表（SlanetPlus）与有线表（UNet）等；与表格方向/类型分类配合。model/table/
seal OCR印章识别：独立检测阈值、多边形后处理与裁剪；语言模式 seal，不是普通 OCR 的隐式降级。model/ocr/pytorch_paddle.py
atom model本地小模型的原子实例（layout/OCR/MFR/表格等）；由 AtomModelSingleton 按后端、设备、语言与参数缓存。model/runtime/hybrid.py
Hybrid local context窗口准备/收尾持有小模型集合与设备锁的上下文；VLM 推理期间释放锁。HybridLocalModelContextSingleton
VLM predictor窗口依赖的最小抽取协议：带布局抽取、两步抽取、文本切片识别及异步版本。model/vlm/contracts.py
http-clientmodel.vlm.server_url 非空时的远程 VLM 后端；OpenAI 兼容，不加载本地引擎，失败不回退。model/vlm/client.py
GGUF / mmprojllama.cpp 的主模型文件与多模态投影文件；两者必须配对，官方仓库使用 Q8_0。model/registry.py
LoRA / adapter低秩适配器：只训练少量附加权重；部署前通常 merge 回基座。训练在外部完成，MinerU 只消费结果。外部训练框架
CER字符错误率：编辑距离 / 参考长度；评测文本时需先固定归一化规则。评测脚本（课程 16）
TEDS表格结构相似度指标（外部实现）；也可用单元格 F1 / 结构精确匹配替代。外部评测
parse batchDoclib 的解析批次；按页范围与档位记录状态、错误与产物，不等同于 HTTP 父任务。doclib/services/parse_queue_svc.py
server tier服务部署的能力上限（--tier），包含较低档位；不是单次请求档位。api-server
Content List bboxContent List 输出的 0–1000 整数框；MiddleJson 是 0–1，OCR 原子模型是输入图像像素。render/_internal/content_list/
3.x 术语避坑：旧课程里的 pipeline / vlm-engine / hybrid-engine 是 3.x 的后端名称，不是 4.x 的产品概念。4.x 用 tier（flash/basic/standard/advanced）表达质量，用 small backend（ONNX/Torch）与 VLM engine（llama.cpp/vLLM/LMDeploy/MLX）表达实现。看到旧文章时先做这个映射，不要把旧名当参数传。
