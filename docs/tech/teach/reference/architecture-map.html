Reference · Architecture

架构地图

MinerU 4.1.7 的分层、调用链与模块职责。用于在改动前快速定位“应该改哪里”。

1. 分层

入口层mineru CLI · mineru-kit · Python SDK · V1 API · WebUI
MinerU 产品层parser · backend · model · render · doclib · tasks · kit/router
DocVortex 共享层原生格式解析 · PDF 访问与分类 · schema · 确定性后处理 · 七种通用 renderer · export
边界：依赖单向。MinerU 可以使用 DocVortex 的公开接口，但不得导入其私有实现；DocVortex 也不得反向依赖 MinerU。 依据：CLAUDE.md「DocVortex 与 MinerU 的文档架构」。

2. 三条调用链

2.1 无状态解析

mineru-kit parse / Python parse()
  → MinerUParser._prepare_input()        # 类型识别、图片转 PDF、页范围
  → doc_analyze()                        # 统一分析门面
      → analyze_pdf()                    # PDF：窗口流水线
      → analyze_office() / html() / …    # 原生格式：DocVortex
  → ModelJson                            # 内部原始结果
  → model_json_to_middle_json()          # DocVortex 确定性后处理
  → apply_llm_aided_postprocess()        # 可选 LLM 增强（默认关）
  → ParseResult(middle_json)             # SDK 结果
  → render() / save()                    # 九种输出 / 结果包

2.2 Doclib 文档库

mineru parse / read / search
  → DoclibClient                        # 读取 endpoint 文件发现服务
  → Doclib Server (/api/v1)
      → IngestService                   # 路径入库、sha256 身份
      → ParseQueueService               # 缓存覆盖、按页排队、优先级
      → ParseWorkerPool                 # 抢占批次
      → ParseExecutionService           # 本地 Flash 或 API 解析
      → SQLite + parsed/ 批次 JSON      # 持久化
      → ContentReadService              # locator / context / limit / 导出

2.3 HTTP Tasks

POST /v1/tasks
  → tasks/service.py                    # 父任务与逐文件状态
  → ApiTaskBackend                      # 文件存储、上传、执行
  → 同一解析门面（MinerUParser / analyze）
  → task_outputs.build_task_output()    # default / docx / html / latex
  → GET /v1/tasks/{id}                  # 每文件独立结果链接

2.4 VLM 运行时

backend/analysis/pdf/window.py            # high / xhigh 的 VLM 阶段
  → get_vlm_predictor()                   # 读配置、校验环境
      → server_url 非空 → http-client
      → 否则 → resolve_vlm_engine() → 本地引擎
  → ModelSingleton.get_model()            # 按缓存键复用、初始化屏障
  → VlmPredictor                          # 抽取 / 两步 / 文本切片（含 aio 版本）
  → RuntimeOwner 释放                     # 最后一个引用关闭

3. 模块职责

路径职责改动入口
mineru/parser/输入准备、tier→effort、页范围、本地/远程解析门面新增输入类型前置逻辑、SDK 参数
mineru/backend/analyze.py统一分析门面、按后缀路由、构造 ModelJson新增格式路由、元数据
mineru/backend/analysis/pdf/PDF 生命周期、窗口编排、layout/OCR/MFR/表格/VLM解析质量、阶段顺序
mineru/backend/analysis/Office/ODF/EPUB/OFD/HTML/MHTML/CSV 原生分析原生格式接入
mineru/backend/postprocess/确定性后处理边界、可选 LLM 增强、历史兼容后处理策略
mineru/model/layout/OCR/MFR/table/VLM 推理与模型生命周期模型、设备、引擎
mineru/render/九种输出门面与选项新增输出格式
mineru/doclib/SQLite、FTS、入库、排队、执行、读取、后台任务缓存、读取、服务 API
mineru/tasks/Tasks 协议、编排、执行、HTTP 路由HTTP 行为
mineru/kit/mineru-kit 命令、API server、Router、file-parse、Gradio服务入口
mineru/cli/mineru 文档库 CLICLI 交互
mineru/config.py两阶段配置、来源信息、VLM/LLM 配置新增配置项
mineru/filetypes.py扩展名边界、MIME 映射新增格式
mineru/errors.py错误码 → 类型 → HTTP 状态新增错误语义

4. 常见改动的落点

想改什么先看这里注意
PDF 某阶段的行为/顺序backend/analysis/pdf/window.py窗口准备/推理/收尾的锁边界
档位默认选择parser/tier.py、types.py 的选择顺序不同入口的默认策略不同
VLM 引擎model/vlm/selector.py、runtime.py同步 + 原生异步两条路径
小模型后端model/runtime/device.py、hybrid.pyONNX/Torch 都要验证
输出格式render/contracts.py、render/api.py通用格式归 DocVortex
Doclib APIdoclib/server.py、doclib/client.py服务端/客户端路径保持一致
HTTP 任务tasks/http.py、parser/task_backend.py状态机与文件独立完成
