常见问题

把“看起来像 bug”的高频现象按使用、服务、模型、微调、开发分组。每条给最短结论、原因和对应课程；细节以源码与 docs/next 为准。

1. 使用与输出

问题结论与原因详见
为什么不同入口默认档位不同？Doclib 主动解析按 standard → basic；Tasks 按 standard → basic → flash → advanced；缓存读取按 advanced → standard → basic；原生格式固定 flash。语义不同，不能复用同名选择器。档位矩阵
flash 是不是最差？不是。它决定“是否用 VLM、是否两步、是否图片分析”；原生格式只有 flash，质量由格式解析决定。flash 更适合发现、预览、索引。02
为什么 mineru parse 只读前 10 页？Doclib 默认 default_parse_range 是前 10 页，控制首次阅读成本；整本用 --pages all。05
第二次 parse 为什么快？缓存按 sha256 + tier + 页范围 覆盖；已完成的页直接扣除，只解析缺失页。05
--force、invalidate、forget 有什么区别？force 只让本次跳过 done 缓存；invalidate 让未来请求避开旧缓存但不触发解析；forget 移除记录与缓存但不删源文件。05
mineru read 会触发解析吗？不会；只读已有缓存。没有缓存返回 not_cached / tier_not_cached。05
图片会单独走一条流水线吗？不会；输入准备阶段先转 PDF，之后与普通 PDF 同一条路径。01
为什么页数对不上？坏页会以空块占位保留页序；也可能是页范围重写。检查 PageInfo 与日志。09
公式为空 / 表格乱？公式先看 pdf.inline_vlm 切片告警与回退；表格先确认 txt/ocr 模式与原生表格优先，扫描件应走 OCR 档位。03

2. 服务与部署

问题结论与原因详见
配了 remote URL 和 Key，为什么不上传？存在配置 ≠ 允许上传；必须显式 --remote 或规则允许。自动上传是 bug。06
HTTP 200 就代表解析成功吗？不代表。任务创建/查询是 200 级别，但逐文件状态可能是 failed；按 file 状态与结果链接判断。07
parse_wait_timeout 后任务被取消了吗？没有；解析仍在后台。可稍后 read 缓存或重新等待；客户端超时不等于取消。09
为什么服务只监听了 127.0.0.1？默认 loopback 是安全边界；对外必须显式改 host，并加 TLS 与 --api-key。17
Windows 上 Doclib 用什么传输？UDS 不可用时自动回退 TCP loopback（默认 15980）；endpoint 写入 doclib.endpoint.json。06
服务重启后旧 task/file ID 还能用吗？api-server 的资源元数据在内存，重启不恢复；Doclib 的持久化缓存与解析记录另算。17
Router 和 api-server 什么关系？Router 对外仍是 Tasks 协议，负责 worker 发现/调度/公共 ID；worker 必须是完整 Parse API，不能指向原生 vlm-server。07
怎么判断服务健康？/v1/health、/v1/models、/v1/tiers；Doclib 用 mineru server status --json。托管 worker 默认 warning 日志。17

3. 模型与引擎

问题结论与原因详见
GPU 为什么没用上？先看小模型后端（Torch 依赖/设备）与 VLM 引擎选择；Torch 不可用会回落 ONNX/CPU，日志会给出实际 provider。13
为什么 CPU 上用 llama.cpp？auto 固定规则：非 Linux/Windows、CPU、无 vLLM/LMDeploy 时选 llama.cpp；CPU 上不求高吞吐。02
远程 VLM 断了会自动回退吗？不会。远程优先且无回退；失败直接报错，避免结果漂移。13
模型下载/离线怎么弄？mineru-kit models download --tier standard；离线设 MINERU_MODEL_SOURCE=local 并准备本地目录；models verify 校验。命令速查
GGUF 为什么需要两个文件？llama.cpp 需要主模型 + mmproj 多模态投影；两者必须配对，不匹配会乱码或静默错误。13
vlm-server 和 api-server 能互相替代吗？不能。vlm-server 只做 OpenAI 兼容推理；api-server 才是完整解析 Tasks。Router 只能接 api-server。13
显存不够怎么办？降低 max_concurrency、用小批量、换 llama.cpp/更小模型、减窗口大小；不要盲目加 worker。17

4. 微调与评测

问题结论与原因详见
仓库里有训练代码吗？没有。MinerU 是模型使用方，通过 MinerUClient 消费模型；训练在外部完成。10
微调后“没效果”？先确认档位是 standard/advanced（flash/basic 不调用 VLM）、请求确实到了新权重、评测输入与推理输入分布一致。12
训练数据要什么形态？匹配推理：按块裁剪图 + 类型专属 prompt + 目标格式（表格 HTML、公式 LaTeX、文本原文）。11
怎么证明变好了？固定协议做 A/B，按块类型分项指标，报告配对均值与 95% 区间；同时看回归集与成本。16
量化为什么掉点？长公式、密排表格、稀有字符更敏感；必须分项验收，不能只看平均 CER。16
微调权重怎么接回来？三条路径：远程 vLLM（推荐）、本地引擎加载、GGUF + llama.cpp；都要用 standard 端到端验证。12

5. 开发与扩展

问题结论与原因详见
新增格式解析写在哪？原生格式只在 DocVortex 实现；MinerU 只登记扩展名与路由。复制第二份实现会破坏唯一归属。08
新增渲染格式写在哪？通用格式在 DocVortex；Content List V1/V2 与专用选项在 MinerU。加 RenderFormat、render() 分支与 __all__。08
新增 VLM 引擎改哪？selector.py 的显式映射与 auto 规则、runtime.py 的构造/关闭分支、必要的 ModelRepo 与 optional extra。08 / 13
能用运行时注册/猴子补丁吗？不行。项目原则是确定性优先：显式映射、显式导出、无 import 副作用、重依赖惰性加载。CLAUDE.md
旧 3.x 结果还能直接读吗？通用读取不兼容；历史兼容仅在 Doclib 缓存读取边界，由 read_cached_middle_json 处理。middle-json
内容列表坐标是 0–1 还是像素？Content List 是 0–1000 整数；MiddleJson 是 0–1；OCR 原子模型返回输入图像像素。14 / 15
小图解析为空怎么办？先判断是 Layout 没给块还是识别错；前者可直调 OCR 原子模型并封装受控端点，后者走模型/数据改进。15
改完怎么自查？过课程 08 的护栏五查：副作用、导入/导出、隐私、协议、生命周期；再跑四线测试。08
