Lesson 12 · 微调系列 3/3

服务化微调模型：接回推理链路

这节课只做一件事：把训练完的权重按三条路径之一接入 MinerU（远程 vLLM 服务 / 本地引擎权重 / llama.cpp GGUF），并用一次真实 standard 解析验证端到端生效。

验收原则：接入成功的唯一标准是“MinerU 解析某文档，输出确实体现了你的微调效果”——而不是“服务启动了”。每条路径的验证步骤都以端到端解析收尾。

1. 路径回顾与选择

A 远程 vLLM首选 · 多机可复用
改动最小 · 只改配置
B 本地引擎权重单机 · 免服务
vLLM/LMDeploy 直接加载本地目录
C GGUF + llama.cppCPU 友好 · 需要转换
主模型 + mmproj 两文件

2. 路径 A：远程 vLLM 服务（推荐）

2.1 起服务

# 在 GPU 机器上（或本机）起 vLLM OpenAI 服务
# MinerU 4.x 官方路径：vllm serve <模型目录>
vllm serve /path/to/your-finetuned-model \
  --served-model-name mineru-vlm-finetuned \
  --port 30000

# 健康验证（两个端点都必须可用，MinerU 会调用 /v1/models 做模型名发现）
curl http://127.0.0.1:30000/v1/models

2.2 接入 MinerU

# config.yaml
model:
  vlm:
    server_url: http://127.0.0.1:30000/v1    # 保留代理前缀；会自动去尾部 /v1
    api_key: ${VLM_API_KEY:-}                # 可为空
    model: mineru-vlm-finetuned              # 上游只有一个模型时可留空
    http_timeout: 600
    max_concurrency: 100                     # VLM 请求并发

2.3 端到端验证

mineru-kit parse 你的样例.pdf -o out.md --tier standard
# 命中标志：vLLM 服务日志里出现 chat completion 请求
# 且 out.md 的内容体现微调改进（如领域表格结构、专有符号）

# 若想同时对照基线，起两个端口分别在配置间切换解析

依据：mineru/model/vlm/client.py——server_url 非空即 http-client；settings.validate_environment() 会校验 URL 形态；远程模式不回退本地引擎。

3. 路径 B：本地引擎加载微调权重

  • vLLM/LMDeploy/MLX：_create_model 在 model_path 为空时会 MINERU_2_5_PRO_2605_1_2B.ensure() 下载官方权重；把 model.source 设为 local、并按 ModelRepo 目录布局放入微调权重即可替换。
  • 目录约定在 model/registry.py 的 ModelRepo（HuggingFace/ModelScope 同名仓库布局）。
  • 引擎选择：auto 按 resolve_vlm_engine()；显式指定用 model.vlm.engine: vllm / lmdeploy。
# 本机 GPU 直跑（无独立服务进程）：
model:
  vlm:
    engine: vllm        # 或 lmdeploy
# 权重位置：按 ModelRepo 布局放入 model.base_dir（默认 ~/.mineru/models）

4. 路径 C：GGUF + llama.cpp

# llama.cpp 后端需要两个文件（model/registry.py 的 GGUF 仓库约定）：
#   MinerU2.5-Pro-2605-1.2B-Q8_0.gguf        ← 主模型（你的微调权重须转换）
#   mmproj-MinerU2.5-Pro-2605-1.2B-Q8_0.gguf  ← 多模态投影（视觉侧mmproj）

# 转换流程（在 llama.cpp 工具链内，非本仓库）：
# 1) 微调权重 → f16 GGUF（convert_hf_to_gguf.py）
# 2) 量化到 Q8_0（llama-quantize）
# 3) 视觉投影 mmproj 沿用官方文件（若视觉塔未动）
  • 接入点：_create_model 的 llama-cpp-engine 分支——按 repo.paths["main"] 与 repo.paths["mmproj"] 从模型目录取两文件。
  • 设备：CPU 自动 n_gpu_layers=0；有 GPU 时 llama.cpp 会尝试 offload（resolve_llama_device）。
  • 注意：mmproj 与主模型 必须 匹配（同一次训练产出的视觉塔 + 语言塔组合），不匹配会导致乱码或静默错误。

5. 三条路径的验证清单

#检查方法
1模型被加载的是你的权重远程：查 /v1/models 名称；本地：日志 backend + loading 路径；GGUF：文件路径
2MinerU 的请求真的带到了它服务侧日志出现请求；或解析输出体现微调改进
3档位仍选 standardflash/basic 根本不调用 VLM——用 --tier standard
4并发配置生效max_concurrency 是 VLM 请求并发，与解析任务并发独立
5无静默回退远程模式的回退不存在；本地引擎失败会报错不是换模型

7. 动手练习（你的环境）

  1. 不用真微调也能走全流程：用官方 MinerU2.5-Pro-2605-1.2B 权重起一个 vLLM 服务（路径 A），把 server_url 指向它，解析一份 PDF——先确认链路通，权重换成微调版时只改一行。
  2. 观察服务日志中的请求形态：每个 chat completion 的文本应以 \nText Recognition: 等开头——这正是课程 11 捕获的 prompt。
  3. 若手上有微调权重：按路径 B 或 C 替换，并用课程 09 的错误码矩阵排障。

遇到 invalid_api_key / 上游 401：确认 server_url 与 api_key 匹配；连接被拒：确认端口与防火墙。
