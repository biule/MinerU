Lesson 16 · 微调系列 4/4

微调验收：A/B 评测与量化部署

这节课只做一件事：用同一套文档、同一套协议、同一套指标，证明“微调后的模型确实更好，且没有把通用能力搞坏”；然后用同样的方法验收量化模型，决定是否上线。

为什么补这一课：课程 10–12 解决了“怎么训、怎么接”，但没有解决“怎么证明”。没有评测门的微调，只是换了一个权重；没有回归集的量化，只是把风险藏起来。

你将能够

  • 设计一个可复现的 A/B 评测：固定输入、档位、配置、引擎与采样。
  • 按块类型计算文本、表格、公式与结构指标，并解释各自局限。
  • 用配对比较与置信区间判断“提升是不是噪声”。
  • 用同一套 harness 验收 GGUF / AWQ / GPTQ 等量化模型。
  • 写出可执行的验收门槛与回滚条件。

1. 评测回答三个问题

变好了吗目标集：领域表格/公式/字符是否提升
变差了吗回归集：通用文档是否退化
代价多少延迟、显存、吞吐、部署复杂度
集合内容作用
目标集（target）你的领域文档，含微调覆盖的版式/符号证明改进
回归集（general）论文、报告、扫描件等通用样本防止灾难性遗忘
边界集（edge）空页、旋转、极小图、密排表格发现新的失败模式

划分按文档，不是按块/页；同一文档的块跨集合会泄漏，指标虚高。

2. 固定协议：只允许一个变量

必须固定做法原因
输入与页范围同一批文件、同一 page_range输入变化会污染比较
tier / parse_mode都用 standard + auto（或都 ocr）不同档位调用不同模型
VLM 采样参数同一引擎、同一默认采样解码随机性会影响输出
硬件与引擎版本同一机器/驱动/引擎速度与数值差异
评测代码版本指标实现与归一化固定否则“提升”可能来自指标改动
 
# 一次只改一个变量：base 服务 vs finetuned 服务
from mineru.config import VlmConfig

3. 指标：按块类型分开算

对象主指标辅助注意
普通文本CER（字符错误率）精确匹配、词级 WER先做 NFKC、空白折叠；保留归一化版本号
表格单元格 F1 / 结构精确匹配TEDS（外部实现）HTML 属性顺序不应影响结果
公式归一化 LaTeX 精确匹配编辑距离空格、定界符、等价写法要先统一
结构块类型 F1阅读顺序距离、页覆盖率避免只比数量
业务字段字段 F1关键字段召回率最终交付指标，优先看它
成本p50 / p95 延迟显存峰值、页/秒质量提升必须能承受代价
 
# tools/eval_ab.py —— 指标骨架（可运行的核心部分）
from __future__ import annotations

import json
import re
import unicodedata
from pathlib import Path

from mineru.config import VlmConfig
from mineru.parser import parse
from mineru.render import RenderFormat, render

WS = re.compile(r"\s+")


def norm(text: str) -> str:
    text = unicodedata.normalize("NFKC", text or "")
    return WS.sub(" ", text).strip()


def levenshtein(a: str, b: str) -> int:
    if len(a) < len(b):
        a, b = b, a
    prev = list(range(len(b) + 1))
    for i, ca in enumerate(a, 1):
        cur = [i]
        for j, cb in enumerate(b, 1):
            cur.append(min(prev[j] + 1, cur[j - 1] + 1, prev[j - 1] + (ca != cb)))
        prev = cur
    return prev[-1]


def cer(ref: str, hyp: str) -> float:
    ref, hyp = norm(ref), norm(hyp)
    return levenshtein(ref, hyp) / max(1, len(ref))


def by_type(items: list[dict]) -> dict[str, list[dict]]:
    out: dict[str, list[dict]] = {}
    for item in items:
        out.setdefault(item["type"], []).append(item)
    return out


def evaluate(pdf: Path, cfg: VlmConfig | None, ref_payload: dict) -> dict:
    result = parse(pdf, tier="standard", vlm_config=cfg)
    items = render(result.middle_json, RenderFormat.CONTENT_LIST)
    grouped = by_type(items)

    hyp_text = norm("\n".join(i.get("text", "") for i in grouped.get("text", [])))
    ref_text = norm(ref_payload["text"])
    hyp_eq = [norm(i.get("text", "")) for i in grouped.get("equation", [])]
    ref_eq = [norm(x) for x in ref_payload["equations"]]
    eq_hit = sum(1 for x in ref_eq if x in hyp_eq) / max(1, len(ref_eq))

    return {
        "pdf": pdf.name,
        "text_cer": cer(ref_text, hyp_text),
        "equation_exact": eq_hit,
        "table_count": len(grouped.get("table", [])),
        "block_count": len(items),
    }


if __name__ == "__main__":
    # 每个变体独立运行：python tools/eval_ab.py --config base.json
    cfg = VlmConfig(server_url="http://127.0.0.1:30001/v1", model="mineru-ft")
    refs = json.loads(Path("eval/refs.json").read_text(encoding="utf-8"))
    rows = [evaluate(Path(p), cfg, ref) for p, ref in refs.items()]
    Path("eval/candidate.json").write_text(json.dumps(rows, ensure_ascii=False, indent=2), encoding="utf-8")
    print(json.dumps(rows, ensure_ascii=False, indent=2))

4. 判断提升是不是噪声

# 配对 bootstrap：同一文档上的差异，重采样文档
import random

def paired_delta(base: list[float], cand: list[float], rounds: int = 2000) -> tuple[float, float, float]:
    diffs = [b - c for b, c in zip(base, cand)]     # 正数表示 CER 下降（变好）
    mean = sum(diffs) / len(diffs)
    samples = []
    for _ in range(rounds):
        pick = [random.choice(diffs) for _ in diffs]
        samples.append(sum(pick) / len(pick))
    samples.sort()
    lo, hi = samples[int(0.025 * rounds)], samples[int(0.975 * rounds)]
    return mean, lo, hi
  • 报告“均值 + 95% 区间”，不要只报一个更好的数字。
  • 样本量：目标集至少几十份文档起步；几份文档的“提升”没有决策价值。
  • 同时看按类型的分项：总体 CER 下降，可能掩盖表格变差、公式不变。

5. 量化验收：用同一把尺子

路径形态验收重点
llama.cpp GGUF官方 Q8_0；可再转 Q4_K_M 等主模型与 mmproj 配对；CPU/GPU offload 后的速度与质量
vLLM AWQ / GPTQ量化权重或量化配置上游服务正常；同一 harness 下表格/公式是否退化
远程服务OpenAI 兼容端点MinerU 不感知量化；只认质量与延迟
 
# llama.cpp：官方 Q8_0 是起点；更低比特用 llama.cpp 工具链转换与量化
# 1) 微调权重 → f16 GGUF
python llama.cpp/convert_hf_to_gguf.py /path/to/finetuned --outfile ft-f16.gguf
# 2) 量化
llama-quantize ft-f16.gguf ft-q4_k_m.gguf Q4_K_M
# 3) 放入本地模型目录，按 ModelRepo 的 main/mmproj 约定替换
mineru-kit models verify --tier standard

# vLLM：量化权重的加载方式由模型目录内的量化配置或服务参数决定
vllm serve /path/to/awq-model --served-model-name mineru-ft-awq --port 30001
  • 不要只看平均 CER：量化对长公式、密排表格、稀有字符更敏感，分项必须看。
  • mmproj 不能乱配：视觉投影与语言塔必须来自兼容训练；不匹配会乱码或静默错误。
  • 速度收益要落在真实链路：服务端 tokens/s 不等于端到端页/秒；用同一批 PDF 计 p50/p95。
  • 先定权重，再量化：常规流程量化后只做验收；若还要继续训练，应重新做量化感知训练（QAT），而不是直接在量化权重上微调。

6. 验收门槛与回滚

门槛建议不通过时
目标集主指标提升，且配对区间下界 > 0继续调数据/训练，不上线
回归集无显著退化；关键类型不下降扩数据、降学习率、回滚基线
边界集不出现新的崩溃/空输出模式修复后重跑
成本p95 延迟与显存在预算内换量化/引擎/规格
可回滚配置切换即可回到基线模型保留 base 服务与配置
 
# 上线顺序：影子 → 小流量 → 全量
# 1) 影子：候选服务接 5% 文档，只记录不采用
# 2) 小流量：采用结果，人工抽检关键字段
# 3) 全量：回归集每日巡检；异常时切回 base 的 server_url/model

8. 动手挑战

  1. 选 20 份文档，建立目标集/回归集/边界集，写出参考文本、公式与表格（人工或强模型校对）。
  2. 用同一 base 模型跑两遍评测，确认指标稳定；如果波动大，先固定采样或增加样本。
  3. 接入课程 12 的微调模型，跑同一套 harness，输出 CER、公式精确匹配、表格数与 p95 延迟。
  4. 把官方 GGUF Q8_0 与一个更低比特量化版本对比；如果表格/公式下降超过阈值，记录并回滚。
  5. 写一份一页纸的验收报告：结论、区间、分项、成本、回滚方案。
