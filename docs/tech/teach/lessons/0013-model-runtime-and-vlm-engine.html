模型运行时与 VLM 引擎调用链

这节课只做一件事：从一个 PDF 窗口的 VLM 阶段出发，完整追到“哪个引擎、哪份权重、哪个客户端、哪把锁、什么时候释放”，并能解释远程与本地、同步与异步、小模型与 VLM 的边界。

为什么学这个：扩展模型后端、接入私有推理服务、排查“GPU 没吃满 / 引擎死了 / 远程超时”，都落在这条链上。课程 02 讲“选哪个引擎”，本课讲“选完之后运行时怎么活”。

你将能够

  • 画出 window.py → get_vlm_predictor() → ModelSingleton → engine/client 的调用链。
  • 区分三层运行时：小模型原子模型、VLM 预测器、资源所有权。
  • 解释本地引擎、远程 http-client、原生异步三者的差异与不可回退语义。
  • 说出缓存键、初始化屏障和关闭顺序，避免资源泄漏或关闭后复用。
  • 按日志与错误现象定位到引擎选择、权重加载、连接或并发中的具体一环。

1. 一条链的两半

PDF 窗口high / xhigh 的 VLM 阶段
get_vlm_predictor()model/vlm/client.py · 读配置并校验
分支server_url 非空 → http-client
否则 → 本地引擎选择
ModelSingleton按缓存键复用 · 同键初始化屏障
RuntimeHandle / AsyncVlmPredictor统一实现 VlmPredictor 协议
# mineru/model/vlm/client.py —— 解析与预加载共用同一个入口
def get_vlm_predictor(vlm_config: VlmConfig | None = None) -> tuple[VlmPredictor, str]:
    settings = (vlm_config or get_config().model.vlm).model_copy(deep=True)
    settings.validate_environment()

    if settings.server_url:
        predictor = ModelSingleton().get_model(
            backend="http-client",
            model_path=None,
            server_url=settings.server_url,
            model_name=settings.model or None,
            server_headers=...,          # Authorization: Bearer <api_key>
            http_timeout=settings.http_timeout,
            max_concurrency=settings.max_concurrency,
        )
        return predictor, "http-client"

    engine = get_vlm_engine(settings.engine, is_async=True)
    return ModelSingleton().get_model(
        backend=engine,
        model_path=None,
        server_url=None,
        max_concurrency=settings.max_concurrency,
    ), engine
先记边界：server_url 非空时，远程优先且不加载本地引擎；连接失败直接报错，不会自动回退本地 VLM。

2. 三层运行时

层负责什么单例 / 入口典型资源
小模型原子模型layout、OCR det/rec、MFR、表格结构/分类、印章AtomModelSingleton（model/runtime/hybrid.py）ONNX Session / Torch 模型 / 权重文件

三层都通过 RuntimeOwner（model/runtime/ownership.py）登记租约。应用释放后，没有其它 owner 且未被 pinned 的模型才会真正关闭。

4. 客户端协议：四类调用

无论本地还是远程，窗口只依赖 VlmPredictor 协议（model/vlm/contracts.py）：

方法用途失败语义
batch_extract_with_layoutstandard：带布局块的单步抽取整批失败按引擎错误传播
batch_two_step_extractadvanced：两步抽取 + 图片分析同上
batch_recognize_text行内公式/文本切片识别单片失败可局部回退 MFR；致命错误必须抛出
aio_* 系列原生异步版本，复用同一并发额度取消传播，迟到结果不覆盖终态

协议很小，这是扩展新引擎最重要的收益：实现这四个方法，窗口编排不需要知道引擎存在。

5. 缓存、并发与原生异步

# model/vlm/runtime.py —— 缓存键由连接与选项共同决定
fingerprint = hashlib.sha256(json.dumps(options, sort_keys=True, default=str).encode()).hexdigest()
cache_key = (backend, model_path, server_url, fingerprint)
  • 同键共享：相同后端、权重、地址、选项只构造一次；max_concurrency、远程超时等连接选项也参与键。
  • 初始化屏障：同一键并发首次获取时只构造一次，其余等待；构造失败会清理后释放屏障。
  • 原生异步：http-client 与 vllm-async-engine 走 AsyncVlmPredictor；同步接口内部复用常驻事件循环。
  • 并发额度：max_concurrency 是 VLM 请求并发，不是 API server 的解析任务并发（--concurrency）。
# mineru/model/vlm/client.py
def uses_native_async_vlm(vlm_config=None) -> bool:
    settings = vlm_config or get_config().model.vlm
    if settings.server_url:
        return True                 # 远程 HTTP 一律原生异步
    return resolve_vlm_engine(settings.engine) == "vllm"

8. 生命周期：能复用，但不能在关闭中复用

  • RuntimeOwner 记录应用/文档租约；关闭 owner 会等待已接纳文档退出，再释放它持有的模型池。
  • 最后一个 owner 释放且模型未被 pinned 时才关闭；关闭期间同键获取会被拒绝（关闭屏障），避免“刚关掉又被复用”。
  • atexit 注册缓存清理；显式 shutdown() 用于测试或长期宿主进程。
  • 进程退出、服务重启或显式更换引擎后，旧缓存不会跨进程复用。
# 每份文档一个 document scope：模型缓存仍留在进程内
from mineru.model.runtime.ownership import runtime_document_scope

with runtime_document_scope():
    predictor, backend = get_vlm_predictor(config)
    ...  # 使用
# 退出后归还文档租约；应用级 owner 由宿主显式 release_runtime_owner(owner) 释放
