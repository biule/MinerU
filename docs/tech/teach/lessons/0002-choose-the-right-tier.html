Lesson 02 · 决策

选对档位：tier、effort 与引擎

这节课只做一件事：给定一个文档、硬件和安装方式，能为一句话解释“该用哪档、会跑什么、为什么不会自动降级”。

你将能够

  • 把产品档位（tier）映射到内部强度（effort）。
  • 解释 flash 与 standard 在 PDF 路径上的本质差异。
  • 按硬件与依赖判断实际会选哪个小模型后端和 VLM 引擎。
  • 说出不同入口的默认档位规则，避免“以为会降级”。
为什么先学这个：扩展 MinerU 时，最容易破坏的不是模型本身，而是“档位语义”。一旦默认选择或降级规则被改错，所有入口都会悄悄变差。

1. tier → effort

tiereffortPDF 执行方式
flashflashtxt：DocVortex 原生 PDF 模型；ocr：布局小模型 + OCR
basicmedium小模型：layout + OCR + MFR + 表格
standardhigh小模型 + VLM 单步抽取
advancedxhigh小模型 + VLM 两步抽取 + 图片分析
 
# mineru/parser/tier.py —— 映射是显式的，不做运行时注册
_EFFORT_BY_TIER = {
    "flash": "flash",
    "basic": "medium",
    "standard": "high",
    "advanced": "xhigh",
}

2. 决策树

输入文档类型 + tier + 硬件 + 依赖
是 PDF/图片吗？否 → 原生格式 → 固定 flash/txt
tier = flash？是 → txt 走原生；ocr 走 Flash OCR
tier = basic？是 → 小模型 medium，不用 VLM
tier = standard / advanced？小模型 + VLM（单步 / 两步）
关键边界：原生格式（Office/ODF/EPUB/OFD/HTML/MHTML/CSV/TSV）没有 basic/standard/advanced。CLI 单文件显式质量档位会报错；Python SDK 与批量入口会归一为 flash。

3. 引擎选择

3.1 小模型后端（ONNX / Torch）

# model/runtime/device.py
if selected in ("onnx", "torch"):
    return selected

# auto：只有 Torch 依赖齐全且设备不是 CPU 时才用 Torch
if all(module_available(name) for name in TORCH_REQUIRED_MODULES) and get_device().split(":")[0] != "cpu":
    return "torch"
return "onnx"

3.2 VLM 引擎

# model/vlm/selector.py（auto 规则）
if 非 Linux/Windows 或设备是 CPU:
    return "llama-cpp"
if Linux 且安装了 vllm:
    return "vllm"
if 设备不是 xpu 且安装了 lmdeploy:
    return "lmdeploy"
return "llama-cpp"

# 但：server_url 非空时，远程 HTTP 优先，不加载本地引擎
场景实际引擎
Windows + CPU + 基础包ONNX 小模型 + llama.cpp VLM
Linux + NVIDIA + 已装 vLLMTorch 或 ONNX 小模型 + vLLM
Windows + NVIDIA + 已装 LMDeploy小模型 + LMDeploy
配置了 model.vlm.server_url远程 HTTP VLM（本地不再加载引擎）

4. 默认选择规则

入口默认
Python parse()standard；不接受 None/auto
mineru-kit parsePDF/图片 standard；原生格式 flash
Tasks / HTTP SDKstandard → basic → flash → advanced
Doclib 主动质量解析standard → basic；无可用档位报错
Doclib 已缓存读取advanced → standard → basic；不新建解析
Doclib parsing rulestandard → basic → flash

显式请求不支持的档位会返回错误，不会静默改档。服务启动的 --tier 是能力上限，不是单次请求档位。

6. 场景练习

先自己回答，再打开源码核对。不要查资料，先凭记忆写出来。

  1. Windows + CPU + 只装了基础包，用户要“正常阅读质量”。选哪档？实际会跑哪些模型？
  2. Linux + NVIDIA + 已装 vLLM，要处理大量 PDF。选哪档？VLM 引擎是什么？
  3. 用户上传一个 .docx，并显式要求 --tier standard。会发生什么？
  4. 配置了 model.vlm.server_url，但机器上没装任何本地 VLM 引擎。standard 能跑吗？

核对：场景 1–2 见 档位矩阵 的引擎表；场景 3 见“常见误区”；场景 4 见 docs/next/tiers.md 的“数据、模型与隐私”。
