Lesson 08 · 综合

安全扩展清单

这节课把前七课串起来：给定四种典型改动（新格式 / 新渲染 / 新引擎 / 新服务 API），能列出完整改动点清单并通过护栏检查。

为什么学这个：这是使命的直接兑现——把 fork 改出定制能力，且不破坏现有行为。

1. 先定位落点

出题改什么、从哪个入口输入
定位格式 → filetypes + analyze
推理 → model
输出 → render
状态 → doclib / tasks
护栏不变量五查 → 测试三线

2. 改动一：新增输入格式

  1. 扩展名进入正确集合（PARSEABLE / INGESTIBLE / DISCOVERABLE，filetypes.py）；登记 MIME。
  2. 确定解析路径：原生格式只在 DocVortex 实现——需要先在 DocVortex 加分析器，MinerU 只登记与路由。
  3. doc_analyze() 加显式路由分支（backend/analyze.py）。
  4. 确认页范围边界（目前仅 PDF）、tier 归属（原生固定 flash）。
  5. Doclib：入库、扫描、watch 自动生效（依赖扩展名集合）。
  6. 测试：单文件、批量、Doclib、API 四线 + 错误路径。

3. 改动二：新增渲染格式

  1. render/contracts.py：加 RenderFormat 枚举与选项类。
  2. render/api.py：加分支、返回类型 overload、options 类型校验。
  3. render/__init__.py：显式导出 __all__。
  4. 通用格式放 DocVortex；MinerU 只保留 Content List 类产品格式。
  5. 测试：结构、图片、公式定界符、空块、asset_base_url。

4. 改动三：新增 VLM 引擎

  1. model/vlm/selector.py：引擎名、后端映射、必需模块、auto 选择逻辑。
  2. model/vlm/runtime.py：构造分支 + 同级 close 逻辑；注意缓存键与单例语义。
  3. 权重格式不同则加 ModelRepo（model/registry.py）。
  4. pyproject.toml：可选 extra 与版本约束。
  5. 测试：同步 + 原生异步两条路径、释放、远程优先不回退本地的语义。

5. 改动四：新增 Doclib API

  1. doclib/types.py：请求/响应模型。
  2. doclib/services/：服务实现（业务在 service，不在 route）。
  3. doclib/server.py：@route(...) 注册。
  4. doclib/client.py：同路径客户端方法（装饰器保持一致）。
  5. 测试：服务端 + 客户端契约、UDS/TCP 两种传输、错误码映射。

6. 护栏五查（改完必过）

#检查依据
1无隐式副作用：import 不读环境、不建目录、不注册、不加载重依赖CLAUDE.md 确定性优先 / 惰性加载
2相对导入 + 显式 __all__；分派用显式映射CLAUDE.md
3隐私：--remote 上传必须有显式许可；存在配置 ≠ 许可docs/next/invariants.md
4协议：公开字段只走 MiddleJson；错误码不换含义；locator 保持可解析invariants.md
5生命周期：取消后迟到结果不改终态；启动失败也要清理已获资源invariants.md

9. 综合练习

  1. Case：“支持 .xlsx 里的多工作表拆成多 page”——列出全部改动点与护栏检查结论。
  2. Case：“给 WebUI 加一个‘再解析一次’按钮”——哪个服务承担执行？需要什么 API 变更？会不会破坏缓存语义？
  3. Case：“新模型引擎想支持 AMD GPU”——引擎选择逻辑里需要动哪几行？auto 与显式选择的差别是什么？

建议把答案写成一份简短的改动计划发给教师（agent）复核。
