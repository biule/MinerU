Lesson 17 · 上线

部署与运维：从能跑到能长期跑

这节课只做一件事：把 MinerU 的进程角色、启动顺序、鉴权、容量、日志、升级与回滚讲清楚，能在一台机器或一组 worker 上稳定运行，并在故障时有明确动作。

为什么学这个：课程 07 讲协议，本课讲“谁来跑、跑在哪、怎么发现坏了”。部署错误通常不是模型问题，而是进程边界、资源上限或鉴权配置错误。

1. 先认清进程角色

客户端 / NginxHTTPS · 鉴权 · 限流 · 大文件
Router（可选）worker 发现 · 调度 · 公共 ID 映射
api-server × N完整解析 API · 模型推理 · 产物
vlm-server（可选）OpenAI 兼容 VLM 推理
Doclib / file-parse / WebUI本地库 · 单文件同步 · 演示界面
角色入口职责状态
api-servermineru-kit api-serverV1 Tasks、模型、下载链接、产物元数据在内存；重启不恢复旧资源 ID
Routermineru-kit router多 worker 统一入口、调度、公共 ID动态 worker 清单不落盘
vlm-servermineru-kit vlm-server只做 VLM 推理，OpenAI 兼容模型服务生命周期
Doclibmineru server start入库、缓存、排队、搜索、watchSQLite + 文件；有 home 锁
file-parsemineru-kit file-parse-server单文件 multipart 同步包装记录持久化；可恢复查询
WebUImineru-kit webuiGradio 演示；未给 api-url 时托管本地 API无状态 UI

2. 三种典型拓扑

拓扑组成适合注意
单机 CPUapi-server（ONNX + llama.cpp）内网、低并发、隐私优先内存与窗口大小；并发通常 1–2
单机 GPUapi-server（Torch + vLLM/LMDeploy）吞吐优先显存、VLM 并发、模型预加载
分离推理api-server + 独立 vlm-server多 API 复用一组 GPUVLM 并发与网络超时；远程无回退
多 workerNginx → Router → api-server × N多 GPU、横向扩展公共 ID、租约、worker 健康
 
# 单机：托管本地 parse-server（Doclib 拉起/停止）
mineru config set parse_server.local.mode managed
mineru config set parse_server.local.managed_tier standard
mineru server start

# 分离：自己起 API 与 VLM
mineru-kit vlm-server --engine vllm --port 30000
mineru-kit api-server --host 127.0.0.1 --port 8000 --tier standard \
  --vlm-server-url http://127.0.0.1:30000/v1 --vlm-max-concurrency 32 --preload-models

# 多 worker：Router 拉起本地 worker（auto 按 GPU 数）
mineru-kit router --host 127.0.0.1 --port 8002 --worker-tier standard --worker-concurrency 1
# 或接外部 worker
mineru-kit router --upstream-url http://10.0.0.11:8000 --upstream-url http://10.0.0.12:8000

3. 启动顺序与配置来源

  1. 准备模型：mineru-kit models download --tier standard；离线环境设 MINERU_MODEL_SOURCE=local。
  2. 起 VLM（如分离部署）：mineru-kit vlm-server，确认 /v1/models。
  3. 起 api-server：设置 --tier 上限、--api-key、--vlm-server-url。
  4. 起 Router（如多 worker）：配置 --upstream-url 或本地 GPU 列表。
  5. 起 Doclib：配置 parse_server.local.mode 后 mineru server start。
  6. 健康检查：/v1/health、/v1/tiers、mineru server status --json。
配置层示例何时生效
命令行--tier、--port、--api-key本次进程
环境变量MINERU_MODEL_VLM_SERVER_URL、MINERU_LOG_LEVEL本次进程
文件配置$MINERU_HOME/config.yaml 的 model、doclib、log启动时读取
运行时 KVparse_server.local.mode、parse_server.remote.api_keyDoclib 运行中

4. 关键参数与容量

参数默认说明
--tierautoPDF/图片最高开放档位；包含较低档位；不是单次请求档位
--concurrency1并发解析任务数；不是 VLM 请求并发
--preload-models关启动时初始化模型/远程 VLM；失败让能力接口报错
--api-key空设置后除 health/models/tiers 外均需 Bearer
--upload-dir自动一个目录只能由一个 API 实例占用
--retention-seconds86400终态资源保留；0 关闭自动回收
--vlm-max-concurrency100上游 VLM 请求并发
--worker-tierstandardRouter 托管 worker 的能力上限
档位 / 引擎模型下载最低内存加速
basic / ONNX~0.8 GB2 GBCPU 可用
basic / PyTorch~0.8 GB8 GB建议 GPU/MPS
standard / ONNX + llama.cpp~2 GB8 GBCPU 可用；建议 Vulkan
standard / PyTorch + vLLM/LMDeploy~3 GB16 GBGPU/MPS，8 GB+ 显存

API server 的 --tier auto：GPU 开放四档；CPU 按可用逻辑核数推荐（≥12 → standard；4–11 → basic；<4 → flash）。显式上限可覆盖推荐，但仍执行依赖预检。

5. 进程守护与反向代理

# /etc/systemd/system/mineru-api.service
[Unit]
Description=MinerU API server
After=network-online.target

[Service]
User=mineru
WorkingDirectory=/opt/mineru
Environment=MINERU_HOME=/var/lib/mineru
Environment=MINERU_MODEL_SOURCE=local
EnvironmentFile=-/etc/mineru.env
ExecStart=/opt/mineru/.venv/bin/mineru-kit api-server \
  --host 127.0.0.1 --port 8000 --tier standard --preload-models \
  --api-key ${MINERU_API_KEY}
Restart=on-failure
RestartSec=5
TimeoutStopSec=60

[Install]
WantedBy=multi-user.target
# Doclib 直接以模块运行，由 systemd 托管（会获取 doclib.lock）
ExecStart=/opt/mineru/.venv/bin/python -m mineru.doclib.app
Environment=MINERU_HOME=/var/lib/mineru
# /etc/nginx/conf.d/mineru.conf
server {
    listen 443 ssl;
    server_name mineru.example.com;

    client_max_body_size 200m;              # 大 PDF
    proxy_read_timeout 3600s;               # 长解析
    proxy_send_timeout 3600s;

    location /v1/ {
        proxy_pass http://127.0.0.1:8002;   # Router 或 api-server
        proxy_set_header Host $host;
        proxy_set_header X-Request-ID $request_id;
        proxy_set_header Authorization $http_authorization;
    }
}
Windows：仓库没有内置 Windows 服务管理。可用 NSSM、sc.exe 或任务计划程序托管 mineru-kit.exe；把 MINERU_HOME、模型目录与日志路径设为机器级环境变量，避免服务账户找不到用户目录。

6. 鉴权与隐私

边界要求常见错误
解析 API默认 loopback；对外必须 TLS + --api-key直接 0.0.0.0 无鉴权
DoclibUDS/TCP + 持久 token；MINERU_DOCLIB_AUTH_TOKEN 覆盖把 token 写进镜像或日志
远程 VLM--vlm-api-key 独立于解析 API Key两个 Key 混用
远端解析必须显式 --remote 或规则允许“配了 Key 就以为会上传”
上传来源URL 输入默认只允许 HTTPS；--allow-http-source 才放开内网明文源被 SSRF 利用

curl http://127.0.0.1:8000/v1/health

curl http://127.0.0.1:8000/v1/tiers

# Doclib 状态：队列、worker、managed parse-server、日志路径
mineru server status --json

# 日志
~/.mineru/logs/doclib.log
~/.mineru/logs/doclib.access.log
~/.mineru/logs/doclib.parse-server.stdout.log
~/.mineru/logs/doclib.parse-server.stderr.log

# 阶段计时：pdf.layout / pdf.ocr_detection / pdf.formulas
#           / pdf.table_recognition / pdf.inline_vlm / pdf.image_assets
  • API server 的 --log-level 只管服务侧（Uvicorn/访问日志）；模型日志跟随 MINERU_LOG_LEVEL。
  • 托管 worker 默认用 --log-level warning，避免访问日志刷屏；排障时调 MINERU_LOG_LEVEL。
  • 仓库不内置 Prometheus 指标；用 Nginx 访问日志、请求 ID、server status 与阶段计时做基础观测。

8. 运维手册

操作命令 / 动作注意
启动 Doclibmineru server start同一 MINERU_HOME 只能一个 owner
停止 Doclibmineru server stop等待 endpoint 不可连且锁释放
重启mineru server restart先 stop 再 start，避免双实例
升级停服务 → 备份 MINERU_HOME → 换环境 → 启动旧 endpoint 会返回 doclib_upgrade_required
备份config.yaml、doclib.db、parsed/、模型目录素材与协议一起备份才能重渲染
恢复停服务 → 还原 → 启动 → server status不要热替换 SQLite
清理磁盘调小 --retention-seconds / 手动归档0 表示永久保留，谨慎
回滚切回旧镜像 + 旧模型目录先确认缓存协议兼容边界

9. 常见故障速查

现象根因动作
server_not_runningDoclib 未启动mineru server start
server_busy / service_unavailable同 home 已被另一个进程持有查 doclib.lock 与 PID；不要抢占
quality_tier_unavailable没有 basic/standard 引擎起本地服务 / --remote / 显式 flash
engine_dead / 503vLLM 等引擎死亡重启引擎；Router 剔除 worker
首个请求很慢模型未预加载--preload-models / 预热
上传 413Nginx 或服务端大小限制调 client_max_body_size / 分片
401API Key 缺失或 VLM Key 混用分别检查 --api-key 与 --vlm-api-key
磁盘涨满保留期过长 / 上传目录未清理调 retention；检查 --upload-dir 独占

11. 动手挑战

  1. 用 mineru-kit api-server --tier standard --preload-models 起服务，记录启动耗时、显存/内存、/v1/tiers 输出。
  2. 加一个 Nginx 反代（或本机端口转发），上传 100 MB PDF，确认超时与大小限制。
  3. 配置 --api-key，分别测试无 Key、错误 Key、正确 Key 的 health 与 tasks 请求。
  4. 模拟引擎故障（停掉 vllm-server），观察错误码、日志与 Router 的 worker 健康变化。
  5. 写一份值班卡片：启动顺序、健康检查、日志位置、回滚步骤，贴在项目 docs/tech/teach/reference/ 下。
