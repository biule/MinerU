Lesson 06 · 配置

配置与隐私边界

这节课只做一件事：能说清两阶段配置（启动前 / 运行时）、优先级顺序，以及“配置了远端 ≠ 允许上传”的不变量。

为什么学这个：隐私不变量是 MinerU 的硬约束。新增任何“默认走远端”的便捷行为都是事故；任何配置改动都要先过这一关。

1. 两阶段配置

阶段存储例子为什么
启动前$MINERU_HOME/config.yaml + 环境变量 + 默认值UDS/TCP、DB 路径、模型目录、日志、VLM 连接server 还没起来，读不了 SQLite
运行时SQLite config 表 + watches / rules 表parse_server.local.mode、远端 URL/Keyserver 起来后才可读写
  • MINERU_HOME 默认 ~/.mineru；默认配置文件 $MINERU_HOME/config.yaml；MINERU_CONFIG 显式指定。
  • Config() 只构造默认值；首次 get_config() 读取并缓存进程默认配置，之后不自动刷新。
  • 启动前文件配置与 SQLite 配置不定义同一 key，设计上避免互相覆盖。

2. 优先级

1. 当前命令显式参数        # --tier standard、--remote
2. 当前进程环境变量        # MINERU_MODEL_VLM_SERVER_URL 等
3. 文件配置 / SQLite 配置
4. 内置默认值

环境变量按字段路径覆盖任意强类型字段，例如 MINERU_LLM_AIDED_FEATURES_TITLE_LEVELING。

3. 运行时 KV 关键项

key默认值说明
parse_server.local.modedisableddisabled / managed / self_hosted
parse_server.local.managed_tierstandard托管服务能力上限
parse_server.remote.urlhttps://mineru.net/api远端解析地址
parse_server.remote.api_key无未配置时回退 MINERU_API_KEY

4. 隐私不变量

# 存在 remote URL / API Key ≠ 允许上传
# 上传必须由当前请求或 parsing-rule 显式允许

# parse_queue_svc.py：远端限制在请求层强制执行
if remote and ext not in TIERED_PARSE_EXTENSIONS:
    raise InvalidRequestError("remote_unsupported_for_file_type", ...)
if remote and tier == "flash":
    raise InvalidRequestError("tier_unsupported_for_remote", ...)
  • 没有显式远端配置，不把文档上传到远程解析服务。
  • --remote 只支持 PDF/图片，且不支持 flash。
  • API Key 优先读取 SQLite 配置；未配置才回退环境变量 MINERU_API_KEY。
  • 环境变量不改变“是否允许 remote 上传”的判断。
判断准则：任何“自动上传”的行为都是 bug。宁可报 quality_tier_unavailable 让用户选择，也不要静默把文档送出去。

5. 其他要点

  • Doclib 凭证：doclib.auth.token 首启动时用配置锁写入文件；MINERU_DOCLIB_AUTH_TOKEN 覆盖文件值且不回写秒；以 SecretStr 保存，repr/JSON 脱敏，不进运行时 /configs。
  • 远程 VLM：model.vlm.server_url 非空即远程；远程模式不自动回退本地 VLM。
  • LLM 增强：两个功能默认关；任一启用时连接三项必须非空。
  • 日志：log.level 管 Loguru 默认 sink；doclib.log.level 是 Doclib 进程局部覆盖；api-server --log-level 只覆盖服务侧 stdlib 日志。
