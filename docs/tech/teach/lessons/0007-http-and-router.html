Lesson 07 · 服务

HTTP 服务与 Router

这节课只做一件事：能走完一条 Tasks 生命周期（创建 → 上传 → 执行 → 下载 → 取消），并说出 file-parse、WebUI、Router 各自的存在理由。

为什么学这个：服务化是 fork 的常见扩展方向。Tasks 的“逐文件独立完成”和“ID 不透明”两条规则，是最容易被破坏的契约。

1. Tasks 协议

MethodPath用途
POST/v1/tasksJSON files 清单创建任务；返回缺失文件的上传链接（202）
PUT返回的上传链接每个链接上传一个文件；没有 complete 请求
GET/v1/tasks/{task_id}总状态 + 逐文件状态 + 成功文件的结果链接
POST/v1/tasks/{task_id}/cancel取消未完成文件；成功文件保留产物
GET/v1/files/{file_id}/content下载结果（default/docx/html/latex）
GET/v1/health · /v1/models · /v1/tiers能力发现（免鉴权）

2. 逐文件状态机

waiting-file等待上传
pending上传完成，等待执行
running解析执行中
completed / failed / canceled终态
  • 就绪文件独立执行，不等其他文件上传。
  • 单文件 completed 即可下载其结果，不要求父任务终结。
  • 父任务状态是聚合：全部成功 completed；部分成功 partial；出现取消 canceled。
  • 取消后迟到的结果不能改成成功。

3. 资源与 ID

  • task 聚合逐文件状态；file 是源文件视图或解析产物。
  • ID 是 OpenAI 风格前缀 + 随机串（如 file-r9NS…）；不透明，客户端不得从中推断时间、租户或存储路径。
  • Router 场景下公共 file_id 与 worker 内部 ID 可以不同，不由客户端推导。
  • 认证：配置了 API Key 后，除 health/models/tiers 外均需 Authorization: Bearer …；未配置时本地允许匿名。

4. 输出打包

# parser/task_outputs.py —— 每个输入只发布一个完整可下载文件
formats = default / docx / html / latex

default → markdown.md + middle_json.json + structured_content.json
docx    → document.docx（单格式时直接返回该文件）
html    → document.html（图片内嵌）
latex   → document.tex
多格式  → result.zip（default/latex 附 images/ 目录）

5. 兄弟服务

服务入口存在理由
file-parsemineru-kit file-parse-server单文件 multipart 直传 + 同步等待 + 请求 ID 恢复；超时返回 202
WebUImineru-kit webuiGradio 界面；未指定 api-url 时托管本地 V1 API
Routermineru-kit routerworker 发现/认证/调度、公共 ID 映射、源缓存与结果租约；对外仍是 Tasks 协议

file-parse 先持久化源文件与 request_id，再创建/上传/等待上游 Tasks；等待超时可继续查询；客户端断连不自动取消。
