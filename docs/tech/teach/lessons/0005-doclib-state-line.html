Lesson 05 · 状态

Doclib 状态线：缓存、排队与读取

这节课只做一件事：能解释“mineru parse 第二次为什么快”——按页缓存怎么算覆盖、批次怎么复用、读取为什么不会触发新解析。

为什么学这个：Doclib 是 Agent 阅读体验的核心。缓存覆盖算法和“读取不建解析”的两条不变量，决定了任何 Doclib 改动的安全边界。

1. 路径与内容身份

  • 路径（file）是实例，可有状态：active / deleted / unreachable。
  • sha256（doc）是内容身份；多个路径可指向同一内容。
  • 解析缓存按 sha256 + tier + 页范围 组织；forget 移除记录不删源文件。

2. 排队算法：按页去重

# doclib/services/parse_queue_svc.py —— request_parse 核心步骤

# 1) 先刷新路径，确保 files.sha256 对应当前内容
refreshed = await self.ingest_svc.refresh_file(path, ensure_ingested=True, allow_images=True)

# 2) tier 在缓存检查前确定
if ext in TIERED_PARSE_EXTENSIONS:
    requested_tier = tier or parse_policy.resolve_default_tier(health=self.health, remote=remote)
else:
    requested_tier = "flash"

# 3) 默认页范围：已知页数取前 10 页；未知取第 1 页
request_page_range = expand_page_range(
    page_range or parse_policy.default_parse_range(page_count), page_count or 1)
needed = parse_page_range_set(request_page_range)

# 4) 已完成且可读的批次覆盖的页，直接扣除 → 纯缓存命中
if not force:
    for batch in valid_done_batches:
        needed -= parse_page_range_set(batch["page_range"])
    if not needed:
        return _done_response(...)   # status = done

# 5) 排队/解析中批次覆盖的页：复用 + 把优先级提到 1，不新建
if batch["id"] in reused_parse_ids and batch["priority"] < 1:
    await self.db.execute("UPDATE parses SET priority=1 ...")

# 6) 仍缺的页创建新批次（priority=1，前台请求高优先级）
请求path + tier + pages
刷新与校验文本文件 → parse_not_required；非 PDF 页范围 → 报错
缓存检查done 批次扣页 → 全覆盖则 done
活动批次复用parsing/pending 扣页 → 提升优先级
新批次只解析缺失页（priority=1）

3. force / invalidate / forget

操作作用不做什么
--force本次请求跳过 done 缓存不删除、不作废旧结果
invalidate未来解析与读取避开旧缓存不自动触发新解析
forget移除文件记录与缓存不删源文件；可能被 watch 重新发现

4. 执行状态机

# doclib/background/parse_worker.py + parse_execution_svc.py
# worker 循环：acquire_task → process_doc → done/failed

async def process_doc(self, task):
    # 抢占校验：状态必须仍是 parsing（丢失锁的批次直接放弃）
    if current["status"] != PARSE_STATUS_PARSING:
        return False

    if tier == "flash":
        result = await self._parse_via_local(...)      # 本地 parse()，跑在线程里
    else:
        result, via = await self._parse_via_api(...)   # managed / self_hosted / remote
  • 启动时清理崩溃遗留：parsing → failed、释放锁。
  • 任何失败都会写 error_code/error_msg 并释放锁。
  • 取消后迟到的结果不能改写终态。

5. 读取：locator 与续读

doc:{short_id}                                    # 自动选最高已缓存档位
doc:{short_id}/tier:{tier}
doc:{short_id}/tier:{tier}/page:{page_no}         # 页码 1 起
doc:{short_id}/tier:{tier}/page:{page_no}/block:{block_no}
doc:{short_id}/tier:{tier}/page:{page_no}/block:{block_no}/char:{offset}  # 0 起
  • 读取不会触发新的质量解析；没有缓存时返回错误（如 tier_not_cached）。
  • --context N：页 locator 取上下 N 页；块 locator 取上下 N 块。
  • --limit 是软字符预算；超限时输出带续读游标（next_request.after）。
  • markdown 按读取需要从缓存 MiddleJson 现场渲染；缓存里存的是 JSON 与素材，不是 markdown。
