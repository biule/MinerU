Lesson 10 · 微调系列 1/3

微调总览：VLM 在哪里、能改什么

这节课只做一件事：能指出 MinerU 里“模型”被调用的确切位置，说清三条微调落地路径各自的边界，并判断你的需求属于哪一条。

先认清边界：本仓库不含训练代码。MinerU 是模型的使用方：它通过 mineru_vl_utils.MinerUClient 调用模型。微调本身在外部完成（vLLM/transformers 等框架），落地方式是把微调后的模型接回 MinerU 的推理路径。

1. 模型在哪里被调用

窗口推理high/xhigh 档位的 VLM 阶段
VlmPredictor 协议batch_extract_with_layout · batch_two_step_extract · batch_recognize_text
MinerUClientmineru_vl_utils · 构造 prompt / 采样参数 / 后处理
四个后端llama.cpp · vLLM · LMDeploy · MLX ·(或 http-client 远程)
# mineru/model/vlm/runtime.py —— 所有本地/远程后端最后都收敛到一个客户端
predictor = MinerUClient(
    backend=backend,            # llama-cpp-engine / vllm-async-engine / http-client / …
    model_name=model_name,
    server_url=server_url,      # 远程模式
    ...
    enable_table_formula_eq_wrap=True,
    image_analysis=True,
)

2. 能“改模型行为”的四层

层是否需要训练改哪里影响范围
Prompt / 采样参数❌mineru_vl_utils 的 DEFAULT_PROMPTS / DEFAULT_SAMPLING_PARAMS每种块类型的识别指令（table / equation / text…）
抽取开关❌not_extract_list、image_analysis、skip_list哪些块交给 VLM、跳过哪些类型
模型权重✅ 微调权重文件（Safetensors / GGUF）识别质量、新版面、专属领域
流水线策略❌backend/analysis/pdf/ 阶段逻辑何时调用 VLM、回退规则

练手顺序：从上往下。多数“模型不听话”的问题在第一、二层就能解决，不必微调。

3. 微调后的三条落地路径

路径 A：远程服务微调模型 → vLLM OpenAI 服务
→ model.vlm.server_url 指向它（首选）
路径 B：本地引擎权重放本地 → vLLM/LMDeploy 本地加载
或转换为 GGUF + llama.cpp
路径 C：无训练适配只改 prompt / 开关 / 流水线
不碰权重

路径 A：远程服务（推荐起点）

MinerU 对远程 VLM 是一等公民支持——docs/next/config.md 明确：上游“须部署支持 MinerU 文档理解输出的模型，并提供 /v1/models 和 /v1/chat/completions”。微调后的模型用 vLLM 起一个 OpenAI 服务即可接入：

# config.yaml —— 所有本地解析入口共享；远程地址优先于本地引擎
model:
  vlm:
    server_url: http://127.0.0.1:30000/v1
    api_key: ${VLM_API_KEY:-}
    model: ""            # 空时要求上游模型列表恰好包含一个模型
    http_timeout: 600
    max_concurrency: 100
  • 验证来源：mineru/model/vlm/client.py —— server_url 非空即构造 http-client，不加载本地引擎。
  • 远程模式不会自动回退本地 VLM。
  • max_concurrency 是 VLM 请求并发，与 API server 的 --concurrency（解析任务并发）不同。

路径 B：本地引擎

  • vLLM / LMDeploy：放本地权重目录，引擎按 resolve_vlm_engine() 自动选择或显式指定。
  • llama.cpp：需要把微调权重转换为 GGUF（主模型 + mmproj 投影两个文件），放入 MINERU_2_5_PRO_2605_1_2B_GGUF 仓库的路径约定（main + mmproj）。
  • 模型来源可用 model.source: local + model.base_dir 指定本地目录。

路径 C：不训练的适配（先试这个）

MinerUClient 把每种块类型的 prompt 与采样参数显式列在表里：

# mineru_vl_utils/mineru_client.py
DEFAULT_PROMPTS = {
    "table": "\nTable Recognition:",
    "equation": "\nFormula Recognition:",
    "image": "\nImage Analysis:",
    "[default]": "\nText Recognition:",
    "[layout]": "\nLayout Detection:",
}
DEFAULT_SAMPLING_PARAMS = {
    "[default]": MinerUSamplingParams(presence_penalty=1.0, frequency_penalty=0.05),
    ...
}

改这张表 = 改全部 standard/advanced 调用的行为；动表之前先用 content_extract 手工验证因果。

4. 决策树

症状“识别错了/漏了/领域不对”
是 prompt 或开关问题吗？是 → 路径 C（改表 / not_extract_list）
通用模型缺领域知识？是 → 微调 → 训练数据（课程 11）
服务化还是单机？多机/服务 → 路径 A（vLLM 远程）
单机 → 路径 B（本地引擎）
