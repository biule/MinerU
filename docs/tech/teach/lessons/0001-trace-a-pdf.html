Lesson 01 · 主线

追踪一个 PDF：从输入到 MiddleJson

这节课只做一件事：能在不查资料的情况下，说出一个 PDF 从命令行进入 MinerU 后，经过哪些模块、在哪些点做出决策、最终变成什么对象。这是后续所有改动的地基。

你将能够

  • 画出 `parse()` → `doc_analyze()` → `analyze_pdf()` → `MiddleJson` 的调用链。
  • 说出 PDF 在 flash/basic/standard/advanced 下的不同执行路径。
  • 定位“输入准备 / 路由 / 窗口编排 / 后处理”四个改动落点。
为什么先学这个：你要扩展这个 fork。任何功能改动都要落在某条链路的某一环；说不清链路，就只能靠猜。

1. 一张图

输入path + tier + ocr_mode + page_range
MinerUParser._prepare_input()类型识别 · 图片转 PDF · 页范围重写
doc_analyze()按 file_suffix 路由
analyze_pdf()分类 → 选择模型 → 窗口流水线
ModelJson内部原始结果
model_json_to_middle_json()确定性后处理 + 可选 LLM
ParseResult(MiddleJson)渲染 / 保存 / 读取

2. 五个决策点

决策点 1：输入被当成什么？

图片不会单独走一条流水线，而是先转成 PDF；页范围只有 PDF 支持。源码 mineru/parser/mineru_parser.py：

# 1) 页范围语法先归一（1-5 / r1 / all）
page_range = normalize_page_range_input(page_range)

file_bytes = path.read_bytes()
suffix = guess_suffix_by_path(path)
source_suffix = suffix

# 2) 图片统一转 PDF，后续走同一条 PDF 流水线
if suffix in IMAGE_EXTENSIONS:
    from docvortex.document.pdf import PDFDocument
    file_bytes = PDFDocument.from_image(file_bytes).bytes
    suffix = "pdf"

# 3) 页范围只允许 PDF；其他格式整本解析
if source_suffix not in PAGE_RANGE_PARSE_EXTENSIONS and page_range.strip():
    raise InvalidRequestError("page_range_invalid", ...)

# 4) PDF 只保留请求页；坏页会被记录，稍后补空占位
file_bytes, retained, broken = self._maybe_adjust_pdf_bytes(file_bytes, suffix, page_range)

决策点 2：交给哪个分析器？

doc_analyze() 是统一门面。它先校验参数，再按后缀显式路由：

if file_suffix == "pdf":
    result = analyze_pdf(...)          # PDF：窗口流水线
elif file_suffix in ("csv", "tsv"):
    result = analyze_csv(...)          # 原生 Flash
elif file_suffix == "epub":
    result = analyze_epub(...)
elif file_suffix == "html":
    result = analyze_html(...)
elif file_suffix == "mhtml":
    result = analyze_mhtml(...)
elif file_suffix == "ofd":
    result = analyze_ofd(...)
else:
    result = analyze_office(...)       # Office / ODF / RTF

决策点 3：PDF 用哪条执行路径？

这是最重要的分叉，发生在 _prepare_analysis()：

state.document = PDFDocument(file_bytes)

# auto：由 DocVortex 分类文本层；否则使用显式 txt/ocr
if parse_mode == "auto":
    parse_mode = state.document.classify()

# flash + txt：完全不加载小模型，直接走原生 PDF 模型
state.flash_txt_mode = effort == "flash" and state.parse_mode == "txt"

if not state.flash_txt_mode:
    # 其他情况：加载/复用 Hybrid 小模型
    state.hybrid_model = HybridLocalModelContextSingleton().get_model()
    acquire_document(state.hybrid_model.device)

    # high/xhigh：额外创建 VLM 预测器
    if effort in {"high", "xhigh"}:
        state.predictor, _backend = get_vlm_predictor(vlm_config)

决策点 4：窗口里做什么？

PDF 按窗口（默认 64 页）处理。每个窗口固定三段：准备 → 推理 → 收尾。

准备渲染页面
小模型 layout
表格方向/原生表格
推理flash：OCR
medium：MFR/表格/OCR
high/xhigh：VLM
收尾正文回填
公式编号合并
视觉块裁图
# 准备与收尾持有本地模型锁；VLM 推理期间释放锁（window.py）
with local_model_stage(hybrid_model.device):
    state = _prepare_pdf_window(...)

if effort in {"high", "xhigh"}:
    result = (vlm_predictor.batch_extract_with_layout(**options)
              if effort == "high" else
              vlm_predictor.batch_two_step_extract(**options))

with local_model_stage(hybrid_model.device):
    return _finish_pdf_window(state, result, ...)

决策点 5：结果如何变成公开协议？

# 1) 分析结果先包装为 ModelJson（内部对象）
model_json = _build_model_json(result, file_suffix, page_index_map, source_properties)

# 2) DocVortex 做确定性后处理；MinerU 只在 PDF 上追加可选 LLM 增强
middle_json = model_json_to_middle_json(model_json, llm_aided_config=get_config().llm_aided)

# 3) 返回 ParseResult；渲染与保存都从 MiddleJson 出发
return ParseResult(middle_json=middle_json)
记住这条边界：ModelJson 只服务内部；公开协议是 MiddleJson；ParseResult 只持有 MiddleJson，不持有 PDF 对象。

打开仓库，完成这三个检索任务。每个任务都能在 2 分钟内完成；做完再回来核对。

  1. 在 mineru/parser/mineru_parser.py 找到图片转 PDF 的那一行，并说出为什么后缀要改成 pdf。
