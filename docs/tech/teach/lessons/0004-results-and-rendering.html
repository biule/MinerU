Lesson 04 · 协议

结果协议与九种渲染

这节课只做一件事：能区分 ModelJson、MiddleJson、ParseResult 三个对象的边界，说出九种输出格式的归属，并正确使用 save() 与 render()。

为什么学这个：协议是公共契约。弄错对象边界（比如把 ModelJson 交给下游），产出的集成会直接坏掉。

1. 三个对象

ModelJson内部原始结果
raw pages + page_index_map
MiddleJson公开语义树
schema 2.0
ParseResult只持有 middle_json
渲染 / 保存
对象是否公开内容
ModelJson❌ 仅内部raw pages、page_index_map、metadata、extensions；只服务分析与后处理
MiddleJson✅有序 PageInfo（page_idx + blocks）；带 schema 身份 docvortex.middle、版本 2.0
ParseResult✅唯一字段 middle_json；pages 是属性；不持有 PDF 对象

2. MiddleJson 的身份字段

  • schema / schema_version：协议身份（JSON 键为 schema，Python 属性为 schema_id）。
  • metadata：文件类型、生产者（producer.name = "mineru"、版本）、源文档属性。
  • extensions["mineru"]：实际执行的 tier 与 parse_mode，严格校验（extra="forbid"），不记录 effort 或请求值。
  • pages：每页 page_idx（内部 0 起）+ blocks；自然语言 InlineSpan 不携带字体或几何信息。
# integrations/docvortex.py —— 记录“实际执行”，不是“请求值”
EFFORT_TO_TIER = {"flash": "flash", "medium": "basic", "high": "standard", "xhigh": "advanced"}

class MinerUMetadata(BaseModel):
    model_config = ConfigDict(extra="forbid", strict=True)
    tier: Literal["flash", "basic", "standard", "advanced"]
    parse_mode: Literal["txt", "ocr"]

3. 九种渲染

格式返回归属

PDF 输出布局由 PdfLayout 控制：AUTO（默认，有几何保留原始布局）、ORIGINAL（仅原始）、REFLOW（仅语义重排）。

4. 结果包

# parser/base.py —— 先序列化全部内容，再写文件；缺素材在写出前失败
def save(self, writer: DataWriter) -> None:
    from docvortex.export import materialize_middle, validate_materialized_assets

    # 在副本上外置素材，不修改原语义树
    middle_json, assets = materialize_middle(self.middle_json)
    validate_materialized_assets(middle_json, assets)
    exported = ParseResult(middle_json=middle_json)
    text_files = {
        "markdown.md": exported.markdown(),
        "middle_json.json": exported.to_json(),
        "structured_content.json": ...,
    }
    for path, content in text_files.items():
        writer.write_string(path, content)
    for path, payload in sorted(assets.items()):
        writer.write(path, payload)
规则：渲染与保存不得修改原语义树；不依赖已关闭的 PDFium 对象或源文件；单独的 middle_json.json 不能替代带素材的结果包。
