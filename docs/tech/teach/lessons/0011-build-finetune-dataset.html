Lesson 11 · 微调系列 2/3

构建微调数据集：捕获（图，指令，目标）三元组

这节课只做一件事：能复现 MinerU 真实调用模型的输入形态——裁剪图 + 按块类型的 prompt + 输出约定——并据此写出自己的数据捕获脚本，产出（image, prompt, completion）三元组。

本课立场：微调数据必须匹配推理时的输入分布。MinerU 推理时给模型的从来不是整页原图 + 通用问题，而是“按块裁剪 + 类型专属 prompt + 采样参数”；数据集偏离这个分布，微调就会白做。

1. 推理时的真实输入形态

页面图VLM 收到的原始输入（xhigh 还有布局块列表）
prepare_for_extract按块 bbox 裁剪 → 角度旋转 → resize 到上限 → PNG 字节（http-client）
prompt 选择按 block.type 查表：table/equation/image/text
模型输出文本（表格=HTML、公式=LaTeX、图=分析文本）→ post_process
# mineru_vl_utils/mineru_client.py —— prepare_for_extract 的实质（简化）
for idx, block in enumerate(blocks):
    if block.type in skip_list:

三个必须复刻的细节：① bbox 是 0–1 归一化后乘页面尺寸再裁剪；② 角度不为 0 时先旋转再送入；③ 输出尺寸有上限（resize_by_need）。训练数据若不复刻这些预处理，模型学到的将是另一套分布。

2. 数据捕获脚本骨架

思路：用同一个 MinerUClient 跑普通解析，但在 _predict 之前截获 (裁剪图, prompt, 采样参数)，让人工标注/更强模型生成目标输出。

# tools/finetune_capture.py —— 捕获三元组的可执行骨架（Python 3.11+）
"""从 MinerU 的 standard 档解析过程中捕获 (image, prompt, params) 三元组。

原理：MinerUClient.helper.prepare_for_extract() 是所有抽取路径
（content_extract / extract_with_layout / two_step_extract）的必经点，
在它返回后、真正调用模型前落盘，即可拿到与推理完全一致的输入。
"""
import json
from pathlib import Path
from PIL import Image

from mineru_vl_utils import MinerUClient          # 与 MinerU 运行时同一客户端
from mineru_vl_utils.structs import ContentBlock

CAPTURE_DIR = Path("finetune_data")
CAPTURE_DIR.mkdir(exist_ok=True)
manifest_path = CAPTURE_DIR / "manifest.jsonl"


def capture(client: MinerUClient, page_image: Image.Image,
            blocks: list[ContentBlock], *, source: str, page_no: int) -> int:
    """把一次抽取的全部块输入落到磁盘，返回样本数。"""
    block_images, prompts, params, indices = client.helper.prepare_for_extract(
        page_image, blocks
    )
    samples = []
    for image, prompt, sampled_at, idx in zip(block_images, prompts, params, indices):
        case_name = f"{source}_p{page_no}_b{idx}"
        image_path = CAPTURE_DIR / f"{case_name}.png"
        # http-client 模式拿到的是 PNG 字节，本地模式是 PIL Image
        (image_path.write_bytes if isinstance(image, bytes) else image.save)(image_path)
        samples.append({
            "id": case_name,
            "source": source,
            "page": page_no,
            "block_idx": idx,
            "block_type": blocks[idx].type,
            "bbox": list(blocks[idx].bbox),
            "angle": blocks[idx].angle,
            "prompt": prompt,                      # 与推理逐字节一致
            "sampling": str(sampled_at),
            "image": image_path.name,
            "completion": None,                    # 人工标注 / 强模型生成后回填
        })
    with manifest_path.open("a", encoding="utf-8") as f:
        for s in samples:
            f.write(json.dumps(s, ensure_ascii=False) + "\n")
    return len(samples)

接入方式 A（侵入）：pip install -e 的 fork 里直接在 window.py 的 _process_pdf_window 调 capture()；接入方式 B（无侵入）：包一个小脚本，用 MinerUClient.batch_extract_with_layout 喂你的页面与布局块。

3. 目标输出（completion）的来源

来源适用注意
人工标注小而精（数百条起步）质量的天花板；建立标注约定再动手
更强模型蒸馏规模化起步让强模型在同样的裁剪图 + prompt 下产出，避免分布漂移
PDF 文本层对齐文本块复用 MinerU 的文本证据逻辑：排除公式/表格区域
合成渲染表格/公式渲染 HTML/LaTeX → 截图 → 以渲染结果为 completion

每类块目标的格式约定即推理输出约定：表格 = HTML、行间公式 = LaTeX、普通文本 = 原文（带公式定界符的行内切片拆成文本与行内公式）。

4. 训练样本格式

# manifest.jsonl 的一行，补全 completion 后即为一条训练样本
{"id": "paper_p3_b12", "block_type": "table", "prompt": "\nTable Recognition:",
 "image": "paper_p3_b12.png", "completion": "<table><tr><td>…</td></tr></table>"}

# 常见训练框架消费形态（chat 模板示例）
{"messages": [
  {"role": "system",    "content": "You are a helpful assistant."},
  {"role": "user",      "content": "<image>\nTable Recognition:"},   # <image> 占位
  {"role": "assistant", "content": "<table>…</table>"}]}
  • system prompt 推理时是固定的 "You are a helpful assistant."——训练时保持一致，不要另起炉灶。
  • 采样参数（presence/frequency penalty）不进训练；它们影响推理解码，不影响权重学习目标。
  • 划分：留出块级别验证集（同文档的块不跨集合），防止同文档过拟合泄漏。

  1. 把 tools/finetune_capture.py 骨架跑通：解析一个 3 页 PDF，确认 manifest.jsonl 里每行都有 image + prompt。
  2. 手工标注 10 条 [default]（text）样本，用 PDF 文本层对齐的方式生成 completion，检查与裁剪图内容逐字一致。
  3. 统计你的 manifest：每种 block_type 各多少条？少于 50 条的类型先不要进训练集（记进 NOTES）。
