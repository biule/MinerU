Lesson 14 · 落地

批量流水线与字段提取

这节课只做一件事：把前十三课的源码知识组装成一条可运行的批处理流水线——目录输入、按类型选档、批量解析、结果落盘、字段抽取、CSV 汇总，并且单文件失败不拖垮整批。

为什么学这个：这是从“会调用 API”到“能交付解析结果”的分界线。真实业务里 90% 的工作不是解析一次，而是稳定地解析一千次。

你将能够

  • 设计六阶段流水线，并把每一步映射到 MinerU 4.x 的真实入口。
  • 按文件类型、扫描/文本、页范围选择档位，而不是一律用默认值。
  • 正确读取 ParseResult 的三种视图，并解释 Content List 的坐标约定。
  • 用关键词、bbox、表格 HTML 三种模式抽取业务字段。
  • 处理并发、重试、幂等、隐私与结果包素材，避免生产事故。

1. 六阶段流水线

1 收集目录 / 数据库 / 对象存储
2 分类PDF / 图片 / 原生格式
3 策略tier · ocr_mode · 页范围

2. 先分类，再选策略

输入建议档位原因
文本型 PDF（Word 导出）flash 或 basic原生文本可用；先预览，必要时升级
扫描型 PDF / 图片standard需要 OCR + 版面 + VLM 抽取
复杂表格 / 公式 / 难版面advanced两步抽取 + 图片分析
Office / HTML / EPUB / OFD / CSVflash原生格式只有 flash；CLI 单文件显式质量档位会报错，SDK/批量归一为 flash
 
NATIVE_SUFFIXES = {
    "docx", "pptx", "xlsx", "odt", "odp", "ods", "rtf",
    "epub", "ofd", "html", "mhtml", "csv", "tsv",
}
IMAGE_SUFFIXES = {"png", "jpg", "jpeg", "bmp", "tif", "tiff", "webp"}

def choose_tier(path: Path) -> str:
    suffix = path.suffix.lower().lstrip(".")
    if suffix in NATIVE_SUFFIXES:
        return "flash"
    if suffix in IMAGE_SUFFIXES:
        return "standard"          # 图片先转 PDF，再走同一条 PDF 流水线
    return "standard"              # PDF 默认标准档
  • ocr_mode="auto" 由 PDF 分类决定 txt/ocr；显式 txt/ocr 不会追加回退。
  • page_range 只对 PDF 合法；非 PDF 传非空值会报 page_range_invalid。
  • 先用 flash 试读首页、再升级，是控制成本的常用策略；但不要在 CLI 单文件入口对原生格式请求质量档位。

3. 最小可运行脚本

"""批量解析目录，保存结果包并输出 summary.csv。"""
from __future__ import annotations

import csv
import hashlib
import json
import traceback
from pathlib import Path

from mineru.parser import MinerUParser
from mineru.parser.writer import FileBasedDataWriter
from mineru.render import RenderFormat, render

IN_ROOT = Path("demo/pdfs")
OUT_ROOT = Path("pipeline_output")
RESULTS = OUT_ROOT / "results"
MANIFEST = OUT_ROOT / "manifest.jsonl"

NATIVE_SUFFIXES = {
    "docx", "pptx", "xlsx", "odt", "odp", "ods", "rtf",
    "epub", "ofd", "html", "mhtml", "csv", "tsv",
}
IMAGE_SUFFIXES = {"png", "jpg", "jpeg", "bmp", "tif", "tiff", "webp"}


def collect(root: Path) -> list[Path]:
    supported = NATIVE_SUFFIXES | IMAGE_SUFFIXES | {"pdf"}
    return sorted(p for p in root.iterdir() if p.is_file() and p.suffix.lower().lstrip(".") in supported)


def choose_tier(path: Path) -> str:
    suffix = path.suffix.lower().lstrip(".")
    if suffix in NATIVE_SUFFIXES:
        return "flash"
    return "standard"


def main() -> None:
    OUT_ROOT.mkdir(parents=True, exist_ok=True)
    RESULTS.mkdir(parents=True, exist_ok=True)
    files = collect(IN_ROOT)
    rows: list[dict] = []

    # 每个档位一个 parser：内部模型/运行时缓存按配置复用
    parsers = {
        "flash": MinerUParser(tier="flash", parse_mode="auto"),
        "standard": MinerUParser(tier="standard", parse_mode="auto"),
    }

    try:
        for path in files:
            suffix = path.suffix.lower().lstrip(".")
            tier = choose_tier(path)
            page_range = "1-10" if suffix == "pdf" else ""
            digest = hashlib.sha256(path.read_bytes()).hexdigest()
            out_dir = RESULTS / f"{path.stem}-{digest[:8]}"

            try:
                result = parsers[tier].parse(path, page_range=page_range)
                out_dir.mkdir(parents=True, exist_ok=True)
                result.save(FileBasedDataWriter(str(out_dir)))

                items = render(result.middle_json, RenderFormat.CONTENT_LIST)
                row = {
                    "source": path.name,
                    "tier": tier,
                    "pages": len(result.pages),
                    "blocks": len(items),
                    "text_blocks": sum(1 for i in items if i["type"] == "text"),
                    "tables": sum(1 for i in items if i["type"] == "table"),
                    "equations": sum(1 for i in items if i["type"] == "equation"),
                    "images": sum(1 for i in items if i["type"] == "image"),
                    "output": str(out_dir),
                    "status": "done",
                    "error": "",
                }
            except Exception as exc:                      # 单文件失败不拖垮整批
                row = {
                    "source": path.name,
                    "tier": tier,
                    "pages": 0,
                    "blocks": 0,
                    "text_blocks": 0,
                    "tables": 0,
                    "equations": 0,
                    "images": 0,
                    "output": "",
                    "status": "failed",
                    "error": f"{type(exc).__name__}: {exc}",
                }
                traceback.print_exc()

            rows.append(row)
            with MANIFEST.open("a", encoding="utf-8") as f:
                f.write(json.dumps(row, ensure_ascii=False) + "\n")
    finally:
        for parser in parsers.values():
            parser.close()

    with (OUT_ROOT / "summary.csv").open("w", newline="", encoding="utf-8-sig") as f:
        writer = csv.DictWriter(f, fieldnames=list(rows[0].keys()) if rows else ["source"])
        writer.writeheader()
        writer.writerows(rows)

    print(f"done: {len(rows)} files; failed: {sum(r['status'] == 'failed' for r in rows)}")


if __name__ == "__main__":
    main()
结果包不是单个 JSON：result.save() 在副本上物化素材并校验，写出 markdown.md、middle_json.json、structured_content.json 与图片。只保存 middle_json.json 会丢素材，后续无法离线重渲染。

4. 三种读取视图

视图入口适合注意
Markdownresult.markdown()给人看、喂 LLM渲染时现场生成，不修改语义树
Structured Contentresult.structured_content()扁平内容字典没有独立 schema 身份，不是协议
Content Listrender(result.middle_json, RenderFormat.CONTENT_LIST)程序化遍历块V1 扁平；V2 按页返回 list[list[dict]]
MiddleJsonresult.pages / result.to_dict()需要完整语义树与几何公开协议；块几何是 0–1 归一化

5. Content List 的字段与坐标

字段含义示例
type块类型text / table / equation / image / list / code / chart
text文本或 LaTeX（公式）公式带 text_format="latex"
text_level标题层级；仅标题块1 / 2 …
table_body表格 HTML<table>…</table>
img_path素材相对路径配合 asset_base_url
list_items列表/目录项嵌套列表用 sub_type 区分
code_body代码内容代码块
bbox0–1000 整数框不是像素，也不是 0–1
page_idx页面索引，0 起面向上游展示时通常 +1
坐标陷阱：MiddleJson 的块 bbox 是 0–1 归一化；Content List 渲染后转换为 0–1000 整数。两者都不同于页面像素坐标。写死像素阈值是最常见的“换一份 PDF 就失效”原因。

6. 字段抽取的三种模式

模式适用实现
关键词 + 同行值“发票号码：12345”在 text 中查找标签并切分
区域匹配位置稳定的字段bbox 0–1000 + page_idx
表格结构行列数据解析 table_body 的 HTML
 
import re
from html import unescape

CELL_RE = re.compile(r"<t[dh][^>]*>(.*?)</t[dh]>", re.S)
TAG_RE = re.compile(r"<[^>]+>")

def cell_texts(html: str) -> list[str]:
    return [unescape(TAG_RE.sub("", cell)).strip() for cell in CELL_RE.findall(html)]

def extract_invoice(items: list[dict]) -> dict:
    fields = {"invoice_no": None, "date": None, "amount": None, "line_items": []}

    for item in items:
        if item["type"] != "text":
            continue
        text = item["text"].strip()
        if m := re.search(r"(?:发票号码|Invoice\s*No\.?)\s*[:：]?\s*([A-Za-z0-9\-]+)", text):
            fields["invoice_no"] = m.group(1)
        if m := re.search(r"(?:开票日期|Date)\s*[:：]?\s*(\d{4}[-/年]\d{1,2}[-/月]\d{1,2})", text):
            fields["date"] = m.group(1)
        if item.get("page_idx") == 0 and item.get("bbox"):
            x0, y0, x1, y1 = item["bbox"]
            if x1 > 700 and y0 > 700:                 # 右下区域（0–1000）
                if m := re.search(r"[¥￥]\s*([\d,]+\.\d{2})", text):
                    fields["amount"] = m.group(1)

    for item in items:
        if item["type"] == "table":
            fields["line_items"].append(cell_texts(item.get("table_body", "")))

    return fields

真实业务通常三种模式组合：先关键词定位，再用 bbox 验证区域，最后用表格结构校验明细合计。任何阈值都应来自样本统计，而不是拍脑袋。

7. 并发、重试、幂等与隐私

问题建议原因
本地小模型并发顺序处理；不要盲目开线程池共享原子模型与推理锁，并行通常只是争锁
远程 VLM 并发parse_batch_async 或自有异步池max_concurrency 控制上游请求并发
重试只重试 remote_timeout / remote_unreachable / 引擎暂时不可用invalid_request_error 重试不会变好
幂等用内容 sha256 + 档位 + 页范围命名输出重复运行不产生半成品或覆盖不同来源
隐私远程 VLM / Tasks 都必须显式允许配置了地址不等于允许上传
失败隔离单文件异常写 manifest，不中断整批批处理的价值在于可恢复
 
# 幂等输出目录示例
out_dir = RESULTS / f"{path.stem}-{digest[:8]}-{tier}-{page_range or 'all'}"

# 断点续跑：manifest 中已 done 且输出存在则跳过
if row.get("status") == "done" and Path(row["output"]).exists():
    continue

10. 动手挑战

挑战 1：跑通批处理

挑战 3：失败注入

把一个 PDF 截断成损坏文件，确认整批继续、manifest 记录 failed，并且重跑时只处理失败项。

挑战 4：成本对比

同一批文件分别用 flash 与 standard，统计耗时、页数和关键字段命中率，写下你的档位策略。
